|---|---|---|---|

**Interpretation: "a Reve bridge only" = both OpenAI-surface bridges (generation and edit), not the native passthrough
routes.** Reasons: the code calls exactly these two adapters "bridges" (`reve.rs:4`, `:507-511` "sealed reve bridge");
the record's §19 puts P18's Reve edit into this step "so that neither side migrates twice"; the record's §2 and lv's D2
already exclude the native routes; and lv's 10-13 pre-approval list sets "Reve: only the bridge" beside other
per-provider scope cuts. The code makes one reading possible that lv should exclude explicitly: "bridge" in the sense
of generation only (create SKUs), leaving the edit bridge native. That reading would keep `reve.rs`'s edit half and its
shared sender alive, i.e. migrate Reve twice, which the record rules out. **RV-Q1** asks.

Consequences of keeping the native routes (D2):

- `reve.rs` does not disappear after cutover. `native_image` keeps its own sender, `reve_credits_from_headers`,
  `collect_reve_headers`, the `ReveFamily` default-SKU table and the `[billing] reve_max_billable_credits` knob
  (`server:gateway/src/infra/config/sections.rs:983-1001`); the bridge deletion removes `generations`, `edits`,
  `send_reve_json_sealed`, `finish_reve_openai_surface` and the bridge-only helpers (about 700 production lines; the
  inventory's estimate, host native-arm inventory, image part §3.8).
- **The native routes resolve the same model rows as the bridge**: a body without `model` bills `reve/reve-create` (or
  `-edit`, `-remix`, `-fast`) and sends that row's `upstream_model` as Reve's `version` (`reve.rs:1074-1084`,
  `:1140-1147`). Any scheme that changes a routed row's `upstream_model` breaks those routes for the same row (RV-Q2).

Out of scope as native: `POST /v1/image/layout`, `GET /v1/image/effect` (`KNOWLEDGE.md:2631-2634`); binary output

## 3. Generation request (`prepare`, operation `generate`)

Reproduces `generations` (`reve.rs:751-823`), `validate_reve_generation_request` (`:173-193`),
`validate_reve_output_format` (`:197-207`), `build_reve_create_body` (`:212-263`) and `size_to_reve_aspect_ratio`
(`:133-162`):

- **Descriptor**: `POST v1/image/create` (host default composition `{base}{path}`; base `https://api.reve.com`,
  `server:gateway/src/infra/config/providers.rs:741`), auth `{"arm": "bearer", "slot": "provider_api_key"}`, body JSON,
  `accept: application/json` (`reve.rs:571-572`; the response carries the meter in the body only in this mode).
- **Body, in native key order**: `prompt` = the client's string **as sent** (native checks a trimmed copy for blankness
  but forwards the original, `reve.rs:216-226`); `aspect_ratio` = the client's `aspect_ratio` if it is a string,
  forwarded **unvalidated**, else the ratio derived from a string `size`, else absent (`:228-241`); `version` = the
  client's `version` if it is a string, else the row's version (RV-Q2) (`:243-253`); then `test_time_scaling`,
  `postprocessing`, `breadcrumb`, each copied as any JSON value when present and not `null` (`:166`, `:255-261`).
- **`size` → `aspect_ratio`**: a non-string `size` is **ignored** (native `as_str`, unlike Ideogram's 400); the string
  is trimmed; empty or `auto` (any case) → none; else split at the first `x` **or `X`** (`:138`), each side trimmed and
  parsed as `u32` (a leading `+` parses); a parse failure → 400 "invalid width in size '…'" / "invalid height in size
  '…'"; no separator → 400 "invalid size '…', expected WxH (e.g. 1024x1024) or 'auto'"; a zero side → 400 "size '…'
  must have positive width and height"; else the nearest of `16:9, 9:16, 3:2, 2:3, 4:3, 3:4, 1:1` by `|r − w/h|` in
  `f64`, the earlier entry on a tie (`:117-125`, `:154-161`; strict `<`). The texts echo the trimmed value.
- **Refusals before dispatch** (`invalid_request`, native texts, in native order after the row checks): `n` other than
  1 ("Reve generates exactly one image per request; 'n' must be 1 or absent (got N)"); `stream` equal to JSON `true`
  ("streaming is not supported for Reve image generation; re-submit without `stream`"; a string `"true"` is ignored, as
  native `as_bool`); `output_format` a string other than `png` in any case (native text naming the native routes); a
  missing, non-string or blank `prompt` ("Missing 'prompt' field"); a bad `size` as above. An elided `prompt` or a
  field the template copies (above 1 MiB) is refused with `image-azure`'s "'{field}' is longer than the gateway
  accepts" (P7).
- **Dropped**: `response_format` (any value; native always answers `b64_json`, `reve.rs:170-172`), `model`, `n`,
  `size`, `quality`, `style`, `user` and every other field.
- **Immutable body paths**: `version`, `test_time_scaling`, `postprocessing` (= `REVE_IMAGE_OWNED`,
  `server:…/handler/images/execute.rs:63-64`, JSON paths, `server:…/handler/images.rs:74-75`): operator request extras
  would let the credit meter exceed the reservation.
- **Facts**: `operation` `generate`; no `inputs`; `requested_outputs` 1; no `size` (Reve receives a ratio, not a size;
  I3-1 §5 item 3 / I3-5 P5 precedent); no tier; `metering_forms` `[credits]`; no `bounds` (RV-Q3 note); `repeat` 1;
  `response_body_form` `json`; response elision path `/image`.
- **`state`**: `{}` plus what render needs that the response lacks (nothing today; render always emits `b64_json`).

## 6. Metering form `credits`: what a host needs to serve it generically

### 6.1 How native bills today

| | Bridge (this step) | Native routes (kept, D2) |
|---|---|---|
| Price | `credit_price_per_million` on the model row (µ$ per million credits; migration 0039; `server:gateway/src/infra/config/models.rs:224-233`); Reve sells $10 = 7,500 credits, so `1_333_333_333` | same |
| Settlement | `round(credits × rate / 1e6)` (`calculate_credit_cost`, `media.rs:101-107`), frozen as `FrozenStreamUsage::Credits` (`reve.rs:702-723`), `usage_unit = credits` | same (`reve.rs:1294-1316`) |
| Reservation | **the image surface's flat formula**: `image_price × 1` on generation (`server:…/handler/images/execute.rs:149-183`, via `handlers.rs:260-273`), `image_price × 10` on edits (`handlers.rs:1097-1112`) — a column that is not Reve's price | `reve_max_billable_credits × rate` (`reve.rs:1182`; global knob, default 100) |
| Over-reservation settlement | parked for review (`settlement charge … exceeds authorized maximum`, `server:gateway/src/modules/billing/repo/settlements.rs:1845-1853`) | same |

So a Reve row that carries only its real price (`credit_price_per_million`) cannot be served by the bridge: the
reservation is 0 and admission refuses it with 400 "this model has no price configured…"
(`server:…/engine/text_admission/sender.rs:4198-4206`); nor can it be enabled, because the image-modality enable gate
does not read `credit_price_per_million` (`server:gateway/src/modules/catalog/pricing_state.rs:146-162`). Native Reve
rows therefore carry an `image_price` that acts only as the bridge's per-call bound (the host's BYOK test row does:
`image_price = 250000` beside `credit_price_per_million`, `server:gateway/tests/byok_media_ownership.rs:1157-1168`,
`:1197`). A call whose credits cost more than that `image_price` (a `test_time_scaling` of 15 multiplies the meter,
`KNOWLEDGE.md:2605-2607`) parks. Host defect §10 item 1.

### 6.2 What a generic `credits` path needs

Every piece is provider-independent: a column name, a bound and a form, chosen by catalog data, never by provider type.

1. **The form decision** (the host's single function, record §9.3, `media.rs:1122-1134`): a row with a positive
   `credit_price_per_million` is priced in `credits`; it is checked before the token and image rules, since a credit
   row's `image_price` may be a leftover bound (§6.1). No other image row sets the column today (Kiro's credit meter is
   text and is not priced, root `CLAUDE.md` "One registered exception").
2. **The price** is already catalog data: `credit_price_per_million` (domain, repo, manifest, sync,
   `server:gateway/src/modules/catalog/{domain.rs:65, repo/models.rs:106, manifest.rs:65, sync.rs:100}`). The enable
   gate's image bucket must count it (`pricing_state.rs:146-162`).
3. **The bound** (record §8: "the host has no request-derived credit bound"). The reservation needs a host number of
   credits per call; options: (i) a per-model catalog column, `max_billable_credits` (data beside the price; the
   meter differs by an order of magnitude between rows: fast 5, create 18, edit and remix 30 credits per call,
   `KNOWLEDGE.md:2603-2605`, times up to 15 for `test_time_scaling`); (ii) a global billing knob, the generic form of
   `reve_max_billable_credits` (the native routes' answer; one number for every row, so it either over-reserves fast
   rows or parks heavy ones); (iii) the component's `bounds.max_credits` alone — not allowed: the record forbids a
   component-supplied number from being both the reservation and the check (§8). Reservation =
   `calculate_credit_cost(model, min(host bound, component bound))`, then `byok_admission_bound` as for every image
   row. A missing host bound is a 503 before admission (never admit with a 0 reservation, the 66-P2c rule).
4. **The settlement**: `calculate_credit_cost(model, credits)` with the decimal parsed from the `credits` fact, frozen
   as the existing `FrozenStreamUsage::Credits { credits, estimated_input_tokens: 0, estimated_output_tokens: 0 }`;
   check 5 (settlement ≤ reservation) stays the worker guard; §9.4 item 1 (the fact is present) the executor's
   `check_succeeded` arm for `Credits` (`checks.rs:143-147`, today a refusal).
5. **Held**: `finish_held_success` with the credits cost (RV-Q4 decides whether credits rows go held at all).

### 6.3 Options

- **(a) A generic `credits` path in the host** (§6.2 items 1-5). Reproduces native billing exactly, including the
  `test_time_scaling` / `postprocessing` surcharges and content violations, and fixes §6.1's bound. Host work: one
  branch in the form decision, one bound source, two `match` arms in the executor, the enable gate.
- **(b) The package meters `images`**, the catalog carries a flat per-call `image_price`. Reproduces native only when
  every call of a row costs the same number of credits. It does not: `test_time_scaling` (1-15) and `postprocessing`
  multiply the meter, a client `version` can switch a row between fast and normal pricing, and a content violation
  bills credits with no image (`images_reported` is meaningless). (b) would either misbill those calls or need the
  package to refuse `test_time_scaling`, `postprocessing` and `version` (a regression the native arm was built not to
  have, issue #190), and it replaces an upstream-reported meter with a host estimate, which the root billing contract
  allows only for subscription backends without a priced meter.
- **(c) `requests`** has the same flaw as (b) and no consumer either (`mod.rs:1559`).
- **(d) Leave Reve native** (no package). Possible if RV-Q0 shows Reve is being dropped anyway.

**Recommended (RV-Q3): (a), with bound (i)** (a per-model `max_billable_credits` column, refused 503 before admission
when missing), the generic knob (ii) only as the native routes' existing value. The package supplies no
`bounds.max_credits` in 1.0.0: Reve's per-call credit table is a documentation fact that is itself unverified (RV-Q0).

## 7. `charged_failure`: native settles then answers 400, the host parks and answers 502

### 7.1 The two behaviours

| | Native bridge (`reve.rs:702-743`) | Host component executor today |
|---|---|---|
| Funds | `finalize` with the credits cost, then lift to 400 (`usage_records.upstream_status` stays 200) | `delivery_unknown`, no `finalize`, evidence sealed (`mod.rs:1024-1031`); held: `park_held_uncertain` |
| Client | 400, OpenAI error `type` / `code` `content_policy_violation` plus the flat metadata (`reve.rs:414-431`), `X-Reve-*` headers | 502 with the envelope's text (`parked_error`, `mod.rs:1289-1294`) |
| Held | not wired; `Prefer` ignored, sync (`server:…/handler/images/durable.rs:447-456`) | a routed model is held-wired (`durable.rs:474-476`), so a Reve row would answer 202 and park its violations |

The host wrote its reason down (P22 C5 deviation 2): settling would need a second `finalize` site against the
executor's "exactly one" ratchet, and the held framework has no "failed but charged" terminal state; the plan deferred
the decision to I3-6 (P22 plan §5.3 and Q7).

### 7.2 Why parking is the wrong steady state for this outcome

A content violation is the one outcome where the component **knows** the charge (the meter is a required fact, record
§9.1) and the upstream **says** nothing will be produced. Parking every one sends a decided case to manual review, and
answering 502 tells a client to retry a request that will be refused and charged again (the host's own reason for 502
on parked funds is the opposite case: a 4xx while funds may still be charged invites a retry the client thinks is free,
`mod.rs:1286-1288`). It is not covered by a precedent: I3-4 SI-Q3 avoided the outcome (Stability's filtered image is
delivered and billed), and the P2 / IM-Q6 precedent is about funds the host cannot decide.

### 7.3 What the host needs (RV-Q4)

- **Sync**: settle `charged_failure` through the executor's one `finalize` — the verdict gains a variant
  `Charged { cost, usage, error }` beside `Deliverable`, the same `finalize` call serves both, and the response is the
  component's envelope with its status (400 here). The ratchet stays at one site.
- **Held**: either (h1) credits-priced calls ignore `Prefer` (a generic rule on the pricing form, extending
  `held_async_can_honour`; matches native, which never goes held for Reve), or (h2) the task framework gains a
  "failed, charged" terminal state (the record §10.3 mapping "`charged_failure` → a failed terminal state after
  settlement"), or (h3) held parks it, as today (a registered difference). **Recommended: (h1)** now; (h2) when a
  second family needs held `charged_failure`.
- **South**: the suite checks required facts only on `succeeded` (`image_suite.rs:623-643`); record §9.1 requires
  `credits` (or `images_reported`) on `charged_failure` too. This step extends `missing_meter_is_not_zero` to
  `charged_failure` (a `charged_failure` without its required fact fails the row, and the package's pack carries a
  violation without a meter, whose outcome must be `unknown`). This tightens the suite for every package; none
  shipped returns `charged_failure`, so none changes.

## 10. Host defects found on the way (read, not run)

1. **The bridge reserves against `image_price`, a column that is not Reve's price** (§6.1): a credit-only row is
   refused 400 before dispatch; a row with an `image_price` below a call's credits cost parks that call; edits reserve
   ten times it. Fixed on the component path by §6.2.
2. **Edit refusals after admission do not cancel the hold**: `edits` returns every validation error (`mask`, `n`,
   `stream`, `output_format`, `prompt`, `size`, extras, image count, family, unpriced) with `?` / `return Err` without
   `cancel_pre_dispatch`, so the hold and capacity slot wait for the stale sweep (up to the 120 s lease; the code says so,
   `reve.rs:844-847`). The P22-F6 fix (`handlers.rs` "field_checks") covered the generic edit path, not this one. The
   component path refuses all of them before admission (P3).
3. **A hollow 200 is billed**: a 2xx with `content_violation` false and an empty or missing `image` answers 200 with
   `"b64_json": ""` and settles the credits (`reve.rs:394-399`, `:725-735`), against the root contract "never swallow an
   upstream failure as a 200 with empty content". Component: `unknown`, parked.
4. **A negative `credits_used` settles $0** (`reve_credits_from_json` accepts any finite number; `calculate_credit_cost`
   returns 0 for `≤ 0`). Component: `unknown`.
5. **`credits_remaining` exposes the operator's upstream account balance** to every caller on the platform credential
   (`reve.rs:405`, `:428`, and the `X-Reve-*` header copy, `:462-484`); with BYOK it is the caller's own. RV-Q5.
6. **`aspect_ratio` is forwarded unvalidated** (`reve.rs:229-233`): any string reaches Reve. Reproduced, not fixed.
7. **The image enable gate ignores `credit_price_per_million`** (`pricing_state.rs:146-162`), which is what forces the
   bound-as-price `image_price` of item 1. Fixed by §6.2 item 2.
8. **The upstream dialect is unverified since 2026-08-14** (§0.2).

Per lv's I3-2 ruling, native-arm defects (items 1 to 6) are registered here and leave with the arm; items 1 and 7 are
also prerequisites of §6.

## 11. Differences that follow precedent (accepted under lv's 2026-10-13 pre-approval)

- **P4 Generic refusal texts**: an undeclared upstream id → 503 before admission (native 400 "not a recognized Reve

- **RV-Q1 Scope.** (a) Both OpenAI bridges — generation (create) and edit (edit, remix) — in one package; the native
  passthrough routes stay native (D2); (b) generation only. **Recommended: (a)**, the record's "same batch" (§9).
- **RV-Q2 How the package tells create, edit and remix apart.** Native classifies by the gateway model name's last
  segment (`reve.rs:104-113`); a package sees only the upstream id, which is Reve's `version` and is shared by all three
  (`latest`, `latest-fast`). Options: (a) the routed row's upstream id carries the endpoint (`create:latest`,
  `remix:reve-remix@20250915`) and the package splits it — no host or contract change, but the native routes (D2) send
  that row's upstream id as `version` for bodies without `model`, so routing a default-named row
  (`reve/reve-create` …) breaks them; (b) infer: generation → create; a dated id names its family
  (`reve-edit@…`, `reve-remix@…`); a family-less id on edit picks edit for one image and remix for two to six — no row
  change, but a remix row with one image goes to `/edit` with `edit_instruction`, an edit row with several images is
  served instead of refused, and a `latest` row serves both endpoints; (c) a generic host feature: image routes gain the

  key `endpoint` (R20, the MiniMax `group_id` precedent) — no code, but every credential and BYOK key is entered three
  times. **Recommended: (c)**; (b) if lv prefers no host change and accepts its differences.
