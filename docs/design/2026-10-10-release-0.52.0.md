## 1. What this release carries

The first batch of the image world (record §19, S-I-1 to S-I-6 and this release, S-I-8). S-I-7 (xAI) is not in it: it
waits for the host's tier-keyed price list (record §14, Q8; lv 2026-10-10). The SSE decoder `decode_sse_v1` is not in it
either: Q-B6-6 (lv 2026-10-09) ships it separately.

- **`contracts.media` v1** (`south_contracts::media`, record §6, §11): the elider `elide_v1` over a strict, order- and
  text-preserving JSON tree; the multipart parser `parse_multipart_parts_v1` and encoder `encode_multipart_v1`; the
  closed transform vocabulary of both media worlds (`as_is`, `base64`, `data_url`, `from_data_url`, `from_base64`,
  `from_hex`, `concat`, `wav_pcm_s16le`) on crate-private codecs; `MediaRequestDescriptorV1` with `MediaAuthV1` and
  `expand_json_template_v1`; the request and response views (`build_media_response_view_v1`, `ResponseBodyFormV1`
  including `sse`, which the view builder refuses until the decoder ships); `ArtifactUrlV1` and
  `is_forbidden_egress_address`. Golden vectors for hosts that do not link the crate:
  `crates/south-contracts/tests/vectors/media-v1.json`. `compatibility.json` records `contracts.media` 1 and the
  `media_limits` table, pinned to `MediaLimitsV1::V1`.
- **`contracts.image` v1** (`south_contracts::image`, record §7–§10): facts, metering with nullable buckets (`null` and
  `0` stay distinct), artifact forms and the delivery table, the dialect-bound model capabilities (R-1), the call and
  render contexts, `PreparedImageCallV1`, and the render template check and fill.
- **HTTP contract 12** (S-I-2): `execute_multipart_binary_call_v1` (a multipart POST whose response is read as bytes)
  and `TextPostRequestV1` with `execute_text_binary_call_v1` (the speech world's SSML body); a new transport host suite
  `south.provider-media-binary.v1` (six cases).
- **The `image-adapter-v1` world** (S-I-3, S-I-4): `wit/image-adapter.wit`, the manifest row, gate ① (a provider
  family and at least one of `generate`, `edit`; a family's `config_schema` and credential attributes admitted, nothing
  else of the provider world's declarations), and the runtime world with no host import. The enumerated world
  exclusions became properties of `WorldSchemaV1` (`host_import`, `value_channel`, `request_declarations`,
  `instance_declarations`); the four existing worlds behave exactly as before.
- **Gate ② `south.image-component.v1`** (S-I-5): fixture packs over `capabilities`, `prepare`, `response` and `render`;
  five new `CheckV1` rows (`metering_sample`, `missing_meter_is_not_zero`, `evidence_absent_is_null`,
  `pre_dispatch_refusal`, `reference_integrity`); `admit_media_descriptor_auth`, built on the same rule as
  `admit_descriptor_auth`.
- **Gate ③ `south.safe-fetch.v1`** (S-I-5): the host's safe fetch executor held to record §11 over injected resolver and
  transport ports (26 cases).
- **The `image-azure` package** (S-I-6): Azure AI Foundry's MAI image API, generation and edit, transcribed from the
  server's native arm; 36 hand-written fixtures; the sandboxed component passes gate ② byte for byte against the
  native reference.

## 2. Breaking for hosts on re-pin

- `HTTP_CONTRACT_VERSION` 11 → 12, and `RequestBodyRefV1` gains `Text` (the enum is not `#[non_exhaustive]`; a host
  that matches it exhaustively needs an arm).
- `ManifestErrorV1::ImageOperationRequired` (a host that matches the enum exhaustively needs an arm).
- `WorldSchemaV1` gains public fields (a host that builds one with a struct literal must name them).
- `CheckV1` gains five variants.
- `compatibility.json` `schema_version` 6 → 7 (new `media_component_capabilities` table, `contracts.media`,
  `contracts.image`, `media_limits`, the image suite fields).

A host whose range lists neither `media` nor `image` refuses `image-azure` by contract number and is otherwise
unaffected; no existing package's contracts change.

## 3. Package identities and `south_runtime`

The three crates every guest links changed — `south-contracts` (the two new modules, HTTP contract 12),
`south-provider-api` (the world, gate ①), `south-component-conformance` (the image seam, suite, codecs and reference) —
so under boundary record §13.12 step 2 each takes a new minor version, 0.50.0 → **0.51.0**, with the requirements on them,
every component lockfile and `fuzz/Cargo.lock`. A same-path rebuild of every package at `v0.51.1` and on the commit that
bumps those crates (workspace still 0.51.1) gave a different `component.wasm` for each, so every identity published with
0.51.1 retires (`the_image_world_retires_every_published_0511_package_identity`). Their behavior is unchanged and none
needs anything newer, so each keeps its `south_runtime`.

`image-azure` 1.0.0 is new: family `azure-mai`, capabilities `generate` and `edit`, auth arm `header_secret`, contracts

## 4. Hosts

A host that only re-pins changes nothing it serves: the new world, contracts and package are additive, and a range
without `media` / `image` skips `image-azure` (W5). Serving `image-azure` needs, on the host side, the generic media
executor of record §19 "Prerequisites outside south" item 2 (view building with `elide_v1`, multipart parse and encode,
reference expansion before admission, the binary entry points, verify-then-settle, GatewayHeld wiring), a range that
lists `media` 1 and `image` 1, and the safe fetch executor for `url` artifacts (not used by Azure).
