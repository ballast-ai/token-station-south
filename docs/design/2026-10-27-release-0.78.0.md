## 1. What this release carries

- **A placeholder signature on a replayed Gemini tool call** (accepted by lv on 2026-10-27). When a replayed assistant
  turn carries tool calls and none of them has a signature, `gemini_text.rs` (shared by `provider-gemini` and
  `provider-vertex`) writes Google's documented placeholder `skip_thought_signature_validator` as the
  `thoughtSignature` of the turn's first `functionCall` part. A turn in which any call is signed is left as it is, an
  empty signature is still refused, and the response direction, the streaming parser and the north codec do not change.
  Gemini 3 answers a replayed turn with no signature at all by HTTP 400; a client on the Messages or Responses surface,
  a Chat client that drops `extra_content`, or a conversation that began on another model can now complete its second
  turn.

## 2. API changes

None to a public contract.
- `south-component-conformance` 0.76.0 → 0.76.1 (compatible change, patch): the new request translation for an unsigned
  replayed turn and the updated Gemini and Vertex fixture packs.
- `south-contracts` (0.56.0) and `south-provider-api` (0.63.0) are unchanged, as are `south-north-codec` and every other
  workspace-versioned crate apart from the release number. The kernel pin is unchanged (protocol 0.7.0). No South
  contract number changes; `compatibility.json` records the same kernel tuple, `canonical_ir` 5 and `stream` 3.

## 3. Hosts

Nothing breaks on re-pin: no struct gains a field, no enum gains a variant, no delivery suite changes, and a host that
records runtime 0.77.0 admits every package of this release, because no package raises its declared runtime (§4). The
host still has to move its pin to the 0.78.0 release index and tag, because every package took a new version and
therefore a new identity.

The behaviour change a host will see: a Gemini or Vertex request whose history holds an assistant turn with unsigned
tool calls now carries the placeholder on that turn's first call, where it used to carry no signature. For Gemini 2.x
this changes nothing observable (the measurements in the feature record show both forms accepted); for Gemini 3 it turns
a 400 into an answer.

`compatibility.json`: the delivery suites are unchanged.

## 4. Package identities

`south-component-conformance` is linked by every component, so the version bump changes every `component.wasm` and every
package takes a new version (boundary record §13.12, §16 Q47):
- `provider-gemini` 1.6.0 → **1.7.0** and `provider-vertex` 1.3.0 → **1.4.0** (the placeholder);
- the other 39 packages take one patch with unchanged behaviour, for example `provider-anthropic` 1.4.3 → 1.4.4 and
  `provider-openai-compatible` 2.13.1 → 2.13.2.

Declared runtime: **no package raises `south_runtime`; all 41 keep 0.77.0.** The release introduces no manifest field or
value that an older runtime's gate ① refuses or reads differently, and no runtime-side meaning a descriptor depends on
(CONTRIBUTING, "Usage judges for released provider packages"; boundary record §13.6). The kernel tuple (`canonical_ir`
5) is the one 0.77.0 introduced, so 0.77.0 stays the lowest runtime that admits them. The tests that pin it are
unchanged: `declared_runtime_now` still returns 0.77.0 for every package, and the workflow test that shows the workspace
release and a component's declared runtime are independent now reads release 0.78.0 against a package declaring 0.77.0.
The release index is expected to list 41 packages and 1 catalog.

## 6. Verification

The gate is the release pull request's CI run (`quality`, which on `release/*` branches includes
`scripts/check-declared-runtime.sh --build`; `crate-versions`; `language`). The release workflow (build scripts, gate ②
reports, `check-declared-runtime.sh --dist`, the release index, `check_crate_versions.py --tag` and the
digest-stability comparison with the published `v0.77.0` index) runs on the tag.

Local verification on this tree, each step judged by its own exit code: `cargo fmt --all -- --check`,
`cargo clippy --workspace --all-targets --all-features -- -D warnings`, `cargo nextest run --workspace --all-features`,
`scripts/check-boundaries.sh`, `scripts/check-language.sh`, `python3 -m unittest discover -s scripts -p 'test_*.py'`,
`python3 scripts/check_crate_versions.py --unreleased` (against `v0.77.0`), `scripts/check-declared-runtime.sh --build`
and `cargo metadata --locked --offline --manifest-path fuzz/Cargo.toml`.

The tag itself is not created here.

## 7. Not verified

- The placeholder was measured on 2026-10-27 through the server's deployed 0.77.0 packages, by a client sending the
  placeholder as a signature, over the Chat surface, non-streaming, against Gemini API and Vertex. The packages of this
  release have not been called against an upstream. Parallel calls were measured only non-streaming, and streaming was
  not measured at all (the replayed request does not depend on the response mode, but this was not observed).
- Whether a placeholder signature costs the model any quality. Google's error text warns that a missing signature may
  degrade performance; nothing here measures the same for a placeholder.
- Whether Claude Code (Messages) and Codex-style clients (Responses) actually complete a Gemini 3 tool round trip after
  the host re-pin: that needs the server's end-to-end journey rerun against a deployment that carries these packages.
