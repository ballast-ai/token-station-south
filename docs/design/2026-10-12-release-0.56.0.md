## 0. Released before its measurement

The R3 record §3.2 makes a staging measurement on a real Codex account a precondition of release: whether the backend
accepts `max_output_tokens` (R-Q5), whether it needs headers beyond those of §2.3, a reasoning replay round trip, and
whether the refresh needs `scope`. **lv ruled on 2026-10-12 to release 0.56.0 without it**, so that KC1 (canonical IR 4)
can follow at once as 0.57.0. Consequences, which hosts must honour:

- **No host row may be cut over to the `openai-codex` family until the measurement is recorded** in the R3 record §3.2.
  The family is shipped and gated, not cleared for use.
- A package change the measurement requires ships as a **patch release** (a new package version, Q47 as usual).
- The `openai-responses` family and the four request fields do not depend on the measurement.

## 1. What this release carries

- **#186, Responses step R3.** `provider-openai-responses` 1.2.0:
  - the second family `openai-codex`: `{base_url}/codex/responses`, `accept: text/event-stream`, `stream: true` forced
    and a non-streaming request refused at build time with zero upstream calls (R-Q5), `input` always an item list,
    `instructions` defaulted, no `temperature` and no `max_output_tokens` (`output_cap: []`), `store: false`, the
    immutable paths `store`, `stream`, `instructions`, `temperature`, `max_output_tokens`, `north_passthrough: responses`,
    `chatgpt-account-id` from the exported `account_id` attribute only;
  - a `credentials` section scoped to `openai-codex`: fields `access_token`, `refresh_token` (secret) and `account_id`
    (non-secret, syntax `token`, persisted), `require_one_of`, import from the Codex CLI's `auth.json`, slot
    `provider_api_key` minted by recipe `codex` (OAuth refresh with `scope`, rotation with write-back, a fixed
    3000-second window, the `id_token` account checked against the stored one; a 429 from the token endpoint is
    `transient`, RQ3-Q9);
  - the `openai-responses` family writes `user`, `metadata`, `prompt_cache_key` and `truncation` onto the body
    (RQ3-Q5: the Codex family does not, until measured).
- **North codec**: the Responses codec validates the four fields (fail closed, `null` = absent) and writes them as
  request extensions under the Chat codec's names (RQ3-Q3, RQ3-Q4). A request without them is unchanged byte for byte.
- **Gate ②**: a stream fixture may name its usage chunk (`{"usage_chunk", "usage_pointer"}`), and
  `UsageNeverDefaulted` then runs on it. New fixture pack `fixtures-openai-codex/`, judged together with
  `fixtures-openai-responses/` as the package's one pack; the recipe's rows run in `CredentialRecipeMatch` (RQ3-Q10).
- **The release commit** (this branch): the workspace bump (§5) and the release notes (README row and package row,
  ARCHITECTURE v0.56.0 paragraph, the status lines of the R3 and Responses records, this record).

No contract number changes (`compatibility.json` `schema_version` stays 7), the kernel pin is unchanged, and no package's
`south_runtime` moves.

## 2. API changes

### `south-north-codec` 0.55.0 → 0.56.0 (workspace version)

- New: `RESPONSES_REQUEST_FIELD_MAX_BYTES` (512), `RESPONSES_METADATA_MAX_ENTRIES` (16),
  `RESPONSES_METADATA_KEY_MAX_CHARS` (64), `RESPONSES_METADATA_VALUE_MAX_CHARS` (512).
- Behavior: `chat_request_from_responses` writes `user`, `metadata`, `prompt_cache_key` and `truncation` into
  `ChatRequest.extensions` and refuses out-of-bounds values (`invalid_request`).

### `south-component-conformance` 0.53.0 → 0.54.0 (#186)

- `CaseV1` gains the public field `usage_chunk: Option<usize>`.
- New: `reference_openai_responses::CODEX_FAMILY`; `responses_vocabulary` gains the four extension names and their bounds
  (`USER`, `METADATA`, `PROMPT_CACHE_KEY`, `TRUNCATION`, `CLIENT_FIELDS`, `MAX_FIELD_BYTES`, `MAX_METADATA_*`,
  `TRUNCATION_VALUES`) and a `codex` module (`FAMILY`, `PATH`, `DEFAULT_INSTRUCTIONS`, `ACCOUNT_ATTRIBUTE`,
  `ACCOUNT_HEADER`).
- The references' `VERSION` constants follow §4.

`south-contracts` (0.52.0) and `south-provider-api` (0.52.0) are unchanged.

## 3. Hosts

**Breaking for hosts on re-pin.** A host that builds `CaseV1` with a struct literal must name `usage_chunk`. A Responses
(and, through the Chat codec's raw keys, a Chat) request whose `user`, `metadata`, `prompt_cache_key` or `truncation` is
out of bounds is now refused where it used to pass with the field dropped; in-bounds values now reach an
`openai-responses` upstream.

Serving `openai-codex` needs the host's recipe executor (rotation, write-back, `must_equal_field`), the exported-attribute
channel (`ProviderConfig.declared`, boundary record §13.8) and a credential handover from the host's native Codex rows —
and, by §0, the recorded staging measurement. Hosts that only re-pin serve what they served before.
