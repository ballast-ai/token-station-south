# Release 0.86.0: the family catalog

Status: released, tag `v0.86.0` (#356, commit `4a712dfe`).

Date: 2026-11-24

Records: [the family catalog](2026-11-24-family-catalog.md),
[CI as the verification gate](2026-10-16-ci-as-the-verification-gate.md),
[boundary record](2026-09-30-host-zero-vendor-boundary.md) §13.11 (catalog data) and §13.12 (Q47),
[release 0.85.1](2026-11-19-release-0.85.1.md).

A minor release: it adds a release data artifact and one public host-side interface. No package changes identity.

## 1. What this release carries

- **The family catalog** (#355, issue #354). `family-catalog-v0.86.0.json`, schema `south.family-catalog.v1`, is
  published beside the model catalog and listed under `catalogs` in the release index. It gives every
  `provider-adapter-v2` and `task-adapter-v2` family a zh-CN / en display name and description, a group (provider
  families) and a modality (task families), with translated descriptions of the config keys and credential fields the
  packages declare. The release index refuses a catalog that misses a declared family or describes one, or one of its
  keys, that no package declares.
- **`fuzz/Cargo.lock` takes `url` 2.5.9** (RUSTSEC-2026-0592), carried by #355. The component lockfiles still resolve
  `url` 2.5.8: updating them re-identifies every package, so it waits for a package round (§7).

## 2. API changes

- `south-core` 0.86.0 adds `FamilyCatalogV1` and its types, `declared_families_v1`, and depends on `serde_json`.

`south-core` is host-only: no component links it, so no component lockfile, `component.wasm` or package identity
changes. South contract numbers and the kernel tuple are unchanged (`canonical_ir` 5, `stream` 3).

## 3. Hosts

A host re-pins to the 0.86.0 tag and release index, and installs `family-catalog-v0.86.0.json` beside the index (the
server host's fetch script installs every catalog the index lists). The packages are the ones 0.85.1 published.
Labeling the family pickers from the catalog is the host's change.

## 4. Package identities

Every package keeps the identity 0.85.1 published. Declared runtime: unchanged.

## 5. The release bump

Step 1 of boundary record §13.12:
- `[workspace.package] version`, 0.85.1 → 0.86.0;
- `compatibility.json` `release.version`;
- the requirements on the workspace-versioned crates in `south-provider-conformance`, `south-testkit`,
  `south-transport-reqwest` and `fuzz`;
- the release-number literal in the workflow test (`rust_library_version_is_independent_of_component_runtime_identity`);
- `fuzz/Cargo.lock`;
- `ARCHITECTURE.md`, `README.md` and `docs/releases.md`; the 0.85.1 record's status.

## 6. Verification

The gate is the release pull request's CI run. On `release/*` branches the `components` job runs
`scripts/check-declared-runtime.sh --build`, and `crate-versions` and `language` run as well. The release workflow
runs on the tag; its `release_index.py generate` step checks the family catalog against the archived manifests.

## 7. Not verified

- No host has loaded the catalog yet; the server host's adoption follows the re-pin.
- The scheduled fuzz target `contract_parsers` does not cover `FamilyCatalogV1::parse`.
- RUSTSEC-2026-0592 in the component lockfiles (`url` 2.5.8, through `south-contracts`): not assessed here for
  reachability from a component, and not fixed, because the fix re-identifies every package.
