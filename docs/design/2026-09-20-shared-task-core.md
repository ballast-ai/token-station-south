# 共享任务执行核心候选

本次新增 `south-task-core` Rust 库，独立版本 `0.1.0`，不修改已发布的
八个 South 库、v0.31.0 组件运行时、Task5 / HTTP9 或七个 Wasm 包身份。
候选先由两宿主固定源码接入；正式发行方式另行确定，不冒用原 tag。

本轮发行方式确定为：两个新 Rust 库独立版本 `0.1.0`，宿主固定完整 Git 提交；
原八包继续固定 `v0.31.0`。不创建 `v0.1.0` 组件发行 tag，不重发已有七包，
不改变旧任务持久绑定。这一区分避免仅新增编排库就迫使既有任务排空。

核心只共享提交、一次观察、同步观察应用、等待和取消的调用顺序。
宿主提供有类型的效果接口；准备/派发闸/结果提交分别保持原复合原子事务，
任务、资金、租约与 outbox 不拆成独立回调。宿主仍拥有凭证解析、精确执行
身份恢复、计价、预占、退费、重试政策和交付许可。核心没有数据库、秘密、
网络、环境、后台任务、隐式时钟或组件 IR 依赖。

提交先准备，重放/冲突立即返回；只有赢得原子派发闸才能执行一次 send。
send 错误只代表受理未知，记录 Unknown；其他效果错误原样返回，不重发。
记录结果的 CAS 落败必须回读权威持久结果；不得返回本轮网络结果冒充赢家。
宿主恢复句柄包含原绑定及租约事实，核心不查询当前目录或换用最新组件。
取消执行 future 并不保证上游未受理：派发闸须先持久化，宿主恢复处理歧义；
核心不会在 Drop 中写数据库，也不承诺进程崩溃后自行完成结果提交。

观察先加载宿主恢复计划，再查询、归一化/政策映射、原子应用。同步直喂复用
同一 apply→CAS 落败回读函数。私有费用 token 由宿主关联类型携带，核心不
把供应商 Cancelled 等同免费，也不将未知费用释放。计费 held 与执行状态
分轴，宿主等待投影只能把允许交付的结果列为 Ready。

等待显式注入单调时钟、sleep 和取消信号。核心负责循环、剩余预算及竞争，
取消优先于到期，到期优先于本次读取结果；读取与等待都受预算限制。
每次 inspect 可读取状态或调用共享 observe 推进一步；禁止宿主复制等待循环。
超时/取消本身只退出当前等待，不取消上游任务或修改资金；观察到的事实仍由
宿主正常原子结算。中断查询/事务不能保证撤销已提交效果，宿主须保持可恢复。
零间隔明确拒绝。
取消任务使用另一接口：宿主授权/读态、prepared 原子取消，失败后只记录
取消意图；记意图必须重新原子守卫终态，不能覆盖已结束任务。

效果方法使用 `&mut self` 和 Send boxed future，避免为了仅执行一次的宿主
future 强制 Mutex 或 Sync。关联业务类型不要求 Debug/Serialize/Clone。
公共接口不吞掉过程：prepare、dispatch、send、record，以及 load、query、
normalize、apply、reload 分离；核心真实拥有顺序和所有 CAS 落败路径。

验证先公开行为红测，再最小实现；确定性时钟和故障效果替身验证核心顺序，
不将其冒充数据库原子性证明。两宿主通过独立公共 conformance 故障套件验证
真实存储和复合原子效果。最终运行 README 全部 16 项，本地事故不超过 60 秒。
