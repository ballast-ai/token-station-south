## 1. What this release carries

- **`served_models`** (issue #299): every task, image and speech family declares the upstream model ids it serves,
  as `ids`, `prefixes` or `any: true`. Gate ① requires it for every family of those worlds and refuses it in the
  provider and embeddings worlds. A host refuses a model route whose upstream id (for an alias row, its
  `upstream_model_family`; record §8 I-1) the routed family does not serve.
- **`required_prefetch`** (issue #299): the two Veo families and `vertex-interactions-video` list the request fields
  they accept only as `data:` URIs, so a host refuses a route whose `fetch_images` misses one when the route is
  written instead of at the first image.
- **Task contract 9** (issue #302): a failed task observation may carry `category` (`content_policy`,
  `upstream_timeout`), set only from an explicit upstream signal. `task-veo-v2` reports `content_policy` when
  `raiMediaFilteredCount` is above 0 and is the one package on contract 9. No other family has a captured signal yet
  (record §8 I-5).

## 3. Hosts

A host breaks at compile time on re-pin, by design:
- a `TaskObservationV2::Failed { kind, code, message }` pattern or literal needs `category` (or `..`);
- an exhaustive match on `ManifestErrorV1` needs the five new arms;
- a host that builds `WorldSchemaV1` values (none known) needs `served_models`.

Behaviour a host takes on (record §6):
1. Route writes (task and image routes): refuse an upstream id outside the family's `served_models` (400) and a
   `fetch_images` that misses the family's `required_prefetch` (400). Match the shape id (I-1).
2. Deployment checks: the same two rules, read from the installed packages.
3. Map `category` `content_policy` → `error.reason` `content_policy`, `upstream_timeout` → `upstream_timeout`; absent
   keeps today's mapping.
4. A host's range for `task` admits 9; a host whose range stops at 8 refuses `task-veo-v2` 0.39.0 by name.
5. Host test fixtures that load a synthetic task, image or speech manifest need `served_models`, and routes in host
   tests need upstream ids the routed family serves.

## 4. Package identities and declared runtimes

Pull request #305 already moved every identity: every task, image and speech package took a minor (it declares
something new), every provider and embeddings package the Q47 patch, for example `task-veo-v2` 0.38.0 → 0.39.0,
`image-qwen` 1.1.1 → 1.2.0 and `provider-openai-compatible` 2.13.4 → 2.13.5.

Declared runtime: **every task, image and speech package (29 packages) raises `south_runtime` to 0.81.0**. Each
declares `served_models`, and `ComponentManifestV1` is `deny_unknown_fields`, so an older runtime's gate ① refuses
the manifest. The 12 provider and embeddings packages keep 0.77.0. The release index is expected to list 41 packages
and 1 catalog.

## 6. Verification

The gate is the release pull request's CI run. `quality` includes `scripts/check-declared-runtime.sh --build` on
`release/*` branches; `crate-versions` and `language` run as well. The release workflow runs on the tag.

Local checks on this commit, each judged by its own exit code: `cargo fmt --all -- --check`,
`cargo clippy --workspace --all-targets --all-features -- -D warnings`, `cargo nextest run --workspace --all-features`
(2448 tests), `scripts/check-language.sh`, `cargo metadata --locked` for every component, guest, `fuzz` and the root,
and `python3 scripts/check_crate_versions.py --unreleased`.

The tag itself is not created here.
