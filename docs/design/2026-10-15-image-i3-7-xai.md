## 2. Scope: the six Grok Imagine ids, generation and JSON edit

The native arm is not a provider type: xAI rows are `provider_type = openai` and the arm is selected by the provider
row's **name** `xai` plus `is_xai_imagine_image_model` (`server:…/handler/images/xai.rs:20-24`; `handlers.rs:186`,
`:1839`; `openai_compat.rs:263-264`; `execute.rs:172-173`). That predicate accepts six upstream ids:

| Id | Card (`media.rs:813-821`, `:880-882`, `:980-1010`) |
|---|---|
| `grok-imagine-image` | standard: one card, 2K priced as 1K |
| `grok-imagine-image-quality`, `-pro`, `-quality-latest`, `-quality-20260403` | quality family: own card, plus the "2.0 low" successor card natively |
| `grok-imagine-image-2.0` | `low` / `medium` quality cards; `auto` lets the upstream choose |

- **Generation** (`/v1/images/generations`): the OpenAI-compatible fallback forwards the client's body to
  `{endpoint}/v1/images/generations` with `model` rewritten (`openai_compat.rs:41-99`), after the xAI resolution
  normalisation (`handlers.rs:183-189`), and returns the upstream bytes to the client unchanged (`openai_compat.rs:
  107-113`).
- **Edit** (`/v1/images/edits`): JSON only (`handlers.rs:1754`, `:1839-2108`), posted to `{endpoint}/v1/images/edits`;
  the multipart shape is refused with a dedicated text (`handlers.rs:847-856`).

The model catalog already carries all six ids (`catalogs/model-catalog.json`: `resolution` options `1k` / `2k` with
default `1k`, `input_image` maxima 3 and, for 2.0, 5). **XI-Q1**: exactly these six ids, both operations; another id on
an xAI row (for example a retired `grok-2-image-*`) is not declared, so the host refuses it before admission.

## 3. Request (`prepare`)

### 3.1 Operation (XI-Q2)

Both surfaces send a JSON view; the host checks `facts.operation` against the endpoint and answers 400 on a mismatch
(record Q4; `component/mod.rs:1607-1612`), so the component infers it from the view: a body with a **non-null**
`image`, `images`, `image_url` or `image_urls` is an edit, any other a generation. A multipart view is refused with the
native text ("/v1/images/edits for xAI grok-imagine models requires Content-Type: application/json …").

### 3.2 Generation

Reproduces `normalize_xai_image_generation_body` (`xai.rs:26-30`, `:338-378`, `:392-405`) and the fallback:

- **Descriptor**: `POST v1/images/generations`, `{"arm": "bearer", "slot": …}`, body `json` whose template is the
  client's body with every field the native arm does not touch passed through (record §6.2: an elided string is
  re-emitted as an `as_is` reference), `model` set to the upstream id, `size` removed and `resolution` replaced as
  below. No headers (the host writes `content-type`).
- **`resolution`**: `resolution` when present and not `null` (must be a string), otherwise `size` (must be a string);
  the text is trimmed, lower-cased, stripped of spaces, `_` and `-`, `*` read as `x`; `""`, `1k`, `1024`, `1024x1024`
  → `1k`, `2k`, `2048`, `2048x2048` → `2k`, anything else 400 with the native text echoing the value as sent. When
  `resolution` wins, `size` is removed unread (even a non-string). A derived word replaces `resolution`; with neither
  field, nothing is sent and the billed word is `1k` (`xai_resolution`, `:380-390`).
- **`quality`** (2.0 only, `xai_requested_quality`, `:168-191`): trimmed and lower-cased for the tier; `low` / `medium`
  pin the tier, `auto`, absent or `null` leave it to the upstream; anything else is refused with the native text. The
  value is **forwarded as the client wrote it** (native prices `" MEDIUM "` as medium and sends `" MEDIUM "`). Other ids
  forward `quality` unread.
- **`n`**: the handler's strict count (`handlers.rs:127-144`): absent or `null` 1, an integer or whole float, 1 to 10,
  with the native texts. The client's `n` is forwarded as written.
- **Order of refusals**: `n`, then the resolution, then the quality, as native.

### 3.3 Edit

Reproduces `normalize_xai_image_edit_body` (`:32-105`) and `xai_image_edit_input_count` (`:111-144`):

- **Descriptor**: `POST v1/images/edits`, `bearer`, the same pass-through template and resolution rule (`size` removed).
- **Aliases**: `image_url` / `image_urls` are removed; if `image` or `images` is non-null and either alias key is
  present (even holding `null`, as native `obj.remove(..).is_some()`), 400. Otherwise a string `image_url` becomes
  `image: {"type": "image_url", "url": …}`, an array `image_url` or `image_urls` becomes `images` (each entry must be a
  string), other shapes are refused with the native texts.
- **Count**: `image` and `images` both non-null → 400; `image` counts **one whatever it holds**; `images` must be an
  array and counts its length; neither → 400. Zero is refused (text: "need at least 1 input image, got 0", §7 P4); more
  than 64 (the contract's per-role cap) is refused. The per-model maximum (3, or 5 on 2.0; `XAI_DEFAULT_EDIT_INPUT_CAP`
  3 when no capability profile, `:109`, `precheck.rs:178-182`) is **catalog data** (record §8, R-1 = A): the host
  enforces `media.roles.input_image.max` against the reported count.
- **`n`** 1 to 10 with the native edit text ("… for xAI /v1/images/edits, got N"); `quality` as on generation.
- **Order of refusals**: `n`, resolution, aliases, count, quality, as native.
- **Elision**: `model-capabilities` declares `/image`, `/image/url`, `/images/*`, `/images/*/url`, `/image_url`,
  `/image_url/*` and `/image_urls/*`, so a source image's string (usually a data URL) never enters the sandbox; each is
  forwarded `as_is` (record §6.4: "xAI forwards the client's data URL unchanged").

### 3.4 Facts

- `operation` per §3.1; `inputs.input_image` the count (edit), 0 on generation; `requested_outputs` `n`; no `size`
  (never forwarded; the resolution word is the fact); no `bounds`; `metering_forms` `[images]`.
- **Tier words** (H5 plan §8.2, lv 2026-10-14 X-Q1 = b, X-Q2, X-Q3 = a; record R-2: xAI's spelling):
  - `tier.resolution`: always, `1k` or `2k` (the billed word, `1k` when the request names none).
  - Standard and quality-family ids: no `quality`, no candidates. The quality family's native "2.0 low" successor card
    (`media.rs:1000-1004`) is not modelled (X-Q1 = b).
  - 2.0 with a pinned quality: `tier.quality` `low` / `medium`, no candidates.
  - 2.0 with `auto` / absent: `tier` carries the resolution only, `tier_candidates` = `[{res, low}, {res, medium}]`
    (native order, `media.rs:991-996`) with `default` `{res, low}` on a generation and `{res, medium}` on an edit
    (`media.rs:993-996`). The host prices the default and every candidate (`tiers.rs:91-104`).
- `immutable_body_paths`: generation `OPENAI_COMPAT_IMAGE_OWNED` (`model`, `n`, `size`, `image_size`, `quality`,
  `resolution`, `response_format`, `execute.rs:32-40`); edit `XAI_IMAGE_EDIT_OWNED` (`model`, `n`, `resolution`,
  `quality`, `image`, `images`, `execute.rs:65-67`). `size` on a generation means "stays absent".
- `state` `{}`; `response_elision_paths` `/data/*/b64_json`.

## 4. Response (`parse-response`) and render

- **Non-2xx**: code by status (`image_shared::status_code`), `provider_message` from xAI's `{"code", "error"}` body's
  `error` string, else `error.message`, else `message` (shape **unverified**, as `speech-xai`); `rejected` for a 4xx other
  than 408, else `unknown`.
- **2xx**: a body that is not a JSON object, or a missing / non-array / empty `data` → `unknown`. Each entry: a
  non-empty `b64_json` → `inline` base64 artifact with media type `image/jpeg` (XI-Q3); else a non-empty `url` → `url`
  artifact with no declared media type (the host sniffs it, I3-5 IG-Q2); else → `unknown` for the whole round (XI-Q4).
- **Metering**: `images_reported` `null` (xAI reports no count; the host counts delivered images); `upstream_cost` from
  `usage.cost_in_usd_ticks`, read as native reads it (`xai.rs:251-256`: a JSON integer within `i64`), converted to decimal
  dollars (1 USD = 10^10 ticks, `media.rs:876-877`), trailing zeros trimmed (`200000000` → `"0.02"`, `1` →
  `"0.0000000001"`, `0` → `"0"`). A negative value is reported absent. The host takes the first of default, then
  candidates, whose list price equals the quote, else the default with a warning (`tiers.rs:167-205`), which is
  `settle_xai_image_cost` (`media.rs:1052-1097`) written generically.
- **Render**: the native client body is the upstream bytes. The component carries the upstream body in `extras` as a
  skeleton (each image field and every host placeholder `null`) and the render puts `{"$south.artifact": {"index": i,
  "as": "b64_json" | "url"}}` where each image was, in the form the upstream answered in (which is the form the client
  asked for, since `response_format` is forwarded). `created`, `usage`, `revised_prompt` and any other field pass
  through. If the skeleton exceeds 48 KiB (the outcome frame holds 64 KiB), the rewritten prompts are dropped first,
  then everything but `created`, `usage` and one empty object per image (§8 interpretation 3). `model-capabilities`
  declares `response_formats` `[url, b64_json]`.

## 6. Doubts registered as unverified (reproduced, not blocking)

1. **Response shape**: `{"data": [{"url" | "b64_json", "revised_prompt"}], "usage": {"cost_in_usd_ticks"}}` is taken from
   the native unit tests (`xai.rs:553-560`), not a capture.
2. **Image format**: JPEG is assumed for `b64_json` (xAI's URLs in the test fixtures end in `.jpeg`); native held storage
   sniffs and falls back to `image/png` (`durable.rs:1322-1323`).
3. **Raw `quality` forwarded**: whether xAI accepts `" MEDIUM "` or `"Auto"` as sent is unknown; native sends it so.
4. **`auto` defaults** (generation `low`, edit `medium`) follow a native comment on xAI's documentation
   (`media.rs:856`, `:975-978`), not a capture.
5. **The quote equals the list price**: recognition assumes `cost_in_usd_ticks` is exactly the list price of the served
   tier (native assumption, `xai.rs:258-259`); negotiated prices fall back to the default tier, as native.
6. **The quality family's slug retirement** (to 2.0 low, 2026-11-02) is xAI's announcement as native records it; X-Q1 = b
   leaves it to operators.
7. **Error shape** `{"code", "error"}` as `speech-xai` records it.
8. **Generation with a source-image field**: native forwards it to `v1/images/generations`; what xAI does with it is
   unknown. The component reads such a body as an edit (XI-Q2), so the host refuses it.

## 7. Differences from native

Following precedent (accepted under lv's 2026-10-13 pre-approval):

- **P1 Billed count**: the host bills the delivered images (record §9.1); native bills the requested `n` on both
  surfaces (`openai_compat.rs:267`, `handlers.rs:1898-1903`), even when fewer or none came back.
- **P2 Funds on non-2xx**: the P29 allow-list on both paths (P22 Q2, I3-1 IM-Q2); native sync edit parks every status
  ≥ 400 (`handlers.rs:2042-2052`).
- **P3 A 2xx without images** (missing / empty `data`, an entry without an image) parks (`unknown`, 502); native sync
  charges `n` and passes the body through.
- **P4 Generic refusal texts**: an undeclared id → 503 (host); zero input images → "need at least 1 input image, got 0"
  (native "support 1..=N input images, got 0" names the catalog maximum the package does not carry); an elided
  `resolution`, `size` or `quality` → "'{field}' is longer than the gateway accepts".
- **P5 Verify-then-settle** on `b64_json` and `url` (record §10.2; I3-1, I3-5): an undeliverable artifact parks.
- **P6 Token-priced xAI rows** are refused 503 before admission (I3-4 §5 item 3, I3-5 P12); native would take the
  token path and answer 502 for a missing `usage` block (`openai_compat.rs:220-261`).
- **P7 Tier pricing from the host's tier table** (Q8 / H5): reservation is the dearest of default and candidates
  (native `xai_image_cost_upper_bound`, `media.rs:1016-1027`, same rule); the warning metric is
  `gateway_image_tier_unrecognized_total`. A negative quote is reported absent, so its reason is `no_report` where
  native counts `unrecognized`; the bill is the same.

New, registered:

- **P8 Quality family successor card** (X-Q1 = b, ruled 2026-10-14): native also recognises the 2.0 low price on a
  quality-family row; the package reports no candidate there.
- **P9 Precheck on the raw view (a host-side difference)**: native normalises `resolution` before its catalog precheck
  (`handlers.rs:183-195`; `parse_xai_resolution_hint`, `xai.rs:392-405`: trimmed, lower-cased, ` `, `_` and `-` removed,
  `*` read as `x`), so it accepts `""`, `1024`, `1024x1024`, `1024*1024`, `2048`, `2048x2048`, `2048*2048`, `2_k`, `2-K`
  and `1_K` in `resolution`. The executor prechecks the client's raw body (`component/mod.rs:1661-1669`), and
  `resolution_admitted` (`capabilities.rs:1601-1618`) only strips whitespace, lower-cases and drops a `p` after digits, so
  against the catalog options `1k` / `2k` every spelling above is refused 400 before admission, although `prepare` accepted it; `1k`, `2K` and
  ` 2 k ` pass both. `size` is unaffected (the xAI catalog entries declare no `size` or `pixels`). The component itself
  normalises every native spelling exactly as native does (§3.2; pinned by `the_resolution_table_is_the_native_one` and
  the `generate-resolution-*` fixtures), so the only gap is the host precheck: a host fix is to precheck the prepared
  facts' tier words, or the template's `resolution`, instead of the raw `resolution`.
- **P10 Operation inference** (XI-Q2): a generation body naming a source image, or an edit body naming none, is refused
  400 by the host's operation check with its own text; native forwarded the first and refused the second with "xAI image
  edits require an `image` object or `images` array".
- **P11 Input count of an array-valued `image`**: native billed it as one image but its catalog precheck counted the
  array's length (`precheck.rs:65-71`, `:172-174`); the package reports one for both.
- **P12 The upstream body in `extras`** is bounded (§4); native passes any size through.

## 10. Open questions (each default implemented)

- **XI-Q1 Scope.** The six ids, generation and JSON edit. **Default: yes.**
- **XI-Q2 Operation from a JSON view.** (a) Edit iff a source-image key is non-null; (b) edit iff a source-image key is
  present, `null` included (reproduces native texts for `image_url: null` on an edit, but refuses a generation whose
  SDK writes `image: null`). **Default: (a).**
- **XI-Q3 `b64_json` media type** (an `inline` artifact must name one). (a) `image/jpeg`; (b) a host sniff for inline
  artifacts too (a contract-free host change). **Default: (a)**, until a C10-style capture.
- **XI-Q4 A 2xx entry without an image.** (a) `unknown` for the round (as `image-azure`); (b) skip it and settle the
  others. **Default: (a)**: the native client would have received an entry without an image and been billed for it.
