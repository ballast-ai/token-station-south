## 1. What this release carries

- **#251, A+ (Q-GM2 (a)).** `glm-coding` renders `reasoning.mode` as Z.ai's `thinking.type` when the body has no
  `thinking`: `enabled` and `disabled` are written, `adaptive` and an absent mode write nothing (the upstream default
  decides), and `reasoning.budget_tokens` is never written. A Chat client's own `thinking` (T9-Q9 (a)) still wins. Every
  other family is unchanged. With Q-GM1 = O1, this is what lets a Messages client of a `glm-coding` row keep its
  thinking switch on the IR path.
- **#250, a codec defect.** The Anthropic north codec mapped `tool_choice: {"type": "none"}` to no choice, so a
  Messages client that forbade tool calls had its tools sent with no choice. It now maps to `ToolChoice::None`, which
  every dialect already renders. `south-north-codec` is not guest-linked, so this moves no package identity.
- **#249, the GLM Messages record.** The difference surface of the IR path against native's pass-through, ruled by lv
  (Q-GM1 = O1, Q-GM2 = (a), Q-GM3 = register the remainder).
- **#244, CI and local verification.** Every component package builds into one shared target directory through
  `scripts/component-build.sh`, and the wasm is copied to the path the tests and this workflow already read. This is the
  first release built that way.

## 2. API changes

- `south-component-conformance` 0.67.0 → 0.68.0: the A+ rendering, its fixtures and the suites.
- `south-north-codec` (workspace-versioned): the `tool_choice` fix. A behaviour change, not an API change.
- `south-contracts` (0.56.0) and `south-provider-api` (0.59.0) are unchanged. No contract number changes; the kernel
  pin is unchanged.

## 3. Hosts

This release has no breaking API change. Two behaviour changes on re-pin:
- On every component row, a Messages client's `tool_choice: {"type": "none"}` now forbids tool calls, once the host
  admits it. **Corrected 2026-10-16:** the server host's text billing admission refused `none` with 400 before either
  arm (so native did not pass it through either); lv ruled the same day that the host admits it (GLM Messages record
  §4).
- On a `glm-coding` row, a Messages client's `thinking` `enabled` / `disabled` reaches Z.ai as `thinking.type`.

Host follow-up (GLM Messages record §7, the host's work): the T9 dual run's Q-T9 case becomes a registered-difference
case for R2, R5, R8–R12 and S1–S6; preflight T9G4 stops holding Messages models on the native arm; the T9 cutover
handbook drops the Q-T9 hold. With Q-GM2 (a), a `-thinking` alias row's `keep_existing` extra injects `enabled` for an
`adaptive` client, where native passed `adaptive` to Z.ai; that is registered with the rest.
