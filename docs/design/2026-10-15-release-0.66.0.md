## 1. What this release carries

- **#230, #232, `provider-vertex` 1.0.0**: Gemini models on Vertex AI for text, family `vertex-ai`
  (`provider-adapter-v2`), `bearer` on the slot minted by the `vertex_sa` recipe, `generateContent` on every surface
  (VX-Q1 (a)); the Gemini reference's request, response and stream code is shared, `provider-gemini` unchanged. Declares
  `north_request_passthrough` `{"vertex-ai": "generate_content"}` (D7). This change moved
  `south-component-conformance` 0.64.0 → 0.65.0 and took this cycle's Q47 patch round (§4).
- **#231, #234, `task-veo-v2` 0.36.0**: the family `vertex-veo-video`, reproducing the native Vertex Veo arm (submit
  `:predictLongRunning`, poll `GET {origin}/v1/{operation}`, the Gemini LRO result shape, gated fetch with `bearer`).
  A re-launch under L-Q2: the native line goes offline with V1, so there is no dual run against native; the clip fetch
  and the success shape have no native baseline (native never fetched a Vertex clip) and are registered as unverified.
- **#235, `image-xai` 1.0.0** (image world step I3-7): xAI Grok Imagine generation and JSON edit, family `xai-image`,
  tier words and candidates per the host's tier price list (H5 §8, X-Q1 to X-Q3), evidence `upstream_cost` from
  `cost_in_usd_ticks`.
- **#236, `provider-anthropic` 1.2.0**: the families `claude-code` (login token from the `claude_code` recipe,
  presented in `x-api-key`, the CLI beta set, identity block and user agent) and `claude-code-setup-token` (static
  Bearer, `oauth-2025-04-20`).
- **#237, `provider-openai-responses` 1.4.0**: the family `bedrock-mantle` (`https://bedrock-mantle.{region}.api.aws`,
  required `region`), and its fixture pack; chat on Mantle stays servable by `openai-compatible`.
- **#233, #238, `image-reve` 1.0.0** (I3-6; RV-Q0 lifted 2026-10-15): the two OpenAI-surface Reve bridges, the endpoint
  read from the route's `endpoint` pin, `credits` metering, the first package to return `charged_failure`. The image
  suite's `missing_meter_is_not_zero` now also judges `charged_failure`; no other package returns it.
- **#239, `speech-vertex` 1.1.0**: Q7's refusal (`mp3`, `opus`, `aac`, `flac` are `invalid_request` before
  dispatch), moved into this release by lv on 2026-10-15 instead of waiting for the host's Vertex TTS dual run.
- **#240, `provider-openai-compatible` 2.7.0** (host plan T9): the families `glm-coding` (Coding Plan path, user agent
  `opencode/1.15.6`) and `azure-openai-dated` (deployment path, `api-version`, default `2024-10-21`, `api-key`).
- **The release commit** (this branch): the release bump (§5) and the release notes (README, ARCHITECTURE v0.66.0
  paragraph and runtime version, this record).

The kernel pin is unchanged (mirror `v0.5.0`, `canonical_ir` 4).

## 3. Hosts

None of these packages is served before host adoption; each record's host prerequisites apply (re-pin, bindings or
component rows, routes, a dual run where a native arm exists, and the cutover preflights). Notable ones:

- `provider-vertex`: D7 step 3 (route `component` rows of family `vertex-ai` on `/v1beta`); the dual run should focus
  on `/v1/messages`, the one surface whose upstream wire changes.
- `vertex-veo-video`: if Vertex returns operation names with the project number while the binding uses the project id,
  the host's `authorize` refuses the poll (unverified).
- `image-xai`: write tier tables before routes; the host's raw-view precheck refuses `resolution` spellings native
  accepted (record §7 P9).
- Claude Code: split native rows by form, migrate credentials; H1 (a minted slot presented in `x-api-key`) works by
  reading the host code but has no host test yet.
- Bedrock Mantle and T9: a generic host model-suffix mechanism for component rows (`-high`, `-thinking`), or accept the
  difference; `glm_coding` Messages clients stay native until the translated path is accepted.
- `image-reve`: `request.set` pins on image routes, the generic credits path and `charged_failure` settlement (RV-Q2 to
  RV-Q4); until they land a routed Reve row is refused before admission.
- `speech-vertex` 1.1.0: a host dual run on 0.66.0 sees the 400 on the four transcoded formats as a registered
  intentional difference.
