**Packages, per SV-Q1 (b).** lv ruled on 2026-10-14 that ASR for a family that already has a TTS package arrives as a later
version of the same package adding `transcribe`, not as a separate package. So OpenAI-compatible, xAI and ElevenLabs ASR
are versions of the three V3-1 packages. Azure has no TTS package yet (Azure SSML TTS is V4), so V3-3 creates
`speech-azure`, and V4 adds `synthesize` to it as a later version, the same rule applied in the other order. Groq's
Whisper rows go through the native OpenAI-compatible arm today (`AsrUpstream::resolve` selects Groq only for TTS,
`audio.rs:91-101`), so they bind to `speech-openai-compatible`; `speech-groq` stays TTS-only. MiMo and MiniMax have no ASR
arm. Whether the three existing packages move their version number is §10.

Order of implementation: OpenAI-compatible (it carries `client_format_rendering` and translation), xAI (the same response
shape), ElevenLabs (word-derived duration and rendering), Azure (a new package). All four come after V3-1 and are
independent of V3-2.

**Common to the four packages** (speech world `speech-adapter-v1`; V3-1 §1 applies unless stated here):

- **Manifest**: `capabilities` gains `transcribe` (and `translate` for `speech-openai-compatible` only); `auth_arms`,
  secret and `contracts` unchanged (`speech-azure`: `["header_secret"]`, `provider_api_key`, `{media: 1}`, `south_runtime`
  0.64.0, no `config_schema`). `contracts.speech` is added at S-S-5 with the other speech packages (V3-1 Implementation,
  "Points that contradict the record").
- **`model-capabilities`** (V3-1 §1 precedent): every configured model of the bound row declares every operation the
  package performs, with `translate` only on a row carrying `speech.translate` (record §4, the intersection with the row's
  words); `metering_forms` = the V3-1 forms plus `seconds` (`speech-openai-compatible` `[characters, tokens, seconds]`,
  `speech-xai` and `speech-elevenlabs` `[characters, seconds]`, `speech-azure` `[seconds]`). Which rows are routed to the
  package, and which surface a row may serve, is the host's route plus its modality check (`tts` for synthesis, `asr` for
  recognition; §6 item 1), not a model list in the wasm (record §4, §15).
- **Facts for recognition**: `operation` = `context.operation` when the package and model declare it, else `capability`
  "the model '{id}' does not declare the operation {word}" (V3-1 interpretation 7; the `undeclared_operation_refused`
  row); `metering_forms` = `context.metering_required` when it is exactly `[seconds]`, else `capability` "this model cannot
  report {form}" (record §8: ASR is priced per second, `calculate_audio_cost`, `audio.rs:339-340`); no `characters`, no
  `output_media_type`, no `reservation` tightening (the host reserves `asr_max_billable_seconds`, today's amount).
- **The request view** is the host's multipart view `{"multipart": {"parts": [...]}}` (record §5). Refused before
  dispatch, `invalid_request`: a body that is not multipart ("a transcription request is a multipart body"); a text part
  above the 1 MiB fallback (elided) ("a text field is longer than the gateway accepts", the `image-azure` text); no file
  part named `file` ("Missing 'file' field"); a `stream` part whose value is `true` (ASCII case-insensitive) or `1`
  ("streaming transcription is not supported; re-submit without `stream` or with `stream=false`"), the host image
  executor's predicate (`image_view.rs:174-177`), which the host also applies before admission (§6 item 4).
- **Client format**: the value of the first text part named `response_format`, absent = `json`. The OpenAI audio set is
  `json`, `text`, `srt`, `verbose_json`, `vtt`; any other value is refused before dispatch `invalid_request` "Unknown
  response_format='{f}'. Supported: json, text, srt, verbose_json, vtt." (`speech-azure` has its own set and texts, §5).
  Values are compared exactly, except by `speech-azure`, which trims as native does.
- **Part list**: built from the view in order (the `image-azure` edit precedent): a file part is forwarded as a `File`
  part with transform `as_is`, its `filename` and `media_type` as the view gives them; a text part as a `Text` part with
  its value; each package names the parts it renames, replaces, drops or appends. A part the package writes itself is
  replaced in place where the client sent it and appended at the end where the client did not (the synthetic reference's
  rule).
- **Descriptor**: `POST`, the multipart body, no `content-type` (the host's multipart encoder renders it from its boundary),
  the auth arm on slot `provider_api_key`.
- **`immutable_form_fields`**: native's `owned_form_fields` for the arm, upstream names (`audio.rs:74-81`), per section.
- **`state`**: `{"op": <operation>, "format": <client format>, "verbose": <bool>}` (`speech-openai-compatible` and
  `speech-xai`), `{"op", "format"}` (the other two); no secrets, far below 8 KiB.
- **Duration value rule** (all four): a reported duration is used only when it is a JSON number that is finite and above
  0; present but `0`, negative, non-finite or not a number is `unknown` ("a malformed duration"). Absent is per package
  (`null` or `unknown`, §2 to §5). `seconds.value` is the number as an f64, unrounded.
- **Transcript `text`**: where a delivery needs the upstream's `text` and it is absent or not a string, the outcome is
  `unknown` ("a 2xx without a transcript"); `""` is a transcript (silent audio). A 2xx body that is not a JSON object where
  the call declared `json` is `unknown`.
- **Delivered media types**: a JSON document is exactly `application/json` (the suite's `delivery_fits_format` compares it
  as a string, `speech_suite.rs:867-876`); a rendered `text` is `text/plain; charset=utf-8` (native Azure's label,
  `multipart.rs:400`); a rendered `srt` is `application/x-subrip` and `vtt` `text/vtt` (the synthetic reference); a
  passed-through text document carries the upstream `content-type` when it passes `is_speech_media_type`, its essence
  when that passes, else the format's type from the list just given (V3-1's `delivered_media_type` with a format
  fallback; §8 P8).
- **Rendering `srt` and `vtt` from timed units** (`asr_shared.rs`; public formats, record §9): cues in order; a cue's
  time is `HH:MM:SS,mmm` (`vtt`: `.`) from seconds rounded to the millisecond; an `srt` cue is its 1-based index line, the
  `start --> end` line, the text trimmed, and a blank line; a `vtt` document starts `WEBVTT` and a blank line, and its cues
  have no index. A unit whose `start` or `end` is not a finite non-negative number, or whose text is not a string, makes
  the outcome `unknown`; an empty unit list renders an empty document (`""`, or `WEBVTT` and a blank line). A rendered
  document above 1 MiB is `unknown` (the synthetic reference; a `text` delivery holds at most the fallback threshold).
- **Non-2xx**: V3-1's `non_2xx` (status table, `rejected` for a 4xx other than 408, else `unknown`, a 3xx `unknown`) with
  each section's `provider_message` source.

## 2. `speech-openai-compatible`: `transcribe` and `translate` (record §12 ASR row 1)

Reproduces `AsrUpstream::OpenaiCompat` (the fallback of `AsrUpstream::resolve`, `audio.rs:91-101`; body at
`audio.rs:226-235`; URL `audio.rs:284-287`; response `audio.rs:559-564`). Translation is this arm's only, as native
(`supports_translation`, `audio.rs:87-89`).

- **Path**: V3-1's API-root rule (V3-1 §2, P11): `audio/transcriptions` or `audio/translations` below the binding's
  `base_url` path, or `v1/audio/…` when the `base_url` is an origin (native `{endpoint}/v1/audio/…`, with the provider-type
  rewrites of `upstream.rs:425-592` expressed by the binding's API root).
- **Auth**: `bearer` (native `upstream.rs:66-72`).
- **Parts**: every part forwarded; every text part named `model` gets the routed upstream id (appended when absent);
  native splices the first byte occurrence of the gateway model name anywhere in the body (`audio.rs:226-234`, §7 D1).
- **Verbose rows** (the routed model's row carries `speech.verbose_json`; record §9): the `response_format` part is set to
  `verbose_json` (replaced or appended); `response_body_form` `json`. Every client format of the OpenAI set is served from
  that response:
  - duration: `duration` by the value rule; absent → `unknown` (the row declares a duration-bearing format; record §9's
    "always reports", Q6, and the synthetic reference);
  - `json` → `{"json": {"text": <text>}}`, the text as a `$south.ref` when the host elided it (S-S-1, the synthetic
    reference);
  - `text` → `{"text": <text>, "media_type": "text/plain; charset=utf-8"}` (an elided text is `unknown`: a `text` delivery
    holds no reference);
  - `verbose_json` → `{"passthrough": {"media_type": "application/json"}}`;
  - `srt` / `vtt` → rendered from `segments[]` (`start`, `end`, `text`); `segments` absent or not an array is `unknown`.
- **Other rows** (record §9 case 1): the client's parts are forwarded unchanged apart from `model`, so the upstream gets
  the client's format; `response_body_form` `json` for `json` and `verbose_json` (and an absent format), `text` for `text`,
  `srt` and `vtt`.
  - A `json` form: duration = `duration` by the value rule; when absent, `usage.seconds` by the value rule if `usage.type`
    is `"duration"` (record §9: whisper's usage seconds count as `reported`, **to be measured**); otherwise `null` (the
    host's 60-second estimate, record §9). Delivery `{"passthrough": {"media_type": "application/json"}}` after the `text`
    check.
  - A `text` form: `{"passthrough": {"media_type": …}}` by the media type rule, `seconds: null`.
- **Translation**: the same rules on `audio/translations`; `translate` is refused unless the row carries
  `speech.translate` (record §4). The output language is not checked by the package (record §4: the host's acceptance test
  with non-English audio, §6 item 13).
- **`immutable_form_fields`**: `model`, `file`, `response_format`, `stream` (= native, `audio.rs:76`).
- **Error body**: V3-1's `openai_error_message`, else the body text.

## 6. What the host must do before a V3-3 cutover (in addition to V3-1 §7 and V3-2 §4)

Every item of V3-1 §7 applies with "synthesis" read as "the speech route"; these are the recognition counterparts,
generic over packages and naming no provider:

1. **Route, modality and surface.** The speech route of V3-1 §7 item 1 serves a row on `/v1/audio/transcriptions` and
   `/v1/audio/translations` (and their `/openai/` aliases) only when the row carries the `asr` modality, and on
   `/v1/audio/speech` only with `tts`. Native has no modality check on the ASR surface: `proxy_audio_multipart` checks
   only the model allow-list and the component-route rejections (`audio.rs:148-165`; no other layer found, **unverified**).
2. **Operation.** `operation` = `transcribe` or `translate` from the route; refused before admission (400, no `prepare`)
   unless the package's manifest and the model's `model-capabilities` both declare it (record §4). Native refuses
   translation on three arms (`audio.rs:181-185`); after cutover the OpenAI-compatible rows that should translate must
   carry `speech.translate`.
3. **Catalog words at cutover.** Set `speech.translate` and `speech.verbose_json` per row from the measurements of §9
   (record §17.5: the operator's or the host catalog's `supported_parameters` is the only path). Before cutting an
   OpenAI-compatible row over, list with a read-only query the rows that have served `/v1/audio/translations` (native
   forwards it for any model on the arm) and lack `speech.translate`: they will answer 400 after cutover.
4. **Northbound view.** `parse_multipart_parts_v1` over the client body with the boundary from its `content-type` (the
   image executor's `image_view.rs:117-133`); a body the parser refuses is 400 before admission (the image precedent);
   `stream=true` or `1` refused before admission (`image_view.rs:174-177`'s predicate and text, adapted). The model name
   stays the host's extraction (`audio.rs:135-136`).
5. **Pricing and reservation** (record §8): `context.metering_required` = `[seconds]`; reserve

### Interpretations

1. **Misspelt dialect words.** `model-capabilities` and `prepare` read a row's words with
   `speech_dialect_words_v1`, so a misspelt `speech.` word refuses the call `invalid_request` "the model row carries a
   misspelt speech dialect word" (the synthetic reference's text, record §4), in all four packages.
2. **`null` is absent.** A duration (or a last word's `end`, or `usage.seconds`) that is JSON `null` counts as absent,
   not as "present but not a number": §4 says so for ElevenLabs, and the other packages follow it. On a verbose row
   that is still `unknown`; on a plain row it is `seconds: null`.
3. **The `stream` refusal** applies to any text part named `stream` whose value, trimmed as the host's image predicate
   trims, is `true` in any ASCII case or `1`; other values (`false`, `0`, `yes`) are forwarded.
4. **Refusal order**: the operation and the metering forms, then not multipart, an elided text part, no file part
   `file`, `stream`, and last the client format (so a padded `" srt"` with `stream=true` is refused for streaming).
   A text part named `file` does not satisfy the `file` requirement.
5. **Part plan.** "Every part named X" is per kind as §1 to §5 say: the `model` rewrites and xAI's removal touch text
   parts only; Azure's dropped names drop parts of either kind (a file part named `model` included) and its rename
   touches file parts named `file` only; a text part named `file` is forwarded. Parts the package writes are replaced
   in place and appended in the plan's order (ElevenLabs: `model_id`, then `timestamps_granularity`).
6. **The verbose-row transcript check** applies to `json`, `text` and `verbose_json` (the passthrough included);
   `srt` and `vtt` are built from `segments` and need no `text`.
7. **A passed-through text document labelled `application/json`** is delivered with the format's media type instead:
   echoing it would repeat native D4, and the suite refuses a text format delivered as JSON.
8. **`segments` and `words` validity.** A segment or word whose start or end is absent, not a number, negative or
   non-finite, or whose text is not a string, makes the subtitle `unknown`. An ElevenLabs entry without `type` counts
   as a word; `spacing` entries must carry string text.
9. **ElevenLabs without `words`.** `srt` / `vtt` render an empty document when the answer has no `words` (a silent
   clip), and are `unknown` when `words` is present but not a list; `verbose_json` writes `"words": []` for no list,
   and omits `language` when `language_code` is not a string.
10. **SV-Q8 constants** (`asr_shared.rs`): a cue closes after a word whose text, trailing whitespace aside, ends in
    `.`, `!`, `?`, U+3002, U+FF01 or U+FF1F; before a word that starts 1 s or more after the cue's last word ends,
    whose `speaker_id` differs (absent equals absent), or that would make the cue end more than 7 s after it starts or
    its trimmed text longer than 84 Unicode scalars. A single word longer than either bound is a cue of its own.
11. **SV-Q9 numbers** (`duration`, `start`, `end`) are written as f64, so `0` is `0.0`; the rendered template is
    `unknown` above 1 MiB, as a rendered text document is.
12. **Azure text elided.** A `combinedPhrases` text or a needed top-level `text` above 1 MiB is `unknown` (§5 says so
    for a phrase); a joined text above 1 MiB is `unknown` before rendering, since no template may carry it.
13. **Azure duration.** `durationMilliseconds` when it is a number (then the value rule, so `0` is `unknown` even with
    a `duration` beside it, as native), else `duration` when it is a number; when neither is a number the outcome is
    "a malformed duration" if either key is present and not `null`, else "the upstream did not report a duration".
14. **The suite's empty format** (decision 3, extended): after trimming, an empty `response_format` counts as absent
    (`json`), as native Azure reads it. The packages that compare exactly refuse `""` before dispatch, so nothing else
    changes.
15. **`result_large_err`** is allowed in `asr_shared.rs` and the ElevenLabs and Azure references: their rendering
    steps return the call's `unknown` outcome as the error.
