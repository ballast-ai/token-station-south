Status: prepared on branch `release/0.75.0`, based on `origin/main` `7d7466f`, which merged #278. Not tagged. Tagging
and the host re-pin are separate steps.

Date: 2026-10-19

Records: [Kiro image input](2026-10-19-kiro-image-input.md), [the Kiro provider component](2026-09-30-kiro-provider-component.md)
(KR1 revised), [CI as the verification gate](2026-10-16-ci-as-the-verification-gate.md),

lv ruled on 2026-10-19 that `provider-kiro` takes images the way the server's production native arm does since server
`b88383cb`. The release was assigned to this session by the user on 2026-10-19.

## 1. What this release carries

- **#278, Kiro image input.** `provider-kiro` 1.3.0 sends a user turn's inline png / jpeg / gif / webp image (an
  `image_url` data URL, or an unmodelled `base64` image block; an image inside an unmodelled `tool_result` block is
  promoted to its turn) in `userInputMessage.images` as `{"format", "source": {"bytes"}}`, the bytes verbatim. An image
  in an assistant turn, a remote image, another media type and malformed bytes stay refused; images in system messages
  and IR tool messages stay dropped.

## 2. API changes

- `south-component-conformance` 0.73.0 → 0.74.0: the Kiro reference reads images (moved by #278).
- `south-contracts` (0.56.0) and `south-provider-api` (0.62.0) are unchanged. No contract number changes; the kernel pin
  is unchanged.

## 3. Hosts

Not breaking on re-pin: no public type changes. A host that serves Kiro rows receives image parts it already passes
to the component; it should price an estimated image by size (the server does since 2026-10-19). The server host's
Kiro dual-run leg registers an image row as an intended difference from its frozen native recording.

`compatibility.json`: the delivery suites are unchanged.

Unverified: the upstream's behaviour with images (nothing was called against an upstream).

## 4. Package identities

`south-component-conformance` changed, so every package published with 0.74.0 retires
(`kiro_images_retires_every_published_074_package_identity`): `provider-kiro` 1.2.0 → **1.3.0**; the other 40
packages take one patch with unchanged behaviour, for example `provider-anthropic` 1.4.1 and `image-openai-compatible`
1.0.5. No package raises its `south_runtime` or moves its `contracts`. The release index is expected to list 41
packages and 1 catalog.
