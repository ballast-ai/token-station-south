- **`state`**: `{"format": <the upstream format word>, "characters": <count>}` (V3-1 interpretation 1: the count is
  what `parse-response` needs for request-sourced metering; MiniMax needs it for the fallback).

## 2. `speech-mimo` (record §12 row 5)

Reproduces `TtsUpstream::Mimo` (selected by the row name `xiaomi`, `tts.rs:114-115`, a P23-F2 / J1 red item; built at
`tts.rs:483-518`; tables at `tts_providers.rs:451-637`). The row is an `openai`-typed provider (KNOWLEDGE.md "Xiaomi
MiMo", endpoint `https://api.xiaomimimo.com`), so the URL is `{endpoint}/v1/chat/completions` (the default arm,
`upstream.rs:592`) and auth `Authorization: Bearer` (`upstream.rs:66-72`).

- **Request**: `POST v1/chat/completions` under the row endpoint, `bearer`. Body, and nothing else from the client:
  ```json
  {"model": <upstream id>, "messages": [<user message>?, {"role": "assistant", "content": <input>}],
   "audio": {"format": <format>, "voice": <voice>}, "stream": false}
  ```
  (`build_mimo_tts_body`, `tts_providers.rs:562-585`). Every other client member (`speed`, `stream_format`, …) is
  dropped, as native.
- **Format** (`mimo_tts_audio_format`, `tts_providers.rs:491-504`), the client `response_format` lower-cased (Unicode
  `to_lowercase`, V3-1 interpretation 5): absent, `wav` or `mp3` → `wav` (`audio/wav`); `pcm` or `pcm16` → `pcm16`
  (`audio/pcm`, `tts_providers.rs:475-480`: little-endian PCM, deliberately not `audio/L16`); `opus`, `aac`, `flac` →
  `invalid_request` "Xiaomi MiMo TTS cannot emit response_format='{f}'. Supported: wav, pcm16 (mp3 is served as wav).";
  any other string → `invalid_request` "Unknown response_format='{f}'. Supported: wav, pcm16 (mp3 is served as wav)."; a
  non-string is absent (`as_str` → `None`, `tts.rs:485`); an elided one is refused with "'response_format' is longer
  than the gateway accepts" (V3-1 interpretation 4).
- **Model classes**, from the upstream id lower-cased (`tts_providers.rs:513-524`; reading the model id is the I3-4 and
  V3-1 Groq precedent, no model list): *design* when it contains `voicedesign`, *clone* when it contains `voiceclone`,
  *preset* otherwise.
- **Voice** (`resolve_mimo_voice`, `tts_providers.rs:531-553`): `voice` absent, not a string or `""` → `mimo_default`
  (no trimming: `" "` passes as `" "`). On a preset model the value lower-cased is matched: `alloy`, `echo`, `fable`,
  `onyx`, `nova`, `shimmer`, `ash`, `sage`, `coral`, `ballad`, `verse` → `mimo_default`; anything else verbatim. On a
  clone or design model the value is verbatim (a clone clip is a base64 data URI; folding `Nova` would corrupt it). An
  elided `voice` (above the 1 MiB fallback, a long clone clip) is forwarded as an `as_is` reference wherever the value
  goes (V3-1 interpretation 4).
- **`audio`**: `{"format", "voice"}`, except on a design model, where it is `{"format"}` only (the voice comes from the
  description, `tts_providers.rs:574-578`).
- **User message** (`tts.rs:499-509`, `tts_providers.rs:570-572`): `instructions` when it is a string that is not blank
  after trimming (sent untrimmed); else, on a design model, the client `voice` as sent (`""` when absent or not a
  string); else none. A message is added only when that text is not blank after trimming. An elided `instructions`, or
  an elided `voice` used as the description, counts as not blank and is sent as an `as_is` reference (the one case
  where this differs from native is a string of over 1 MiB of whitespace).
- **Immutable paths**: `messages`, `stream`, `audio.format`, `model` (= native, `tts.rs:65`).
- **Facts**: `characters {count, upper: count}`; `output_media_type` from the format table.
- **Response** (`decode_mimo_tts_audio`, `tts_providers.rs:599-637`; `tts.rs:1012-1026`): elision path
  `/choices/*/message/audio/data`. A 2xx whose `choices[0].message.audio.data` is not a string (missing, `null`, another
  type) → `unknown` ("a 2xx without audio"); a string of 0 bytes → `unknown` (`empty_audio_is_unknown`); otherwise
  `succeeded` with `inline {pointer: "/choices/0/message/audio/data", encoding: base64, media_type}` and metering
  `characters {value: count, source: request}`. Later `choices` and the chat `usage` (`prompt_tokens`,
  `completion_tokens`) are ignored, as native (`media_arms.rs:960`: "the upstream chat usage's token counts do not take
  part in pricing").
- **Error body**: the OpenAI shape `{"error": {"message"}}` → `message` (V3-1's `openai_error_message`; MiMo's shape is
  **unverified**), else the body text.

## 3. `speech-minimax` (record §12 row 6)

Reproduces `TtsUpstream::Minimax` (selected by provider type `minimax` and an upstream id starting `speech-`,
`tts.rs:139-145`; built at `tts.rs:555-580`; tables at `tts_providers.rs:814-845`, `:980-1162`). The row is the
`minimax-media` provider that also serves `image-01` (image world `image-minimax`) and the Hailuo video tasks
(`task-minimax-v2`); auth `Authorization: Bearer` (`upstream.rs:143-147`); URL `{endpoint}/v1/t2a_v2` plus `GroupId`
(`upstream.rs:511-536`).

- **Request**: `POST v1/t2a_v2` under the row endpoint, `bearer`. Body (`build_minimax_tts_body`,
  `tts_providers.rs:1032-1078`), and nothing else from the client:
  ```json
  {"model": <upstream id>, "text": <input>, "stream": false, "output_format": "hex",
   "voice_setting": {<the client's voice_setting members>, "voice_id": <voice>, "speed"?: <speed>},
   "audio_setting": {<the client's audio_setting members>, "format": <format>}}
  ```
- **`voice_setting`**: the client's `voice_setting` when it is an object (any other type is ignored), its members
  forwarded (elided strings as `as_is` references); `voice_id` always overwritten with the resolved voice. A
  `voice_setting.speed` of `null` is removed. When `voice_setting` then has no `speed` and the client's top-level `speed`
  is a JSON number, `speed` is set to it **as a float** (native `as_f64` and `json!(f64)`, so a client `1` is sent as
  `1.0`; the dual run compares JSON by value and `serde_json` tells `1` from `1.0`). A non-number top-level `speed` is
  dropped; a client `voice_setting.speed` that is not `null` wins and is forwarded as sent.
- **`audio_setting`**: the client's when an object (else ignored), members forwarded; `format` always overwritten.
- **Voice** (`resolve_minimax_voice`, `tts_providers.rs:1002-1020`): `voice` absent, not a string or `""` →
  `Wise_Woman` (no trimming); otherwise lower-cased and matched: `alloy`, `echo`, `fable`, `onyx`, `nova`, `shimmer`,
  `ash`, `sage`, `coral`, `ballad`, `verse` → `Wise_Woman`; anything else verbatim (a system voice id such as
  `English_Graceful_Lady`, or a cloned voice id). An elided `voice` is forwarded as an `as_is` reference.
- **Format** (`minimax_tts_audio_format`, `tts_providers.rs:980-995`), lower-cased: absent or `mp3` → `mp3`
  (`audio/mpeg`); `wav` → `audio/wav`; `flac` → `audio/flac`; `pcm` → `audio/pcm` (`tts_providers.rs:837-844`); `opus`,
  `aac` → `invalid_request` "MiniMax T2A cannot emit response_format='{f}'. Supported: mp3, wav, flac, pcm."; any other
  string → `invalid_request` "Unknown response_format='{f}'. Supported: mp3, wav, flac, pcm."; non-string absent; elided
  refused (as §2).
- **`GroupId`** (I3-1 §2, IM-Q3): the manifest declares config key `group_id` (non-secret, optional, syntax `digits`,
  the HTTP contract's grammar for `GroupId`) under family `minimax-speech`, with `image-minimax`'s description; the
  descriptor carries `query: [{"name": "GroupId", "value": <group_id>}]` only when the key is set. Native appends
  `?GroupId=` with the trimmed value percent-encoded, and only when it is not blank (`upstream.rs:528-535`). The China
  host (`api.minimaxi.com`) needs it; the intl host (`api.minimax.io`) does not use it; keys are platform-scoped (a key
  is invalid, `base_resp` 2049, on the other platform's host; `server:gateway/CLAUDE.md` provider keys). Which host a row
  talks to is its `base_url`, not the package.
- **Immutable paths**: `text`, `output_format`, `stream`, `audio_setting.format`, `voice_setting.voice_id`, `model`
  (= native, `tts.rs:67-74`).
- **Facts** (record §8): `characters {count, upper}`, `upper` = the weighted count of `input`: each scalar value 1 when
  ASCII, else 2 (native `weighted_upper_chars`, `tts.rs:297-303`, used for MiniMax's reservation at `tts.rs:805-806`).
  The host reserves `min(bytes(input), upper)`, which is `upper` (a non-ASCII scalar is at least 2 bytes), the native
  amount. Whether MiniMax's own counting rule is "non-ASCII counts 2" is **unverified**; the bound is the native one.
- **Response** (`decode_minimax_tts_audio`, `tts_providers.rs:1121-1162`; `tts.rs:1093-1114`): elision path
  `/data/audio`. MiniMax answers HTTP 200 for logical failures (record §7), so on a 2xx, in order:
  1. **`base_resp.status_code`**: absent or `null` → success; not an integer → `unknown` (I3-1 decision 3); non-zero →
     an error envelope from the I3-1 table (`minimax_status.rs:43-61`: 1004 / 2049 → 401 `auth`, 1026 → 400
     `content_policy`, 2013 → 400 `invalid_request`, 1002 → 429 `rate_limit`, 1008 / 2153 → 503
     `upstream_unavailable`, any other code → 502 `provider_protocol_error`), `provider_message` =
     `base_resp.status_msg` capped; outcome `rejected` for 1004, 2049, 2013, 1002, 1008, 2153, and `unknown` for 1026
     (IM-Q4: possibly charged) and every other code. T2A-specific codes beyond the image table (for example a voice id
     that does not exist) are therefore `unknown`; which codes T2A emits is **unverified**.
  2. **Audio**: `data.audio` not a string → `unknown`; 0 bytes → `unknown` (record §11 `empty_audio_is_unknown`,
     "empty `data.audio`").
  3. **Characters** (record §9): `extra_info.usage_characters` a non-negative JSON integer above 0 → `characters
     {value, source: upstream}`; absent or `null` → `characters {value: count, source: request}` (record §9's fallback,
     native `tts.rs:1099-1105`); `0`, or present but not a non-negative integer (negative, fractional, a string) →
     `unknown` (SV-Q7).
  4. Otherwise `succeeded` with `inline {pointer: "/data/audio", encoding: hex, media_type}`.

  `data.status`, `extra_info.audio_format`, `extra_info.audio_length` and the rest of the envelope are ignored, as
  native.
- **Error body** (non-2xx): `base_resp.status_msg` (`image-minimax`'s precedent), else the body text.

## 4. What the host must do before a V3-2 cutover (in addition to V3-1 §7)

Every item of V3-1 §7 applies. V3-2 adds, generic over packages and naming no provider:

1. **The `json` response view for speech**: `build_media_response_view_v1` with the call's response elision paths
   (V3-1 §7 item 9 names `binary` and `sse` only). A 2xx body the host cannot build a view from is `unknown`.
2. **`inline` artifacts** (record §10): resolve the artifact's pointer in the view; a placeholder names a blob of the
   upstream body (a non-elided string at the pointer is read from the unelided body); decode it with `from_base64` or
   `from_hex` (south's `decode_base64` / `decode_hex`, so both hosts accept and refuse the same strings); the decoded
   bytes must be non-empty; any failure is `delivery_unknown`, no settlement. Account the decoded bytes against the
   response-body memory budget as native does (`tts.rs:1020-1025`, `:1108-1113`). Native's decoders accept the same
   strings (the `base64` crate's `STANDARD` engine, canonical padding and no trailing bits; the `hex` crate, either case,
   even length); read, not run.
3. **Characters from the upstream** (record §9 checks 1 and 2): `source = upstream` settles `value` and is checked
   `value ≤ bytes(input)`; a settlement above the reservation (the weighted `upper`) goes to review through the existing
   funds guard, as native's does today (the comment at `media_arms.rs:328-330`). `source = request` keeps check 1
   (equal to the host's scalar count). The reservation formula is V3-1 §7 item 6; MiniMax is the first package whose
   `upper` is not `count`, so the gate ③ fixture "`upper` below the host bound is reserved at `upper`" becomes a real
   case.
4. **Declared config values on a speech binding**: pass the row's `config_values` through
   `south_component::declared_values`, as the image executor does (`server:…/handler/images/component/mod.rs:1526-1533`).
   Cutover writes `config_values.group_id` on a China-host MiniMax row (I3-1 §5 item 4); the row's native `group_id`
   column is not read by the component path. A value that is not digits is refused at save (IM-Q3).
5. **Bindings on shared rows**: the `minimax-media` row already carries image and task routes, and the `xiaomi` row
   serves chat models through the provider world. The speech route gets its own binding key (the P13 precedent "the
   route binding key must be separate"), family `minimax-speech` / `mimo-speech`, `base_url` = the row endpoint
   (`https://api.minimax.io` or `https://api.minimaxi.com`; `https://api.xiaomimimo.com`), slot `provider_api_key`.
6. **The `tts` modality check at route save** (V3-1 §7 item 1) also closes §5 item 5: only rows declared `tts` reach the
   MiMo package.
7. **Client status of a 2xx failure**: a `rejected` or `unknown` 2xx (every MiniMax `base_resp` failure, every MiMo or
   MiniMax 2xx without audio) is parked and answered 502 (V3-1 §7 item 10, I3-1 IM-Q6). Native parks the same cases
   and answers MiniMax's mapped status (401 / 400 / 429 / 503 / 502) or, for a missing or undecodable audio string, 500.
8. **Q10** (record §16): include the `xiaomi` and MiniMax speech rows in the read-only listing of rows that have only a
   token price (both arms are characters-only).
9. **Dual run per arm** (record §13): JSON body by value (MiniMax `speed` as a float, §3), headers, path and query
   (`GroupId` present and absent); audio bytes and `Content-Type` byte for byte; reservation (MiniMax weighted), frozen
   characters and amount (MiniMax upstream-sourced). Fixture sources: `media_arms.rs:293` (MiniMax mp3, upstream 9
   characters billed, not the local 11), `:519` (`GroupId` exactly on the wire), `:923` (MiMo mp3 served as wav, the
   exact upstream body); `server:gateway/tests/byok_media_ownership.rs:749-870` (MiniMax BYOK, bearer form);
   `unit_tests.rs:9-258` (MiMo formats, voices, bodies, decode) and `:451-665` (MiniMax formats, voices, the body
   pass-through and `speed` rules, decode, `base_resp`); the live recipes `server:gateway/tests/test_audio.sh:445-490`
   (MiMo, needs a key) and KNOWLEDGE.md "MiniMax Speech / T2A v2" (needs a key).

## 5. Host defects found on the way (read, not run)

1. **MiniMax `usage_characters: 0` settles $0 for delivered audio**: the reported count replaces the local one
   (`tts.rs:1099-1105`) and `calculate_tts_cost` returns 0 for 0 characters (`server:…/engine/token_counter/media.rs:
   480-487`), so the audio is delivered free. This contradicts the arm's own "never bill $0 for delivered audio" rule
   (`tts.rs:1116-1120`, written for the token path). SV-Q7.
2. **A malformed `usage_characters`** (negative, fractional, a string) silently falls back to the local scalar count
   (`as_u64` → `None`), which for non-ASCII text is below what the upstream bills (the weighted count reserved). SV-Q7.
3. **`chars as u32`** (`tts.rs:1104`) truncates a reported count above `u32::MAX`; unreachable with today's input caps,
   listed for completeness.
4. **A non-integer `base_resp.status_code`** (for example `"1004"`) is read as success and the body decoded
   (`tts_providers.rs:1122-1127`).
5. **The MiMo arm is selected by the row name `xiaomi` for every model on the row** (`tts.rs:114-115`), chat models
   included: unlike the Bailian, MiniMax and Vertex arms it has no TTS gate on the model, so a chat model on
   `/v1/audio/speech` is sent a TTS body, answers without audio, and its funds are parked. Unless a layer before
   `speech()` checks the `tts` modality, which I did not find (**unverified**).
6. **A MiMo design model with neither `instructions` nor `voice`** is dispatched without the user message the upstream
   requires (KNOWLEDGE.md: "Param Incorrect: user message content must not be empty for voice design model"); the
   upstream answers 400, which P29 releases. A wasted call, not a funds defect.

## 10. Open questions for lv

**Ruled by lv on 2026-10-14: SV-Q7 as recommended** (a zero or malformed `usage_characters` on a 2xx with audio is
`unknown`; no fallback to the request count). The item below keeps its text; the recommendation is the ruling.

- **SV-Q7 Upstream characters of 0, or malformed.** On a MiniMax 2xx that delivers audio, `extra_info.usage_characters`
  may be `0` or present but not a non-negative integer. Record §9 says only what to do when there is **no** number (fall
  back to `source = request`). Native settles `0` at $0 (§5 item 1) and silently falls back to the local scalar count
  for a malformed value (§5 item 2). Options: (a) `unknown` for both (park; the host answers 502); (b) fall back to the
  request count for both; (c) native parity. **Recommended: (a).** It is the characters counterpart of the token rule
  the host adopted for TTS ("not both zero", `a82c852b`; V3-1 §2) and of I3-2 P4 (malformed counts are `unknown`);
  "null and 0 are different facts" (record §9) argues against reading `0` as "no number"; and (b) would under-bill
  non-ASCII text, because the request count is the scalar count while MiniMax bills the weighted one (**unverified**).
  A capture showing MiniMax legitimately reporting `0` for a non-empty input would reopen it.

### Interpretations

1. **`state`** is `{"format", "characters"}` as §1 says: the upstream format word (the delivered media type is derived
   from it) and the request's scalar count (MiMo's metering, MiniMax's fallback).
2. **A `group_id` that is not digits** never reaches the wire: the reference copies the declared value into the
   descriptor's `GroupId`, whose grammar is digits only, so a value the host should have refused at save makes
   `prepare` fail `internal`, as `image-minimax` does. An empty or non-ASCII value is refused earlier, by the kernel's
   `ComponentValues` grammar, before the component is called.
3. **MiMo `choices[0]`** is the first element of an array only: an object keyed `"0"` is not a choice (native's
   `get(0)`), although the elision pattern `/choices/*/…` matches it.
4. **A non-object `data` or `extra_info`** counts as absent, as native's `.get` chain: `extra_info: null` falls back to
   the request's count; `data` that is an array has no audio. A non-object `base_resp` has no `status_code`, so it is
   success, as native.
5. **SV-Q7's "malformed"** is any present, non-`null` value that is not a JSON non-negative integer as `serde_json`
   reads it: negative, fractional, `9.0` (a float literal), a string, a boolean, an array, an object, or an integer above
   `u64::MAX`. The reasons are "the upstream reported 0 characters for delivered audio" and "a malformed character
   count" (the synthetic reference's text). Likewise `base_resp.status_code` `0.0` is malformed (`unknown`, P5).
6. **One reason for every audio failure.** A missing, `null`, non-string or empty audio string is `unknown` "a 2xx
   without audio", so the V3-1 break module's `SucceedWithoutAudio` applies to both packs; a non-object 2xx body is "a
   2xx without a JSON object body" (`image-minimax`'s text); a body that is not JSON is the host's `unknown`.
7. **MiniMax settings objects** are forwarded member by member with every nested placeholder written back as an
   `as_is` reference; an elided `voice_setting` or `audio_setting` (a string above 1 MiB) is not an object and is
   ignored, as native's `as_object` ignores any string.
8. **The top-level `speed` float** survives the descriptor: the template keeps the number text `1.0`, pinned by
   `prepare.speed-integer-sent-as-float` and `the_top_level_speed_is_sent_as_a_float`.
9. **Refusal order** is V3-1's: `input`, then `response_format`. Native counts a missing `input` as `""` and so refuses
   the format first (P1).
10. **MiniMax non-2xx messages** follow §3 (`base_resp.status_msg`, else the body text through V3-1's `non_2xx`);
    `image-minimax` keeps its own rule (no body-text fallback), since its behaviour may not change.
11. **Elision** covers every choice's audio (`/choices/*/message/audio/data`); only the first is the artifact.

### Points that contradict the record (flagged, not silently chosen)

- **Hangul, not Chinese, in the fixtures.** §8 asks for the weighted `upper` with "CJK" input. The repository's
  English-only gate (`scripts/check-language.sh`) refuses Chinese ideographs and fullwidth punctuation in every tracked
  file, fixtures included, and does not match Hangul. The packs and tests use Hangul (`안녕하세요`: count 5, `upper` 10,
  15 bytes; `hi 안녕`: count 5, `upper` 7) and Latin with diacritics (`Grüße`: count 5, `upper` 7). Each Hangul syllable
  is three bytes in UTF-8, as a CJK ideograph is, so the case "a count above the weighted `upper` but within
  `bytes(input)`" (`characters-above-upper`: 12, between 10 and 15) still holds. lv confirmed the substitution on
  2026-10-15.
