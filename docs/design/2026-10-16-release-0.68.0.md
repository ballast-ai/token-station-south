## 1. What this release carries

All of it comes from #246.

- **D4, the output cap on Azure rows.** Native picks the cap key per row (`needs_max_tokens_rewrite`):
  - the row's `max_tokens_field` column wins when it is set;
  - otherwise, an `azure_openai` or `azure_foundry` row keeps `max_completion_tokens` unless the row cleared
    `accepts_max_completion_tokens`, which defaults to true.

  The families `azure-openai-v1` and `azure-openai-dated` gain the config key `max_tokens_field`, which takes
  `max_completion_tokens` (the default) or `max_tokens`. Any other value is a configuration error (500) before any
  request is built. The other families keep sending `max_tokens`, as native does for those types. Unverified and
  registered: whether a reasoning deployment refuses `max_tokens` on a row that opts back to it.
- **T9-Q9 (a), client thinking passthrough.** A client's `thinking` or `enable_thinking` is forwarded verbatim, `null`
  included, and only when the client sent it. This applies to `openai-compatible`, `azure-openai-v1`,
  `azure-openai-dated`, `github-copilot` and `glm-coding`, whose native types send the client's Chat body.
  `gemini-openai-compatible` does not forward them, because native builds that body from the IR. With this, the host's
  `-thinking` `keep_existing` extra fills only a missing key, as native does. A+ (mapping a Messages client's
  `reasoning.mode`) is deferred, because it needs a new ruling.
- **Record correction (§2.1).** Native `glm_coding` serves Responses through the Chat fallback; it does not refuse
  Responses.

  New registered difference, D11: after that fallback, native collapses text-only part arrays into a string, and the
  component keeps sending the array.

## 3. Hosts

This release has no breaking API change. Host prerequisites (T9 record H2 and H4):
- **Migrating an Azure row.** Copy the row's `max_tokens_field` column when it is set. Otherwise write `max_tokens`
  when the row cleared `accepts_max_completion_tokens`. Otherwise write nothing, so the default applies.
- **Preflight checks.**
  - Fail a row whose column holds any other value.
  - List any `glm_coding` or T8 row whose column is set to `max_completion_tokens`, because the component sends
    `max_tokens` there.
- **`azure-openai-v1` rows.** A row that already uses `azure-openai-v1` sends `max_completion_tokens` after the
  re-pin, as native does.
