## 1. What this release carries

- **#199, north codec G1.** `OpenAiChatStream` in `south-north-codec` renders complete OpenAI chat stream chunks from a
  host-supplied `ChatStreamContext`: chunk identity, `role: "assistant"` on the first delta (N-Q4), frame kinds and the
  usage fold; its conformance is JSON-value equality over the canonical frame sequence (N-Q5). `south-north-codec` is a
  workspace-versioned crate that no component links, so G1 re-identifies no package.
- **#200, image world step I3-5.** The new package `image-ideogram` 1.0.0 (family `ideogram-image`, `header_secret`
  `api-key`): `ideogram-v4-turbo`, `ideogram-v4` and `ideogram-v4-quality` (rendering speed TURBO / DEFAULT / QUALITY),
  generation only (IG-Q1), as a text-only multipart POST to `v1/ideogram-v4/generate` in the native part order; `size`
  snaps to Ideogram's 38 resolutions as the native arm does and is reported as the `size` fact (IG-Q3); entries with
  `is_image_safe: false` or without a URL are dropped, all dropped is `rejected` (content policy 422); `url` artifacts
  carry no declared media type (IG-Q2: the host sniffs the stored bytes); `images` metering with `images_reported` null;
  contracts `{image: 1, media: 1}`, `south_runtime` 0.57.0. No contract change.
- **The release commit** (this branch): the release bump (§5) and the release notes (README row and package row,
  ARCHITECTURE v0.61.0 paragraph, the I3-5 and render-gaps records' status, this record).

The kernel pin is unchanged (mirror `v0.5.0`, `canonical_ir` 4). No contract number changes.

## 2. API changes

### `south-north-codec` (workspace version)

- New: `OpenAiChatStream`, `ChatStreamContext`, `OpenAiChatFrame` and `OpenAiChatFrameKind` (render-gaps record §3, G1).

### `south-component-conformance` 0.58.0 → 0.59.0

- New module `reference_ideogram_image` (`IdeogramImageReferenceV1` and its constants).
- The references' `VERSION` constants follow §4.

`south-contracts` (0.53.0) and `south-provider-api` (0.54.0) are unchanged.

## 3. Hosts

A host that re-pins keeps serving what it served before; every package keeps its `south_runtime` and `contracts`.
Serving `ideogram-image` additionally needs, on token-station-server, the I3-5 record's host items: the generic sniffing
of stored URL artifacts whose media type is undeclared (IG-Q2), a test-only seam for the safe fetch ports (the `b64_json`
dual run), and an `ideogram-image` row in the image cutover preflight with its C10 items.
