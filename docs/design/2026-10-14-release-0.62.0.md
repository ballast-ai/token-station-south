## 1. What this release carries

- **#204, the Kiro provider component.** The new package `provider-kiro` (family `kiro`, `provider-adapter-v2`,
  `bearer` on the slot `provider_api_key` minted by the rotating refresh recipes `social` and `idc` under the selector
  `kiro`; a Kiro sign-in file `kiro-auth-token.json` imports and seeds) translates the IR straight to the
  `generateAssistantResponse` `conversationState` body, one history entry per IR message, with `conversationId` from the
  host's `attempt_id` and `profileArn` from the credential's exported attribute. It declares
  `stream_framing: aws-eventstream`, `request_facts.stream: "none"` (non-streaming callers take the buffered path),
  `output_cap: []`, `usage_evidence: absent`, the user agent the native arm sends and
  `subscription_quota_families: ["kiro"]`. Its `south_runtime` is 0.60.0, the first runtime that parses
  `subscription_quota_families` (§4). K-Q5, K-Q6, K-Q10, K-Q11, K-Q13 and K-Q18 stay provisional until a real-account
  capture; the package implements the native arm's current behaviour for them. Under Q47 `south-component-conformance`
  moved 0.59.0 → 0.60.0.
- **#207, the Kiro tool-argument fix.** The request sends tool-call arguments exactly as the native first hop does:
  arguments that parse as JSON go as that value, anything else (including `""` and whitespace) as a JSON string. KD14
  (empty arguments sent as `{}`) is withdrawn. It changed `reference_kiro.rs` while `south-component-conformance`
  0.60.0 was still unreleased, so it needs no version of its own.
- **#205, task contract 8 and `task-gemini-omni-v2`.** Task contract 8 is additive and leaves the WIT unchanged:
  `TaskArtifactRefV2::Inline` names an artifact whose bytes are a string in the upstream response by a pointer into the
  view the host elided with `elide_v1` and the package's `response_blob_paths`; usage gains declared token buckets from
  the closed fourteen-word `TaskTokenBucketV2` vocabulary (exclusive with `tokens`), and the request estimate gains
  `bucket_ceilings`, which may only tighten the host's bound. A contract 7 value decodes and re-encodes byte for byte,
  `TASK_CONTRACT_VERSIONS` is `[7, 8]`, and every published task package keeps `task: 7`. Gate ① admits
  `response_blob_paths`, `token_buckets` and `required_token_buckets` in the task-v2 world with contract 8 only; gate ②
  adds `DeclaredBucketsOnly` and runs `ReferenceIntegrity`, `UsageNeverDefaulted` and `MissingMeterIsNotZero` on
  contract 8 packages. The new package `task-gemini-omni-v2` 0.1.0 serves Gemini Omni video over the Interactions API in
  two families: `vertex-interactions-video` (sampled: `background` submit, poll by id, inline clip, `bearer`, first
  frame and reference images) and `gemini-interactions-video` (provisional, transcribed from the host's native arm:
  synchronous, Files API `uri` fetched with `x-goog-api-key`, text-to-video only); contracts `{task: 8, media: 1}`.
  Q47: `south-contracts` 0.53.0 → 0.54.0, `south-provider-api` 0.54.0 → 0.55.0, `south-component-conformance`
  0.60.0 → 0.61.0.
- **#206, the I3-3 record** (`image-vertex`, proposed; VI-Q1 and VI-Q2 ruled). Its pull request title says "do not merge
  yet", but it was merged; it adds only `docs/design/2026-10-13-image-i3-3-vertex.md` and changes no code, package or
  contract. `image-vertex` is not in this release.
- **The release commit** (this branch): the release bump (§5), `task-gemini-omni-v2`'s `south_runtime` moved to 0.62.0
  (§4), and the release notes (README row and package rows, ARCHITECTURE v0.62.0 paragraph, the Kiro and Omni records'
  status, this record).

The kernel pin is unchanged (mirror `v0.5.0`, `canonical_ir` 4). `compatibility.json` records `contracts.task` 8
(from #205); no other contract number changes.

## 2. API changes

### `south-contracts` 0.53.0 → 0.54.0

- `TASK_CONTRACT_VERSION` is 8; new `TASK_CONTRACT_VERSION_V7` (7) and `TASK_CONTRACT_VERSIONS` (`[7, 8]`).
- New: `TaskArtifactRefV2::Inline(Vec<TaskInlineArtifactV2>)` and `TaskInlineArtifactV2`; `TaskTokenBucketV2` (fourteen
  words) and `TaskTokenBucketsV2`; `TaskUsageFactsV2::with_token_buckets` / `token_buckets`;
  `TaskRequestEstimateV2::with_bucket_ceilings` / `bucket_ceilings`; `TaskContractErrorV2::InlineArtifactUnresolved`
  and `ReferenceIntegrity`; the host halves `resolve_task_inline_artifact_v1` and `fill_task_artifact_markers_v1`.

### `south-provider-api` 0.54.0 → 0.55.0

- `ComponentManifestV1` gains `response_blob_paths`, `token_buckets` and `required_token_buckets` (task-v2, contract 8
  only); new `TASK_INLINE_CONTRACT` and `TASK_TOKEN_BUCKETS`; `ManifestErrorV1` gains
  `TaskResponseDeclarationsAreTaskV2Declarations`, `TaskResponseDeclarationsRequireContract8`,
  `InvalidResponseBlobPaths` and `InvalidTokenBuckets`.

### `south-component-conformance` 0.59.0 → 0.61.0

- New modules `reference_kiro` (#204) and `reference_gemini_omni_task_v2` (#205); `CheckV1::DeclaredBucketsOnly`; the
  task-v2 fixture and suite gain the contract 8 checks.
- The references' `VERSION` constants follow §4.

**Breaking for hosts on re-pin.** `TASK_CONTRACT_VERSION` is now 8: a host whose task range is built from it alone admits
contract 8 only and refuses every published task package (all declare 7); build the range from
`TASK_CONTRACT_VERSIONS`. `TaskArtifactRefV2`, `TaskContractErrorV2`, `ManifestErrorV1` and `CheckV1` gain variants, so
an exhaustive match on them stops compiling.

## 3. Hosts

A host that re-pins and widens its task range to `[7, 8]` keeps serving what it served before; every published package
keeps its `south_runtime` and `contracts`. Serving the new families needs host work:

- `kiro` (Kiro record §18, "What the host does next"): admit `south_runtime` 0.60.0 and lift its refusals of
  `usage_evidence: absent` and `output_cap: []`; register the package for `kiro`; hand each native credential over to
  the recipe fields in one transaction; run the replaying dual run against the native arm; then a cutover preflight.
- `vertex-interactions-video` / `gemini-interactions-video` (Omni record §17.5): adopt contract 8 once for every
  provider (elide responses of packages declaring `response_blob_paths`, resolve and store inline artifacts before the
  terminal state and settlement, fill render markers, price token buckets with per-output maxima); install the package
  and route Omni rows by `component_task`; dual run the Gemini family against the native arm; a cutover preflight.
- As E-Q5 / image Q5 (Q-S6): a community-host implementation is recommended, and `task_component_capabilities` stays
  `not_verified` for the community host until it lands.
