## 1. What this release carries

- **`task-veo-v2` reports the client's resolution spelling** (issue #294). The `resolution` fact was upper-cased
  (`1080p` became `1080P`); it is now reported as sent. Tier words are matched exactly (R-2) and the model catalog lists
  Veo's resolutions in lower case, so the upper-cased word could never find a per-resolution price row.
- **Durationless transcription formats ask for `verbose_json`** (issue #293; scoped by the host owner, lv, on
  2026-10-28). On `speech-openai-compatible` and `speech-xai`, a client format that carries no duration (`text`,
  `srt`, `vtt`) is always asked of the upstream as `verbose_json` and rendered by the package, as a row declaring
  `speech.verbose_json` already was. `json` and `verbose_json` are asked as sent. Before, such a request came back
  without a duration and the host billed its 60-second estimate.
- **`host_signed` `emits` is a ceiling** (issue #122; lv, 2026-10-28). Documented in `SignedHeaderSetV1` and the
  manifest field: the host declares per request the set its finalizer emits for the credential at hand, never wider
  than `emits`. Documentation only.

## 2. API changes

None to a public contract.
- `south-component-conformance` 0.77.0 → 0.78.0 (minor): the two reference changes and their fixture packs. A
  transcription request in `text`, `srt` or `vtt` now asks the upstream for a different format, and Veo reports a
  different fact, so the change is not compatible (CONTRIBUTING).
- `south-contracts` 0.56.0 → 0.56.1 and `south-provider-api` 0.63.0 → 0.63.1 (patch): documentation comments only.
  Both are linked by guests, so their versions move with their sources (§13.12).
- The kernel pin is unchanged (protocol 0.7.0), as are the South contract numbers and the `compatibility.json` kernel
  tuple (`canonical_ir` 5, `stream` 3).

## 3. Hosts

Nothing breaks at compile time on re-pin: no struct gains a field, no enum gains a variant, no delivery suite changes.
A host that records runtime 0.77.0 admits every package of this release (§4). The host moves its pin to the 0.80.0
release index and tag, because every package took a new identity.

Behaviour a host will see:
- **Veo's resolution fact is lower case.** A host that matched Veo resolutions case-insensitively (token-station-server
  since 2026-10-27) sees no difference in pricing.
- **Text-format transcriptions report measured seconds.** On an OpenAI-compatible or xAI recognition model, `text`,
  `srt` and `vtt` requests now settle at the upstream's reported duration instead of a host estimate. A model whose
  upstream refuses `verbose_json` (the GPT-4o transcription models, by OpenAI's documentation, **unverified**) now
  fails those three formats with the upstream's 4xx, which a host does not charge.

## 4. Package identities

`south-component-conformance` is linked by every component, so the version bump changes every `component.wasm` and every
package takes a new version (boundary record §13.12, §16 Q47):
- `task-veo-v2` 0.37.8 → **0.38.0**, `speech-openai-compatible` 1.1.12 → **1.2.0** and `speech-xai` 1.0.14 → **1.1.0**
  (behaviour changed);
- the other 38 packages take one patch with unchanged behaviour, for example `image-qwen` 1.1.0 → 1.1.1 and
  `provider-openai-compatible` 2.13.3 → 2.13.4.

Declared runtime: **no package raises `south_runtime`; all 41 keep 0.77.0.** The release introduces no manifest field
or value that an older runtime's gate ① refuses or reads differently. The release index is expected to list 41 packages
and 1 catalog.

## 6. Verification

The gate is the release pull request's CI run. `quality` includes `scripts/check-declared-runtime.sh --build` on
`release/*` branches; `crate-versions` and `language` run as well. The release workflow runs on the tag: build
scripts, gate ② reports, `check-declared-runtime.sh --dist`, the release index, `check_crate_versions.py --tag`, and
the digest-stability comparison with the published `v0.79.0` index.

Local checks on the feature commits (#304), each judged by its own exit code: `cargo fmt --all -- --check`,
`cargo clippy --workspace --all-targets --all-features -- -D warnings`, `scripts/check-language.sh`,
`cargo test -p south-component-conformance -p south-contracts -p south-provider-api --tests`, `cargo metadata --locked`
for every component, guest, `fuzz` and the root, and `python3 scripts/check_crate_versions.py`.

The tag itself is not created here.
