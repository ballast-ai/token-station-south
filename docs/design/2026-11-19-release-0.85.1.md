# Release 0.85.1: tool calls cut off by the output cap

Status: released, tag `v0.85.1` (#349, commit `174158d1`).

Date: 2026-11-19

Records: [tool-call arguments cut off by the output cap](2026-11-19-truncated-tool-call-arguments.md),
[CI as the verification gate](2026-10-16-ci-as-the-verification-gate.md),
[boundary record](2026-09-30-host-zero-vendor-boundary.md) §13.6 (declared runtime) and §13.12 (Q47),
[release 0.85.0](2026-11-16-release-0.85.0.md).

A patch release, as 0.83.1 was: it carries one fix and no new feature. It also carries one repository change that
touches no package: the `cargo deny` ignore for RUSTSEC-2026-0543 (`chrono` unmaintained, #347).

## 1. What this release carries

- **A tool call cut off by the output cap** (#346). `openai_chat_response` in `south-north-codec` renders tool-call
  arguments that are not valid JSON when, and only when, the choice's finish reason is `length`, unchanged. Every other
  finish reason keeps the refusal. `provider-openai-responses` keeps the finish reason of an `incomplete` answer
  (`length` or `content_filter`) when the output holds a function call, instead of replacing it with `tool_calls`, in
  both the response and the stream.
- A host that answered such a request with a 502 now delivers the partial call under `length`, which is what tells
  the client to raise its cap.

## 2. API changes

None. `openai_chat_response` keeps its signature; it refuses fewer inputs. South contract numbers and the kernel tuple
are unchanged (`canonical_ir` 5, `stream` 3).

## 3. Hosts

A host re-pins to the 0.85.1 tag and release index, because every package took a new identity and the Chat codec runs
in the host. The re-pin needs no host code change. The server host should first read the review evidence of the
requests that motivated the fix (record §6). The re-pin is done by the session that owns the host's re-pins.

## 4. Package identities

`south-component-conformance` 0.81.0 → 0.81.1 is linked by every component, so every package takes a new version
(boundary record §13.12, §16 Q47). `provider-openai-responses` takes the minor 1.7.0 because its answers change, and
every other package takes the Q47 patch. `truncated_tool_calls_retire_every_published_085_package_identity` pins the
round.

Declared runtime: unchanged. No package declares a field that a 0.85.0 runtime cannot read. The 29 task, image and
speech packages keep 0.81.0, `provider-openai-compatible` keeps 0.83.0, and the other 11 provider and embeddings
packages keep 0.77.0.

## 6. Verification

The gate is the release pull request's CI run. On `release/*` branches the `components` job runs
`scripts/check-declared-runtime.sh --build`, and `crate-versions` and `language` run as well. The release workflow
runs on the tag.

The tag itself is not created here.
