- **`model-capabilities`**: every configured model of the bound row, `operations` `[synthesize]`, `metering_forms`

  `embeddings-openai-compatible`, the package declares every configured model; which model rows are routed to it is
  the host's route plus its `tts` modality check (§7 item 1), not a model list in the wasm (record §4).

- **Facts**: `operation` `synthesize` (any other operation in the context is refused `capability`, the

  `output_media_type` the predicted type (§2 table for OpenAI-compatible, otherwise `audio/mpeg`, the native fallback;

- **Descriptor**: `POST`, JSON body, no `content-type` (the host's JSON executor sets it, I3-1 decision 7), auth arm on
  slot `provider_api_key`.
- **2xx, `binary` form**: an empty body → `unknown` (record §10, row `empty_audio_is_unknown`); otherwise `succeeded`
  with a `body` artifact. The artifact's `media_type` is the upstream's `content-type` (first occurrence in the view's
  headers) when it passes `is_speech_media_type`; else its essence when that passes; else `audio/mpeg` (native
  `tts.rs:899`, `:972-977`; SV-Q2). Metering `characters {value: count, source: request}`.
- **Non-2xx**: an error envelope, `provider_message` from the family's error body (each section below), capped at 256
  characters; code by status as `image-azure` (401 / 403 authentication, 429 rate limit, 5xx unavailable, otherwise
  invalid request); outcome `rejected` for a 4xx other than 408, else `unknown` (`image_shared::non_2xx`); a 3xx is

## 2. `speech-openai-compatible` (record §12 row 1)

Reproduces the native catch-all arm (`TtsUpstream::OpenaiCompat`, `tts.rs:165-166`, built at `tts.rs:664-672`, decoded
at `tts.rs:1116-1143` and `tts_providers.rs:7-81`). The native arm is the fallback for every provider row no other arm
selects; P21 DI4 (lv, 2026-09-30) ruled that it, too, moves into a component.

- **Family and auth**: `openai-compatible`, `bearer` (native `Authorization: Bearer` for `openai`-typed rows,
  `upstream.rs:66-72`). Whether to add the embeddings package's second family `azure-openai-v1` (`header_secret`
  `api-key`) is SV-Q1.
- **Path**: the embeddings package's API-root rule (`reference_openai_compatible_embeddings.rs:78-83`): the binding's
  `base_url` path, or `v1` when the `base_url` is an origin, then `audio/speech`. For an origin-only endpoint such as
  `https://api.openai.com` this is native's `{endpoint}/v1/audio/speech` (`upstream.rs:592`); a row whose native URL is
  rewritten by provider type (DeepInfra `upstream.rs:583-590`, Azure `:551-581`, Gemini, GLM, Bailian, BytePlus) is
  cut over with a speech binding whose `base_url` is its API root (§7 item 2).
- **Body**: the client's JSON with `model` replaced by the upstream id; every other member forwarded unchanged, numbers as
  `serde_json` renders the parsed value (I3-4 decision 3), an elided member written back as an `as_is` `$south.ref`
  (I3-1 decision 5). When `metering_required` contains `tokens`, `stream_format` is set to `"sse"` (overriding the
  client's, as native `tts.rs:667-670`); otherwise a client `stream_format` is forwarded as sent (SV-Q3).
- **Immutable paths**: `input`, `model`, `stream_format`, `response_format` (= native `body_rules`, `tts.rs:78`).
- **No refusals of its own** beyond §1: the native arm validates neither `voice` nor `response_format`.
- **Predicted media type** (`output_media_type`, and the delivered type on the SSE path), the native table
  `openai_tts_content_type` (`tts_providers.rs:72-81`) over the client's `response_format` lower-cased, absent = `mp3`:
  `wav` → `audio/wav`, `flac` → `audio/flac`, `opus` → `audio/opus`, `aac` → `audio/aac`, `pcm` → `audio/pcm`,
  anything else → `audio/mpeg`.

**Character-priced call** (`metering_required` `[characters]`): `response_body_form` `binary`, the §1 rules.

**Token-priced call** (`metering_required` `[tokens]`; the host decides, record §8, `tts_uses_token_pricing`
`server:gateway/src/modules/catalog/pricing_state.rs:120-125`):

- `response_body_form` `sse`; response elision path `/*/data/audio` (the record's `/*/data/delta` was an example; the
  native reader takes the base64 from `audio`, `tts_providers.rs:26-27`).
- **Artifact**: `segments`, one item `{pointer: "/{i}/data/audio", encoding: base64}` per event `i` whose `data` is an
  object with `type` = `speech.audio.delta` and a string `audio`, in event order; other events, `[DONE]` and data that
  is not an object are skipped (native skips them, `tts_providers.rs:14-24`, `:50`). `media_type` from the table above
  (native labels the decoded audio by the client's format, `tts.rs:1130-1136`).
- **Usage**: from the last `speech.audio.done` event whose `usage` carries `input_tokens` and `output_tokens` as
  non-negative JSON integers, not both 0 (native keeps the last valid one, `tts_providers.rs:37-48`). Metering `tokens
  {input, output}`; `input_text` / `input_audio` from `usage.input_token_details.text_tokens` / `audio_tokens` only when
  both are present and sum to `input` (I3-2 GI-Q4 precedent; whether OpenAI sends them on TTS is **unverified**).
- **Outcomes**: no valid usage event (missing `usage`, a missing or `null` count, both 0, a negative or fractional count)
  → `unknown`; no delta, or every delta's blob 0 bytes → `unknown`; otherwise `succeeded`. Native answers 502 and parks
  in every one of these cases except negative counts, which it settles (§9 item 3).
- `state`: `{"form": "binary" | "sse", "format": <the lower-cased client format>}`.

**Error body**: `{"error": {"message", "type", "code"}}` → `provider_message` = `message` (the OpenAI shape; other
compatible upstreams **unverified**), else the body text.

## 6. `contracts.media` 3: a declared query parameter on a media descriptor

lv ruled on 2026-10-14 that a media descriptor accepts a query parameter the package declares, as `contracts.media` 3,
additive, landing with this package (S-S-2 resolution of question 1).

**Wire shape: unchanged.** `"query": [{"name", "value"}]` as in contracts 1 and 2. What widens is the set of names a
host must accept.

**Rule.** Contract 3 is contract 2 plus: a descriptor query entry whose `name` is not one of `QueryParameterV1::ALL` is
admitted when, and only when, it equals (byte for byte, case included) the `name` of an entry of the **same package's**
manifest `query_parameters`, and its `value` passes that entry's declared syntax (`digits`, `token`, `date`, `enum`,
`declared.rs:60-120`). It is carried as `QueryParameterV1::Declared`. Everything else is the HTTP contract's existing
rules (contract 10, B7a): a name appears at most once; a declared name can never equal a sanctioned one
(`DeclaredQueryParameterV1::try_new`); the wire order is canonical (sanctioned names in `ALL` order, then declared names
in byte order), so two hosts emit the same bytes; values never come from credential resolution (the component writes
them from request data or constants). A name neither sanctioned nor declared stays `UnsanctionedQuery`; a declared
name with a value outside its syntax is refused by `QueryStringV1` as today.

**South API, additive:**

- `MediaRequestDescriptorV1::parse_with_declared(json, limits, declared: &[DeclaredQueryParameterV1])`; `parse` keeps
  its signature and behaviour and is `parse_with_declared(…, &[])`.
- `parse_prepared_speech_call_with_declared_v1(json, limits, declared)`; `parse_prepared_speech_call_v1` is the same
  with no declarations. `parse_prepared_image_call_v1` is unchanged: gate ① refuses `query_parameters` in the image
  world (S-S-2), so an image descriptor still names sanctioned parameters only.
- `MediaRequestDescriptorV1::minimum_contract_version` returns 3 when the query carries a declared parameter.
- `MEDIA_CONTRACT_VERSION_V3 = 3`; `MEDIA_CONTRACT_VERSIONS = [1, 2, 3]`; `MEDIA_CONTRACT_VERSION` stays 1 (the 0.59.0
  pattern for media 2).

**Host obligations** (gate ③ for a host that serves a package declaring `query_parameters`):

1. Build the package's declarations once, at load, from its gate ①-validated manifest
   (`DeclaredInstancesV1::from_manifest`, `crates/south-component-conformance/src/declared_instances.rs:64`, the
   sanctioned path), and keep them per package: one package's declarations never admit another's names.
2. Parse every `prepare` result of that package with the declared variant. Any other parse refuses the descriptor
   before admission, which is clean but makes the package unusable; item 4 prevents that state.
3. Send the parsed query unchanged: the `QueryStringV1` goes to the binary entry point exactly as a sanctioned query
   does (HTTP contract 12 already carries declared parameters); the host never adds, drops, reorders or re-encodes an
   entry, and request extras cannot add a query parameter.
4. **Range**: the host's media range is `MEDIA_CONTRACT_VERSIONS`. token-station-server keeps its range as a literal
   that its scripts read, pins it equal to that constant and also asserts the set `{1, 2}`
   (`server:…/engine/south_component.rs:2177-2197`); the literal and the assertion move to `{1, 2, 3}` on re-pin. A host
   whose range lacks 3 refuses `speech-elevenlabs` at load (gate ①'s range half, `compatibility_admits`,
   `crates/south-provider-api/src/manifest.rs:2050`), not per call.
5. Declared values are request data, not secrets: they are logged and shown in a request transcript as sanctioned query
   values are.

**Gate ① (SV-Q5).** Proposed: a speech manifest with a non-empty `query_parameters` must declare `contracts.media` ≥ 3,
else a new `ManifestErrorV1` variant. It is static and cheap, and it turns a package that would fail on every call into
a load-time refusal. The 0.59.0 release record left the general "a package uses only words of the media contract it
declares" check for later; this is the one case visible in the manifest.

**Conformance.** The speech suite and the sandbox seam (`SandboxedSpeechComponentV1`) parse prepared calls with the
package's declarations. New golden vectors beside `crates/south-contracts/tests/vectors/media-v1.json` (a descriptor
with a declared parameter: accepted with the declaration, `UnsanctionedQuery` without it, refused with a value outside
the syntax, canonical order with a sanctioned parameter, a name equal to a sanctioned name refused at declaration), each
with a unit test; a host-obligation test that a host parse with and without the declarations matches the vectors. The
`elevenlabs` pack carries the prepared descriptor; a mutation that writes an undeclared name turns the pack red.

**Versioning.** `south-contracts` minor (§13). `compatibility.json` `contracts.media` 3. A media-1 or media-2 descriptor
parses identically under contract 3, so the widening is additive; packages that use no declared parameter keep their
declared media number.

## 7. What the host must do before any V3-1 cutover

The host has no speech executor. Its image executor (`server:…/handler/images/component/`) is the model: the steps below
are the speech counterparts, generic over packages, with no provider names.

1. **Route and binding.** A model-row speech route column (the `component_image` precedent,
   `server:gateway/sql/migrations/0090_models_component_image.sql`, `server:gateway/src/modules/catalog/
   component_image.rs`): a route to a binding key, a speech binding (package pin, family, `base_url`, slot), a save-time
   check that the row carries the `tts` modality (the `supports_image_modality` counterpart) and is not also routed to a
   task component, and a servability view.
2. **`base_url` per binding**: the row endpoint for `speech-xai`, `speech-groq` and `speech-elevenlabs` (their native
   paths are `{endpoint}/v1/…`); the API root for `speech-openai-compatible` (identical to the row endpoint for an
   origin-only endpoint; DeepInfra, Azure and the other rewritten provider types need their root written, §2).
3. **Pricing form from the package.** `tts_arm_pricing` (`tts.rs:34-42`) derives "characters or tokens" from the native
   arm (`pricing()`, `tts.rs:49-55`). For a routed row it must derive it from the package's `model-capabilities`:
   `metering_forms` containing `tokens` = `CharactersOrTokens`, else `CharactersOnly`. The listing gate, the admin view

## 8. `MAX_SPEECH_SEGMENTS`: what bounds it and how it is measured

The segment count is the number of `speech.audio.delta` events in one buffered response. Three bounds apply, and the
first two are computed here from the contract, not measured:

- **The `parse-response` input** (16 MiB runtime payload, record §6): each event in the view is about 185 bytes once its
  `audio` is elided (`{"event":"message","data":{"type":"speech.audio.delta","audio":{"$south.blob":{"id":"b65535",
  "bytes":…,"head":"<64 bytes>"}}}}`), so 65,536 events are about 12 MB.
- **The outcome frame** (4 MiB, `MAX_SPEECH_OUTCOME_JSON_BYTES`): one item `{"pointer":"/65535/data/audio",
  "encoding":"base64"}` is 51 bytes, so 65,536 items are about 3.4 MB.
- **What OpenAI emits** for the longest input a token-priced row accepts: **not measured**. The agent writing this
  record has no upstream key.

Plan, carried out while the OpenAI-compatible fixtures are written (record §18 S-S-4), by the host team with a real key:

1. One capture per format, at least `mp3` and `pcm` (pcm is the largest), with `gpt-4o-mini-tts`, `stream_format:
   "sse"` and an input at the catalog's `tts_max_input_chars` for the row (or the model's documented maximum).
2. Record in `fixtures-speech-openai-compatible/README.md`: the delta count, the smallest, median and largest decoded
   delta, the total audio bytes, the SSE body bytes, whether events carry an `event:` line, and the `usage` shape
   (including `input_token_details`). The capture itself is not committed (its size); one short real capture is,
   trimmed to its first deltas and its `speech.audio.done` event.
3. A generated case (built by the suite test, not hand-written) with 4,096 events, and a unit test that builds the view
   and the outcome at exactly `MAX_SPEECH_SEGMENTS` events and asserts both fit their bounds; one more event is refused
   by the artifact codec.
4. Rule: if the measured count × 4 stays below 65,536, the bound stays and the README says so; otherwise the bound and
   the view budget are revisited before release (S-S-1 resolution of question 4). SV-Q6 asks whether release waits for
   the capture.

### Interpretations

1. **`state`** carries `characters` (the request's scalar count) besides `form` and, for OpenAI-compatible, `format`:
   `parse-response` needs the count for the `characters {value: count, source: request}` metering of §1, and has no
   other input that carries it. On the token-priced path `characters` is present only when the host also requires that
   form. Decision 2 says "only the form and the client format"; this is the minimum addition (still far below 8 KiB).
2. **`format` in the OpenAI state** is the client's `response_format` lower-cased (ASCII, as `openai_tts_content_type`)
   when it is a string, else `null` (absent or not a string, both `audio/mpeg`). An elided `response_format` is not read
   (it counts as absent for the predicted type) and is forwarded as an `as_is` reference, which is native's result too
   (an unknown format labels `audio/mpeg`).
3. **Both forms required** (`metering_required` `[characters, tokens]`, which no host sends today): the call is
   token-priced (`sse`), and the outcome reports `characters` from the request as well.
4. **Elided members** other than `input`: an elided `voice` or `language` (xAI) or `voice` (Groq) is forwarded as an
   `as_is` reference, as native forwards a value its table does not map; an elided `response_format` is refused before
   dispatch with "'response_format' is longer than the gateway accepts" (xAI, ElevenLabs), the generic text of P4; an
   elided ElevenLabs `voice` cannot satisfy SV-Q4's 128-byte bound and is refused with the voice text.
5. **Lower-casing** follows each native arm: Unicode `to_lowercase` for the xAI, Groq and ElevenLabs tables and the xAI
   and ElevenLabs format checks (the refusal texts quote the lower-cased value, as native), ASCII for the OpenAI media
   type table.
6. **ElevenLabs order of refusals**: `input`, then `response_format`, then the voice grammar, so a request that breaks
   both keeps native's format refusal (`prepare.format-and-voice-refused`). The SV-Q4 text, which the record leaves
   open, is "the ElevenLabs voice_id must be 1 to 128 characters of A-Z, a-z, 0-9, '.', '_', '~' or '-' and not '.' or
   '..'"; it does not echo the value.
7. **Refusal texts the record leaves open**: an undeclared operation is `capability` "the model '{upstream id}' does not
   declare the operation {word}"; an empty `metering_required` is `capability` "the host requires no metering form"
   (the synthetic reference's text); a form the package cannot report is "this model cannot report {form}" (§1).
8. **"Else the body text"** (§2–§5 error bodies): the response view carries a non-2xx JSON body as parsed JSON, not as
   its bytes, so a JSON body of another shape gives its compact serialization (members in key order), a text body its
   text, an empty or opaque body none. The cap is `image_shared::capped` (trimmed, first 256 characters), as
   `image-azure`'s precedent family; the synthetic reference dropped longer messages instead.
9. **A 3xx** is `unknown` with the envelope `status_code` gives (`invalid_request`, the 3xx as `http_status`), the
   image references' table; the host keeps the upstream status (§7 item 10).
10. **`segments` items**: every `speech.audio.delta` event whose `audio` is a string (a placeholder in a conforming
    view) is an item, 0-byte ones included when another delta carries bytes (an empty base64 fragment decodes to
    nothing); `unknown` only when there is no item or all are empty (§2). A stream with more than
    `MAX_SPEECH_SEGMENTS` deltas is `unknown` ("more audio fragments than one artifact carries") instead of an artifact
    the codec would refuse.
11. **The OpenAI-compatible API-root rule** reads the binding's `base_url` as written (`ProviderEndpoint::as_str`):
    with a path, `audio/speech` below it; an origin, `v1/audio/speech` (the embeddings package's `resolve` rule).
12. **Where the declared parse is judged**: the suite re-parses each prepared call (`to_json`) with the manifest's
    declarations and reports a refusal under `EndpointConfinement` (the query is part of the URL), so the record's
    "a mutation that writes an undeclared name turns the pack red" is a named test
    (`elevenlabs_speech_suite::an_undeclared_query_name_turns_the_pack_red`).
13. **Vectors** live in `media-v1.json` (the file the record names "beside"), as a new section, with the error words
    `unsanctioned_query`, `invalid_query_value` and `duplicate_query_parameter`.
14. **The SV-Q5 variant** is named `SpeechQueryParametersRequireMedia3 { declared: Option<u32> }`, after the embeddings
    world's `MediaCapabilityRequiresContract2 { declared }`.

### Points that contradict the record (flagged, not silently chosen)

- **`contracts.speech` is not declared.** §1 says the packages declare `contracts` `{media: 1, speech: 1}`
  (`speech-elevenlabs` `{media: 3, speech: 1}`), and also that `compatibility.json` records the `speech` key only at
  S-S-5. The two cannot hold together now: `compatibility_admits` refuses a declared contract the host range does not
  list, and no host range (the test hosts read `compatibility.json`) has a `speech` key, so a manifest declaring
  `speech: 1` would be refused by every host and by this repository's own sandbox tests. Following S-S-3 interpretation
  16 (the synthetic guest declares `{media: 1}`), the packages declare only `media` (1, or 3 for ElevenLabs).
  **S-S-5 must add `"speech": 1` to all four manifests** in the same change that records `contracts.speech`; the
  packages are unpublished, so that is not an identity change, and `shipped_packages_v1` then needs the `speech` key in
  its expected contracts.
