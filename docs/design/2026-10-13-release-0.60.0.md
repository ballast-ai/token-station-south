## 1. What this release carries

- **#196, D7: request pass-through for the `generateContent` surface.**
  - `NorthProtocolV1::GenerateContent` (wire `generate_content`) and the manifest field `north_request_passthrough`
    (`{ <family>: <protocol> }`): the host may send the client's own body to the URL the component builds for the probe
    IR. Gate ① requires the family to declare the same protocol in `north_passthrough` and the Gemini wire in
    `request_facts` (output cap at `/generationConfig/maxOutputTokens`, model and stream flag in the URL); gate ② adds
    `CheckV1::DescriptorIndependentOfBody`; gate ③ adds `south.north-passthrough-delivery.v2`, parameterised by protocol
    (v1 unchanged, 22 cases). `compatibility.json` records the v2 suite as `not_verified` for both hosts.
  - `provider-gemini` declares both fields for family `gemini`.
  - Riding along (D7 record §8): the provider-world manifest field `subscription_quota_families`;
    `provider-openai-compatible` declares `github-copilot`, `provider-openai-responses` declares `openai-codex`.
- **#197, image world step I3-4.** The new package `image-stability` 1.0.0 (family `stability-image`, `bearer`,
  generation only; Stable Image Ultra, Core and SD3.5 large / large turbo / medium as a multipart POST asking for JSON,
  image-to-image from a client data URL through `from_data_url`, `images` metering with `images_reported` null,
  `CONTENT_FILTERED` delivered like `SUCCESS`), contracts `{image: 1, media: 1}`, `south_runtime` 0.57.0. No contract
  change.
- **The release commit** (this branch): the release bump (§5), the three re-declared runtimes (§3), the test helper
  `declared_runtime_now` in `shipped_packages_v1.rs`, and the release notes (README row and package row, ARCHITECTURE
  v0.60.0 paragraph and crate versions, the I3-4 and D7 records' status, this record).

## 3. Hosts

A host that re-pins must handle the new enum variants (`NorthProtocolV1`, `ManifestErrorV1`) where it matches
exhaustively. `ComponentManifestV1` refuses unknown fields, so a runtime before 0.60.0 cannot parse a manifest that
carries `north_request_passthrough` or `subscription_quota_families`: `provider-gemini` 1.3.3,
`provider-openai-compatible` 2.6.3 and `provider-openai-responses` 1.3.3 therefore declare `south_runtime` 0.60.0, and a
host admits them only with a runtime range that reaches 0.60.0. #196 left the three at 0.57.0; the release commit moves
them, as the 0.59.0 release commit moved `image-gemini`. That an older runtime refuses them is read from code, not
run: `ComponentManifestV1` at `v0.59.0` is `#[serde(deny_unknown_fields)]` and has neither field; the declared-runtime
check (§6) proves the other direction, that each package loads under the runtime it declares. Serving `stability-image` additionally needs, on token-station-server, the I3-4 record §5 items; item
4 (unpriced rows) is settled on the host by its enable gate: a model with no image price cannot be enabled (A10,
`server:gateway/src/modules/catalog/service.rs` `admin_set_model_enabled`), so a routed unpriced row never reaches the
component path; and the SI-Q4 400 for an undeclared operation is on the host's dev-v2 (`9e9419a5`, 2026-10-13).
