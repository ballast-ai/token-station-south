## 2. SF27: a Gemini stream's usage comes from its terminal chunk

With IR billing the default for `component` rows, `token-station-server` found every Vertex AI native stream refused by
`provider-gemini`: Vertex puts a `usageMetadata` without counts (`{"trafficType": "ON_DEMAND"}`) on every intermediate
chunk, and the reference stream parser took any `usageMetadata` for a usage report and parsed it strictly. The rule now
(boundary record §13.10):

- The terminal chunk is the one in which any candidate carries a non-null `finishReason`. It emits `Finish`, then
  `Usage` from its `usageMetadata` under the same strict `usage_of` as `parse_response`, then `Done`.
- An intermediate `usageMetadata` is never emitted. It must be an object, and each count it carries must be a
  non-negative integer no lower than in an earlier chunk; the terminal chunk is held to the same non-decrease rule.
- Any frame after the terminal chunk is a protocol error. A terminal chunk without `usageMetadata` yields no `Usage`
  event, never a zero, which the host refuses for want of evidence.
- `parse_response` (non-streaming) is unchanged.

Gate ② gains two stream fixtures in `fixtures-gemini/`
(`provider.stream.vertex-intermediate-usage-metadata-carries-no-counts`,
`provider.stream.intermediate-counts-are-progress-not-usage`); the refusals are unit tests in `reference_gemini.rs`.
