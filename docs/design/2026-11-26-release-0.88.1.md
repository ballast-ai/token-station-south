# Release 0.88.1: public usage rules

Status: prepared on branch `release/0.88.1`. Not tagged.

Date: 2026-11-26

Records: [public usage rules](2026-11-26-public-usage-rules.md),
[CI as the verification gate](2026-10-16-ci-as-the-verification-gate.md),
[boundary record](2026-09-30-host-zero-vendor-boundary.md) §13.12 (Q47),
[release 0.88.0](2026-11-25-release-0.88.0.md).

A patch release. Two usage rules of `south-component-conformance` become public, and every package takes the Q47
patch.

## 1. What this release carries

- **Public usage rules** (#364). `reference_openai_responses::usage_of` judges the OpenAI Responses terminal
  `response.usage`, and `reference_gemini::usage_of` judges Gemini `usageMetadata`. A host's own component that reads
  either wire applies South's rule rather than a copy. The references call the same functions, so the rules do not
  change. Every refusal is a 502 `provider_protocol_error`, and its text names the upstream or its wire, never a
  product.
- **The round** (#365). `south-component-conformance` 0.82.0 → 0.82.1. Every guest links it, so every one of the 41
  packages takes the Q47 patch.

## 2. API changes

- `south-component-conformance` 0.82.1: `reference_openai_responses::usage_of` and `reference_gemini::usage_of` are
  added. Nothing is removed or changed.
- South contract numbers and the kernel tuple are unchanged (`canonical_ir` 5, `stream` 3).

## 3. Hosts

A host re-pins to the 0.88.1 tag and release index. A host that vendors a South package takes its new version: the
reference code reports it, and the old manifest fails the identity check. Behavior does not change. The fixtures are
the ones 0.88.0 published.

## 4. Package identities

Every package takes a new identity (`public_usage_rules_retire_every_published_088_package_identity`). The identities
it retires were published with 0.87.0, and again unchanged with 0.87.1 and 0.88.0. Declared runtime: unchanged.

## 5. The release bump

Step 1 of boundary record §13.12:
- `[workspace.package] version`, 0.88.0 → 0.88.1;
- `compatibility.json` `release.version`;
- the requirements on the workspace-versioned crates in `south-provider-conformance`, `south-testkit`,
  `south-transport-reqwest` and `fuzz`;
- the release-number literal in the workflow test (`rust_library_version_is_independent_of_component_runtime_identity`);
- `fuzz/Cargo.lock`;
- `ARCHITECTURE.md`, `README.md` and `docs/releases.md`; the 0.88.0 record's status and the #364 record's status.

## 6. Verification

The gate is the release pull request's CI run. On `release/*` branches the `components` job runs
`scripts/check-declared-runtime.sh --build`, and `crate-versions` and `language` run as well. #364 and #365 passed the
full local verification from `README.md` before they merged.
