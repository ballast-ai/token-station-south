## 1. What this release carries

- **#177, Responses upstream step R1.** The new package `provider-openai-responses` 1.0.0 (family `openai-responses`,
  the `bearer` arm on `provider_api_key`, `usage_evidence: reported`, SSE as `bytes`): a stateless Responses body
  (`store: false` always, leading system messages as `instructions`, `input_file` and `file_id` refused), strict
  response and `response.*` stream reading, `incomplete` settled only for `max_output_tokens` and `content_filter`, the
  three failure-frame shapes recognised first, any non-zero `tool_usage` refused. The component splits its own SSE with
  `south_component_conformance::sse_split` and links no host-only crate. Two new provider-world manifest fields,
  `immutable_body_paths` and `north_passthrough` (record §3.4), admitted by gate ① for declared families only. Gate ②
  gains the request-refusal form (`{"error": <envelope>}` on a request case) and the check `ImmutablePathsHonoured`. The
  Responses wire vocabulary is `south_component_conformance::responses_vocabulary`. 69 fixtures; a documentation-derived
  usage judge; a fuzz entry. Details in the record's §17.1–§17.4.
- **#178, gate ③ `wire_auth_exact`.** `south.provider-media-binary.v1`, `south.provider-multipart.v1` and
  `south.provider-get.v1` did not measure the credential arm: an adapter that sent a header secret as Bearer passed. Each
  suite's evidence gains the wire claim `wire_auth_exact` (the transport's complete `auth_headers()` list must be exactly
  the one pair `…AuthArmV1::expected_wire_auth_header` builds from the row's declared arm; `true` on reached rows,
  `false` on refused ones) and the mismatch category `WireAuth`. Suite ids, versions and case counts are unchanged.
  Only `south-provider-conformance` and `south-testkit` changed, both workspace-versioned: no guest-linked crate,
  package or `component.wasm` moved because of #178.
- **The release commit** (this branch): the workspace bump; `provider-openai-responses` declares `south_runtime`
  0.54.0 (§4); the release notes (README row, ARCHITECTURE paragraphs, this record, the "unreleased" notes of #177 and
  #178 turned into released wording, and the stale "Unreleased (B6-2)" paragraph of ARCHITECTURE.md turned into a
  `v0.51.0 (B6-2)` paragraph, since #168 shipped in the `v0.51.0` tag; lv approved the cleanup); and one approved fix:
  `scripts/build-anthropic-bedrock-invoke-component.sh` gains the `SOUTH_COMPONENTS_PREBUILT` guard every other build
  script has, and `.github/workflows/ci.yml` gains its `rust-cache` entry.

No contract number changes (`compatibility.json` `schema_version` stays 7) and the kernel pin is unchanged.
`compatibility.json` statuses are unchanged: the host's `verified` for `provider_multipart` and `provider_get` stays as
recorded, and the host re-verifies (§3).

## 2. API changes

### `south-provider-api` 0.51.0 → 0.52.0 (#177)

- `ComponentManifestV1` gains two public fields, `immutable_body_paths: BTreeMap<String, Vec<String>>` and
  `north_passthrough: BTreeMap<String, NorthProtocolV1>` (both `#[serde(default)]`, omitted when empty).
- New: `NorthProtocolV1` (`ChatCompletions`, `Responses`, `Messages`; serialized `chat_completions`, `responses`,
  `messages`), `are_immutable_body_paths(&[String]) -> bool`, `MAX_IMMUTABLE_BODY_PATHS` (64),
  `MAX_IMMUTABLE_BODY_PATH_BYTES` (256).
- `ManifestErrorV1` gains `DeliveryIsAProviderWorldDeclaration`, `InvalidImmutableBodyPaths { family, detail }` and
  `InvalidNorthPassthrough { family, detail }`.
- Gate ①: both fields are request declarations (provider world only), name only declared families, and the paths follow
  the task world's immutable-path grammar. A runtime before 0.54.0 refuses a manifest carrying either field as an
  unknown field.

### `south-component-conformance` 0.51.0 → 0.52.0 (#177)

- `CheckV1::ImmutablePathsHonoured` (`immutable_paths_honoured`).
- New public modules: `reference_openai_responses` (`OpenAiResponsesReferenceV1`, `FAMILY`, `NAME`, `VERSION`,
  `failure_code`), `responses_vocabulary` (`extension`, `event`, `item`, `part`, `incomplete_reason`), `sse_split`
  (`SseSplitterV1`, `SseFrameV1`, `SseSplitErrorV1`, `MAX_SSE_SPLIT_BYTES`).
- Gate ② (`south.provider-component.v1`, still version 1): a request case whose expected file is `{"error": <envelope>}`
  expects `build-http-request` to refuse, and skips the checks that judge a descriptor. Every existing pack passes
  unchanged.

`south-contracts` is unchanged at 0.51.0.

### `south-provider-conformance` and `south-testkit` 0.53.0 → 0.54.0 (#178)

- `ProviderMediaBinaryEvidenceV1::new`, `ProviderMultipartEvidenceV1::new` and `ProviderGetEvidenceV1::new` take a final
  `wire_auth_exact: bool` (the sixth, fifth and sixth argument); each type gains `wire_auth_exact()`.
- `ProviderMediaBinaryMismatchCategoryV1`, `ProviderMultipartMismatchCategoryV1` and `ProviderGetMismatchCategoryV1`
  gain `WireAuth`.
- `MAX_PROVIDER_MEDIA_BINARY_MISMATCHES_V1` 66 → 72, `MAX_PROVIDER_MULTIPART_MISMATCHES_V1` 50 → 55,
  `MAX_PROVIDER_GET_MISMATCHES_V1` 44 → 48.
- `ProviderMediaBinaryAuthArmV1`, `ProviderMultipartAuthArmV1` and `ProviderGetAuthArmV1` gain
  `expected_wire_auth_header(self) -> (&'static str, Vec<u8>)`; `ProviderMediaBinaryExpectedEvidenceV1`,
  `ProviderMultipartExpectedEvidenceV1` and `ProviderGetExpectedEvidenceV1` gain `wire_auth_exact()`.

No other public item changed: `git diff v0.53.0..HEAD -- 'crates/*/src' 'crates/*/wit'` touches only the files of the
items above, the reference metadata versions (§5) and the OpenAI-compatible reference, which now reads its three
`extensions` keys from `responses_vocabulary::extension` with unchanged behavior.

## 3. Hosts

**Breaking for hosts on re-pin.** None of the enums or structs above is `#[non_exhaustive]`:

- a host that matches `ManifestErrorV1` or `CheckV1` exhaustively needs arms for the new variants;
- a host that builds a `ComponentManifestV1` with a struct literal must name the two new fields;
- a host that matches one of the three mismatch categories exhaustively needs a `WireAuth` arm;
- every call of the three evidence constructors needs the new final argument, measured at the transport boundary from
  the prepared request's complete `auth_headers()` list.

**A host must re-verify all three suites** (`south.provider-media-binary.v1`, `south.provider-multipart.v1`,
`south.provider-get.v1`) after its adapters measure `wire_auth_exact`: the `verified` status `compatibility.json`
records for `provider_multipart` and `provider_get` was earned without the claim. This release leaves those statuses as
they are.

Serving `provider-openai-responses` needs a host runtime of 0.54.0 or later (it declares `south_runtime` 0.54.0) and the
host side of the Responses record: honouring `immutable_body_paths` against operator request extras (§3.4), and, if the
host delivers the upstream's bytes to a Responses client, the pass-through conditions of §8.2 with frames cut by
`SseDecoderV1::position` (0.53.0). A host that ignores `north_passthrough` always renders through the north codec. A host
that only re-pins serves what it served before: every other package keeps its behavior and its `south_runtime`.

## 4. The new package's `south_runtime`

`provider-openai-responses` declared the placeholder 0.53.0, the version being built, until this commit (record §17.2).
No published runtime admits `immutable_body_paths` or `north_passthrough` (gate ① refuses unknown manifest fields), so
0.54.0 is the oldest runtime that admits the package, and lv ruled on 2026-10-10 that the release commit sets it, as
`embeddings-gemini` declared 0.51.0 in #167. `shipped_packages_v1::the_responses_package_declares_the_runtime_that_first_admits_its_declarations`
now pins the literal 0.54.0 (it compared with the workspace version before) and that a host claiming 0.53.0 refuses the
package through the declared runtime (`SouthRuntimeAboveHost`).

The change alters `manifest.json`, so the package's `manifest_sha256` is the one this release publishes; no 1.0.0 was
published before, so no identity retires and the version stays 1.0.0. `component.wasm` does not embed the manifest (the
component crate has no build script and reads no manifest file), so its bytes are unaffected; §6 records the evidence.
