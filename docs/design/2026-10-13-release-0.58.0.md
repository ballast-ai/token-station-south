## 1. What this release carries

- **#190, image world step I3-1.** Two new packages in the `image-adapter-v1` world:
  - `image-minimax` 1.0.0 (family `minimax-image`): generation only, `POST {base_url}/v1/image_generation` with
    `bearer`; `?GroupId=` is appended only when the family's declared config key `group_id` (syntax `digits`) is set
    (IM-Q3); a 2xx whose `base_resp.status_code` is non-zero is a failure detected in the body, its envelope carrying the
    host's status for the code, and 1026 ("output violation") is `unknown` (IM-Q4); inline base64 artifacts declare
    `image/png` (IM-Q5).
  - `image-qwen` 1.0.0 (family `bailian-qwen-image`): DashScope's synchronous multimodal generation, including the edit
    models, `url` artifacts; a `size` fact only when the client sent one; a 2xx carrying a DashScope `code` is
    `unknown`. The `image_url` parts, the `WxH → W*H` size and the forwarded parameters live in the shared module
    `bailian_image` of `south-component-conformance`, which `task-wan-image-v2` now uses too, its behaviour unchanged.
  - Both meter `images` with `images_reported` as evidence (neither applies "≤ delivered + 1": that stays in the host,
    IM-Q1), and both declare `south_runtime` 0.57.0.
- **#191**: the scheduled fuzz workflow builds for `--target x86_64-unknown-linux-gnu` (CI only).
- **#193**: `south-component-conformance` exports the Converse cache-point words under the provider-neutral path
  `declared_parameters::CACHE_POINT_PARAMETERS` (a re-export; no package behaviour changes).
- **`compatibility.json`**: token-station-server's `provider_media_binary` suite is recorded as verified (lv,
  2026-10-13, Q10), pinned by `crates/south-contracts/tests/compatibility_manifest.rs`.
- **The release commit** (this branch): the workspace bump (§5) and the release notes (README row and the two package
  rows, ARCHITECTURE v0.58.0 paragraph and crate versions, the I3-1 record's status line, this record).

No contract number changes (`compatibility.json` `schema_version` stays 7), the kernel pin is unchanged (mirror `v0.5.0`,
`canonical_ir` 4), and no published package's `south_runtime` moves.

## 2. API changes

  provider-neutral path.

- New modules `reference_minimax_image` (`NAME`, `VERSION`, `WORLD`, `MINIMAX_IMAGE`, `GROUP_ID`,
  `MiniMaxImageReferenceV1`) and `reference_qwen_image` (`NAME`, `VERSION`, `WORLD`, `BAILIAN_QWEN_IMAGE`,
  `QwenImageReferenceV1`), and the crate-private module `bailian_image` shared with the Wan image reference.
- The references' `VERSION` constants follow §4.

`south-contracts` (0.52.0) and `south-provider-api` (0.53.0) are unchanged. No workspace-versioned crate changes its
public API.

## 3. Hosts

Not breaking for hosts on re-pin: a host that re-pins serves what it served before. Serving the two new families needs
the host's image executor (media contract 1, image contract 1) and a model-row route per model. The I3-1 record §5 lists
what the token-station host does differently from its native MiniMax and Qwen arms, each registered as a difference:
the settlement of `images_reported` (IM-Q1, landed on the host's `dev-v2` as `06da99c4`), funds on a non-2xx by the P29
allow-list (IM-Q2), and a body-detected failure answered 502 while funds are parked (IM-Q6 as re-ruled).
