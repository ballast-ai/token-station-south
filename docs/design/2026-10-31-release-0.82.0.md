# Release 0.82.0: SSE frames under every line end

Status: prepared on branch `release/0.82.0` on top of `origin/main` `0dae5690` (pull request #318, the parser change
with the new package identities). Not tagged. This release pull request, tagging and the host re-pin are separate
steps; this commit carries only the release bump.

Date: 2026-10-31

Records: [messages pass-through and count tokens](2026-10-17-messages-passthrough-and-count-tokens.md) (revision of the
0.82.0 round), [CI as the verification gate](2026-10-16-ci-as-the-verification-gate.md),
[boundary record](2026-09-30-host-zero-vendor-boundary.md) §13.6 (declared runtime) and §13.12 (Q47),
[release 0.81.0](2026-10-29-release-0.81.0.md).

## 1. What this release carries

- **SSE-bodied provider parsers split frames with `SseSplitterV1`** (#318). `provider-openai-compatible`,
  `provider-anthropic` and `provider-gemini` (and `provider-vertex`, which shares the Gemini parser) found frame
  boundaries only at `\n\n` and `\r\n\r\n`. A host cuts an SSE body with `SseDecoderV1`, where LF, CR and CRLF are all
  line ends and may mix, and hands the component each frame's raw bytes; a frame the host closed on a lone-CR blank line
  was held and dropped at the end of the stream. The three parsers now use the splitter `provider-openai-responses`
  already used. The eventstream packages (`provider-kiro`, `provider-anthropic-bedrock-invoke`, the Converse pair) read
  the host's canonical re-encoding, which only writes `\n\n`, and are unchanged.
- **Messages pass-through suite version 4** (`south.north-passthrough-delivery.v2`). Its mixed-framing body carried a
  CR-framed `content_block_delta` for a block never opened, which the old parser never read and a faithful parser
  refuses. That frame is now a `ping` with the same framing; frame count, scripts and case count are unchanged.
- **Reference-level refusal tests** (#317) for the three components' references, each refusal mutation-checked.
  Test-only.

## 2. API changes

None to a public contract.
- `south-component-conformance` 0.79.0 → 0.79.1 (patch): the three reference parsers' frame splitting. Behaviour
  changes only for bodies the old parsers dropped.
- `compatibility.json` `north_passthrough_delivery_v2_suite` 3 → 4.
- `south-contracts` (0.57.0) and `south-provider-api` (0.64.0) are unchanged. The kernel pin is unchanged (protocol
  0.7.0), as are the South contract numbers and the kernel tuple (`canonical_ir` 5, `stream` 3).

## 3. Hosts

Nothing breaks at compile time on re-pin: no struct gains a field, no enum gains a variant. The host moves its pin to
the 0.82.0 release index and tag, because every package took a new identity, and re-runs the messages pass-through
suite at version 4.

Behaviour a host will see: on the four SSE-bodied provider families, a stream whose upstream closes frames on lone-CR
blank lines now delivers every frame instead of losing those frames.

## 4. Package identities

`south-component-conformance` is linked by every component, so the version bump changes every `component.wasm` and
every package takes a Q47 patch (boundary record §13.12, §16 Q47), for example `provider-openai-compatible`
2.13.5 → 2.13.6, `provider-anthropic` 1.4.7 → 1.4.8, `provider-gemini` 1.7.3 → 1.7.4, `provider-vertex` 1.4.3 → 1.4.4
(behaviour changed as in §1) and `task-veo-v2` 0.39.0 → 0.39.1 (unchanged behaviour).

Declared runtime: **no package raises `south_runtime`**; the 29 task, image and speech packages keep 0.81.0 and the 12
provider and embeddings packages keep 0.77.0. The release introduces no manifest field or value that an older runtime's
gate ① refuses or reads differently. The release index is expected to list 41 packages and 1 catalog.

## 6. Verification

The gate is the release pull request's CI run. `quality` includes `scripts/check-declared-runtime.sh --build` on
`release/*` branches; `crate-versions` and `language` run as well. The release workflow runs on the tag: build
scripts, gate ② reports, `check-declared-runtime.sh --dist`, the release index, `check_crate_versions.py --tag`, and
the digest-stability comparison with the published `v0.81.0` index.

The feature pull request (#318) passed CI; reverting any one parser turns exactly its own `sse_line_endings_v1` test
red. Local checks on this commit, each judged by its own exit code: `cargo fmt --all -- --check`,
`scripts/check-language.sh`, `cargo metadata --locked --offline` for `fuzz`, and
`python3 scripts/check_crate_versions.py`.

The tag itself is not created here.

## 7. Not verified

- No package of this release has been called against an upstream. Which upstreams close SSE frames on lone CRs is not
  known; the change follows the host decoder's grammar, not a captured stream.
