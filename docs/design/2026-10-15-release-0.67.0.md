## 1. What this release carries

All three changes arrived in one pull request, #243.

- **`speech-openai-compatible` 1.1.0**: speech on Azure OpenAI and Azure Foundry rows, following the embeddings
  `azure-openai-v1` precedent (lv, 2026-10-15). There are two families:
  - `azure-openai-v1` serves `audio/speech`, `audio/transcriptions` and `audio/translations` below
    `{endpoint}/openai/v1`.
  - `azure-openai-dated` serves `openai/deployments/{deployment}/audio/…?api-version=` and takes the config key
    `api_version`, declared exactly as `provider-openai-compatible` declares it (default `2024-10-21`).

  Both families present the key as `header_secret` `api-key`. AO-Q1 to AO-Q7 are at their defaults. This change took
  the cycle's Q47 round (§4).
- **`task-veo-v2` 0.36.1** (Q-VV1): consider a Vertex operation name of the shape
  `projects/*/locations/*/publishers/google/models/{m}/operations/{id}`. The package now polls it under the binding's
  own location prefix, so a name that carries the project number stays inside the endpoint the host authorized.
  - A name that already matches the binding gives native's URL unchanged.
  - A name of any other shape is polled verbatim, as before.

  This is unverified: there is no capture of a Vertex Veo create response.
- **`south-provider-api` 0.59.0, `provider-anthropic` 1.2.1** (Q-CC3): a new per-family declaration in the
  provider-world manifest, `immutable_request_headers`. It is shaped like `immutable_body_paths` and lists the request
  headers that a host's extra request configuration must never set, override, append to or remove.
  - Names are lower case.
  - No header is protected implicitly: credential headers and `user-agent` are protected only when listed.

  The `claude-code` and `claude-code-setup-token` families each declare nine headers. Registered difference PRH-D1:
  native refuses every header extra on `claude_code` rows, whereas component rows refuse only the declared names.

## 2. API changes

- `south-provider-api` 0.58.0 → 0.59.0. It gains:
  - the field `ComponentManifestV1::immutable_request_headers`;
  - the error variant `ManifestErrorV1::InvalidImmutableRequestHeaders`;
  - the function `are_immutable_request_headers`;
  - the constants `MAX_IMMUTABLE_REQUEST_HEADERS` and `MAX_IMMUTABLE_REQUEST_HEADER_NAME_BYTES`.

  `ManifestErrorV1` is not `#[non_exhaustive]`.
- `south-component-conformance` 0.65.0 → 0.66.0: the speech Azure references, the Veo rewrite and the Claude Code
  header table.
- `south-contracts` (0.56.0) is unchanged. No contract number changes.

## 3. Hosts

These steps are breaking at re-pin:
- add the `InvalidImmutableRequestHeaders` arm wherever the host matches `ManifestErrorV1` exhaustively;
- add the new field to `ComponentManifestV1` literals;
- make sure the host's accepted runtime range reaches 0.67.0, because `provider-anthropic` 1.2.1 declares it.

A runtime older than 0.67.0 refuses `provider-anthropic` 1.2.1 (`deny_unknown_fields`) instead of loading it and
ignoring the declaration.

The host should enforce `immutable_request_headers` (record §7):
- refuse a matching header extra when it is saved;
- skip and log any stored one at runtime;
- make the Claude Code cutover preflight FAIL on one.

The host keeps its reserved-header floor and its native block on `claude_code` rows until the native arm is deleted.

Further prerequisites:
- **Azure speech**: route Azure OpenAI and Foundry speech rows to the two families, `base_url` per record §5:
  - a dated row binds the row endpoint;
  - a v1 row binds `{endpoint}/openai/v1`.

  These are the same rows that the text families T8 and T9 migrate.
- **Veo on Vertex**: no host change. The poll URL is now always under the bound prefix for publisher-model names.
