A patch release, as FQ-3 of the stream parser record rules: it carries one fix and its CI changes, and no new feature.

## 1. What this release carries

- **The first error of a stream in byte order.** `SseSplitterV1::push` returns the frames it completed before a
  refusal together with the refusal (`SsePushV1`), and the four SSE stream parsers judge those frames first. A stream
  whose bytes hold an invalid frame and, later, a line that is not UTF-8 now reports the invalid frame's error however
  the bytes were chunked. Both errors are a 502 `provider_protocol_error`, so no status code or billing outcome changes.
  Affected packages: `provider-openai-compatible`, `provider-anthropic`, `provider-gemini`, `provider-vertex`,
  `provider-openai-responses`.
- **CI.** The fuzz checks of the Bedrock invoke and Kiro parsers compare what the stream contract promises. Each fuzz
  target reports every finding in one run. A failing scheduled run opens or updates an issue.

## 2. API changes

- `south-component-conformance` 0.81.0: `SseSplitterV1::push` returns `SsePushV1` instead of
  `Result<Vec<SseFrameV1>, SseSplitErrorV1>`. `SsePushV1::into_result` gives the old shape, for a caller that refuses
  its whole input on any refusal.

South contract numbers and the kernel tuple are unchanged (`canonical_ir` 5, `stream` 3). The `StreamParserV1` trait and
the WIT export are unchanged.

## 3. Hosts

A host re-pins to the 0.83.1 release index and tag, because every package took a new identity. The host links
`south-component-conformance` but does not call `SseSplitterV1` (`server:gateway/tests/text_stream_sse_framing.rs`
names it only in a comment), so the re-pin needs no host code change. The re-pin is done by the session that owns the
host's re-pins.

## 4. Package identities

`south-component-conformance` is linked by every component, so every package takes the Q47 patch (boundary record
§13.12, §16 Q47); `first_error_retires_every_published_083_package_identity` pins the round.

Declared runtime: unchanged. No package declares a field that a 0.83.0 runtime cannot read. The 29 task, image and
speech packages keep 0.81.0, `provider-openai-compatible` keeps 0.83.0, and the other 11 provider and embeddings
packages keep 0.77.0.

## 6. Verification

The gate is the release pull request's CI run. On `release/*` branches the `components` job runs
`scripts/check-declared-runtime.sh --build`, and `crate-versions` and `language` run as well. The release workflow
runs on the tag.

The tag itself is not created here.
