# 任务复合原子效果履约套件

状态：公共实现及本地仓验收通过，宿主最终收口另记。公共包 `south-task-conformance` 独立版本
`0.1.0`，不改变 South `0.31.0` 的组件 runtime、WIT 或既有任务绑定身份。

## 目的

共享核心只能规定调用顺序，不能替宿主保证事务。此套件对准备、派发、终结、
取消与恢复的真实效果施加同一组判据。两个宿主可以使用不同数据库与资源政策，
但不允许任务事实、资源动作和终态事件部分提交。

测试适配器提供显式 `AtomicHarness`。套件不访问文件、网络、环境、时钟或
凭证，不依赖宿主、SQL 或缓存。宿主原子接口仍可以携带私有政策 token，
套件只读取任务事实、效果次数与不可逆资源摘要；金额和租户不成为公共合同。

## 十一个事故场景

1. 准备事务最后步骤失败：任务、资源及事件全部回滚，再试能成功。
2. 同键同请求重放与同键异请求冲突：不重复预占或改写事实。
3. 准备已提交但回包丢失：原键重试找到既有任务。
4. 终结事务最后步骤失败：终态 CAS、资源和事件全部回滚。
5. 终结已提交但回包丢失：旧观察重放不再次结账或发事件。
6. 终态重复观察，包括最新版本的重复观察：不二次生效。
7. 新 owner 已持久接管：旧版本不能写回，新版本仍可完成。
8. 取消先赢 prepared 状态：阻止后续派发，资源只关闭一次。
9. 派发先赢：本地取消不能假装证明未执行，也不能二次派发。
10. 取消已确认但费用未知：有资金的宿主保留资源，后续明确免费证据可闭合；
    无资金宿主明确资源不适用，不制造虚拟挂账。
11. 明确失败：终态、资源关闭和事件恰好一次。

`BeforePrepareCommit` 与 `BeforeApplyCommit` 必须让真实事务中的后置步骤失败，
不能用调用前直接返回错误冒充回滚。`After*Commit` 明确在真实提交后丢回包。
每次 `reset` 建立独立夹具，不复用前一个场景的任务。并发竞争与实际进程死亡
保留在宿主补充验收中；两个顺序场景不冒称已经覆盖所有数据库隔离问题。

## 套件自身证据

先提供空 runner，四个公开测试均真红（0/4）；实现后四个测试通过，其中正确
参考实现分别使用有资源与无资源两种形态，三个缺陷变体分别拆开准备事务、
拆开终结事务、忽略版本守卫。它们必须被具名场景拒绝。

参考实现只证明套件可抓住错误，不计为真实宿主采用。真实验收须分别记录
server SQLite、server PostgreSQL、社区 SQLite，以及同一核心和组件包的调用。

独立审查发现并修复了两个漏检：只检查 terminal 布尔值不能防止把成功写为失败；
只检查关闭次数不能防止错误全额退款。新增持久执行类别，以及宿主针对固定
夹具独立计算的预期资源摘要；摘要不可从实际结算结果回读充当答案。无资金
模式在场景开始固定，不能因丢失台账而在途中变成不适用。
两个错误实现均先证明旧套件错误放行，再验证修后拒绝；最终 **6/6** 公共测试，
共五类错误实现被拒。修后 South README 全 **16/16**、707/707，证据索引
`/tmp/target-architecture-m3-south-final-v3-results.json`。
server SQLite 余额/配额、真实 PG 均已通过这 11 个场景；社区 SQLite 也已通过，
真实 CLI 与宿主最终矩阵尚需各自记录，不能由这些仓储结果推导全部已交付。
