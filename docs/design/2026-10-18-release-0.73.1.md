# Release 0.73.1: the Messages pass-through delivery suite follows the parser

and the host re-pin are separate steps.

Date: 2026-10-18

Records: [Messages pass-through, forwarded client headers, and a count-tokens operation](2026-10-17-messages-passthrough-and-count-tokens.md)
§3.5, [release 0.73.0](2026-10-17-release-0.73.0.md), [CI as the verification gate](2026-10-16-ci-as-the-verification-gate.md),

The release follows lv's ruling, relayed to this session, to ship 0.73.1 as a patch release and re-pin the host at once.

## 1. What this release carries

- **#268, the delivery suite answers `Done` on `message_delta`.** The 0.73.0 suite scripted `Done` on `message_stop`;
  the shipped `provider-anthropic` reports `Finish`, `Usage` and `Done` on the `message_delta` that carries usage
  (Anthropic record D3). Record §3.5 (ruled 2026-10-17) makes the suite follow the parser: `Done` must arrive on a
  `message_delta`; from that frame the host withholds it, any clean `ping` and `message_stop`, settles when
  `message_stop` is in hand and releases the withheld frames once the settlement persists. A new test drives the
  reference parser over every faithful `messages` case (`north_passthrough_script_parity`).

## 2. API changes

- `south-provider-conformance` (workspace-versioned): delivery suite v2 at suite version 3, with the `messages` rule
  above; the reference executor follows it.
- `south-testkit` (workspace-versioned): the runner and the script-parity test.
- `south-contracts` (0.56.0), `south-provider-api` (0.61.0) and `south-component-conformance` (0.72.0) are unchanged.
  No contract number changes; the kernel pin is unchanged.

## 3. Hosts

`compatibility.json`: `north_passthrough_delivery_v2_suite` is 3 (moved by #268). The server host's
`north_passthrough_delivery_v2` entry stays `not_verified`; the host re-runs the suite and records the result.

A host that followed the 0.73.0 suite literally refuses `Done` on `message_delta` and parks every real Messages
stream; it should follow §3.5. Nothing else changes for a host: no manifest field, no WIT function, no error variant.

## 4. Package identities

Neither changed crate links into a component, and the three guest-linked crates are unchanged, so no package is
re-identified: every package keeps the version and digest it had in 0.73.0, and every `south_runtime` is unchanged.
The release index is expected to list the same 41 packages and 1 catalog as 0.73.0. The release workflow's
digest-stability comparison with the published `v0.73.0` index checks this on the tag.
