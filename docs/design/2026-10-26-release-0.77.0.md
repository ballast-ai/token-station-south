# Release 0.77.0: Gemini 3 tool-call signatures

Status: prepared on branch `release/0.77.0`, based on `origin/main` `47755a28` (pull request #289, the signatures
feature, on top of #290, the zstd advisory ignores). Not tagged. The release pull request, tagging and the host re-pin
are separate steps.

Date: 2026-10-26

Records: [Gemini 3 tool-call signatures](2026-10-26-gemini-tool-call-signatures.md),
[CI as the verification gate](2026-10-16-ci-as-the-verification-gate.md),
[boundary record](2026-09-30-host-zero-vendor-boundary.md) §13.6 (declared runtime) and §13.12 (Q47),
[release 0.76.0](2026-10-21-release-0.76.0.md).

## 1. What this release carries

- **Gemini 3 tool-call signatures** (`gemini3-tool-signatures`, accepted by lv on 2026-10-26). The kernel pin moves to
  mirror `v0.6.0` (protocol 0.7.0, `canonical_ir` 5, `stream` 3), whose `ToolCall` and `StreamEvent::ToolCallDelta`
  gain `signature: Option<String>`. `gemini_text.rs` (shared by `provider-gemini` and `provider-vertex`) copies a
  `functionCall` part's `thoughtSignature` into that call's signature in both modes and writes it back on the same
  `functionCall` part on the next turn; the results of one parallel tool-call batch now share one `user` turn. The
  Chat Completions north codec renders and reads the signature at
  `tool_calls[i].extra_content.google.thought_signature`.

## 2. API changes

- Kernel: `token-station-protocol` 0.6.0 → 0.7.0 (mirror `v0.5.0` → `v0.6.0`, revision
  `ce6894d99f51283e4985d39a2d533307bda27b6a`). `ToolCall` and `StreamEvent::ToolCallDelta` gain `signature`, omitted
  when `None`, so IR without signatures serializes byte for byte as before.
- `south-north-codec` (workspace-versioned): `CodecError::ToolCallSignatureInvalid { field }`, stable code
  `tool_call_signature_invalid`. The enum is not `#[non_exhaustive]`, so an exhaustive host match must add the arm.
- `south-component-conformance` 0.75.0 → 0.76.0: the new Gemini and Vertex fixture packs and the re-pinned reference
  implementations.
- `south-contracts` (0.56.0) and `south-provider-api` (0.63.0) are unchanged. No South contract number changes;
  `compatibility.json` records the kernel tuple `canonical_ir` 5, `stream` 3.

## 3. Hosts

**Breaking on re-pin**: a host that builds `ToolCall` or `ToolCallDelta` by struct literal must add `signature`; a
host that matches `CodecError` exhaustively must add the new variant. A host must record runtime 0.77.0 and
`canonical_ir` 5 in its range to admit any package of this release (§4).

`compatibility.json`: the delivery suites are unchanged.

Unverified: whether Gemini 3 ever streams a signature on a part separate from its `functionCall` (signatures record
§7); nothing was called against an upstream for this release.

## 4. Package identities

The kernel tuple is package content (`compatibility.ir_schema_id`, `kernel_version`, `kernel_revision`,
`kernel_contracts`), so every package published with 0.76.0 retires
(`gemini_signatures_retires_every_published_076_package_identity`):
- `provider-gemini` 1.5.2 → **1.6.0** and `provider-vertex` 1.2.2 → **1.3.0** (signature capture and replay, merged
  tool results);
- the other 39 packages take one patch with unchanged behaviour, for example `provider-anthropic` 1.4.3 and
  `provider-openai-compatible` 2.13.1.

Declared runtime: every package raises `south_runtime` to **0.77.0**. Its kernel tuple records `canonical_ir` 5, which
no runtime before 0.77.0 records, so no earlier runtime admits it; until the workspace is 0.77.0 no runtime of that
number exists, so the raise lands in this commit, as the raises of releases 0.74.0 and 0.76.0 did. The tests that pin
it move with it: `declared_runtime_now` returns 0.77.0 for every package, the retired-identity rows of earlier rounds
and the single-package runtime assertions read 0.77.0, and the special cases some rounds carried (`image-vertex`,
`task-gemini-omni-v2`, the speech packages) fold into `declared_runtime_now`. No package's `contracts` move. The
release index is expected to list 41 packages and 1 catalog.

## 6. Verification

The gate is the release pull request's CI run (`quality`, which on `release/*` branches includes
`scripts/check-declared-runtime.sh --build`; `crate-versions`; `language`). The release workflow (build scripts, gate ②
reports, `check-declared-runtime.sh --dist`, the release index, `check_crate_versions.py --tag` and the
digest-stability comparison with the published `v0.76.0` index) runs on the tag.

Local verification on this tree, each step judged by its own exit code: `cargo fmt --all -- --check`,
`cargo clippy --workspace --all-targets --all-features -- -D warnings`, `scripts/check-boundaries.sh`,
`scripts/check-language.sh`, `python3 -m unittest discover -s scripts -p 'test_*.py'`,
`python3 scripts/check_crate_versions.py --unreleased`, `cargo metadata --locked --offline --manifest-path
fuzz/Cargo.toml` and `cargo test --workspace`.

The CI run of #289 failed on three zstd advisories published the same day (RUSTSEC-2026-0391, -0398, -0403), unrelated
to this change; they are ignored with their reachability reasons by a separate pull request (#290) until wasmtime moves
to 51. (Corrected 2026-10-27: #290 said 50, but wasmtime 50 still requires zstd ^0.13; the move to zstd 0.14.3 is
bytecodealliance/wasmtime#15003, which ships with wasmtime 51.)

The tag itself is not created here.
