## 1. What this release carries

- **#183, NC-1 and `south.north-passthrough-delivery.v1`** (lv accepted the record on 2026-10-12, NP-Q1 to NP-Q13 as
  recommended).
  - *North codec.* `chat_request_from_responses` keeps every OpenAI reasoning item of an assistant run that carries a
    non-empty `encrypted_content`, in order and with its position, under the replay markers the Claude carrier uses
    (family `openai-encrypted-reasoning`, a `reasoning_item` layout entry, `responses_opaque_reasoning_items`), and no
    longer writes the two single-valued keys `responses_reasoning_id` / `responses_reasoning_encrypted_content`
    (NP-Q5). A request carrying both replay families, an unknown `tsr.` version, an opaque item without a non-empty
    `id`, or more than the NP-Q11 bounds is `reasoning_replay_invalid`. G3: `responses_error_event`, built by the same
    function as the render state's failure frame.
  - *Components.* `provider-openai-responses` 1.1.0 replays such a turn for a model declaring
    `reasoning_replay.openai.v1`, refuses it for any other model, and sends `include: ["reasoning.encrypted_content"]`
    on every request to a declaring model. `provider-openai-compatible` 2.5.0 and `provider-gemini` 1.2.0 refuse the
    OpenAI family instead of dropping it silently (NP-Q4); Anthropic, Invoke and Converse already refused it; a fixture
    row in the Anthropic, Converse and Converse-bearer packs now pins that.
  - *Gate ③.* `south.north-passthrough-delivery.v1`, 22 cases, in `south-provider-conformance` (abstract per-call
    verdicts, no IR, a normal dependency on `south-host-grammars`), with the reference executor and eighteen deliberate
    mistakes (`NorthPassthroughFaultV1`) in `south-testkit`. `compatibility.json` gains the suite id and version and
    `host_capabilities.*.north_passthrough_delivery: not_verified` for both hosts.
- **#184, `image-azure` 1.0.2.** The multipart edit's `PreparedImageCallV1` declares `immutable_body_paths` =
  `model`, `n`, `size`, `width`, `height`, `response_format`, `image`, `mask`, so a host can inject operator request
  extras into an edit without overriding a part the adapter sets. `contracts.image` documents what a path means on a
  multipart descriptor (a single segment naming a part, its `[]` array form included). Doc only in `south-contracts`;
  no type and no contract number changes. The generation's JSON paths are unchanged.
- **The release commit** (this branch): the workspace bump (§5), the release notes (README row and the "unreleased"
  wording of #183 turned into released wording, the ARCHITECTURE v0.55.0 paragraph, status lines of the two Responses
  records, the image world revision note, this record).

No contract number changes (`compatibility.json` `schema_version` stays 7) and the kernel pin is unchanged. No package's
`south_runtime` moves.

## 3. Hosts

**Breaking for hosts on re-pin, by behavior rather than by API.** A host that reads `responses_reasoning_id` or
`responses_reasoning_encrypted_content` from the codec's output no longer finds them; replayable runs carry the NC-1
keys instead and keep assistant texts as separate parts. Requests the codec accepted before can now be
`reasoning_replay_invalid` (§1). A host that re-pins without the record's §2.7 still refuses opaque replay on component
legs (its filter is unchanged), so nothing new reaches a component until the host opts in.

Serving the OpenAI replay needs the host side of record §2.7 and a model declaring `reasoning_replay.openai.v1`.
Delivering upstream bytes to a Responses client under `north_passthrough` should be verified with
`south.north-passthrough-delivery.v1`; both hosts are recorded `not_verified`.

A host that injects operator extras into a multipart image edit should honor `image-azure` 1.0.2's part names as the
image world record §7 describes; a host that injects nothing there is unaffected.
