## 1. What this release carries

- **#194, image world step I3-2.**
  - `contracts.media` 2: the transform word `data_url_payload` (a base64 `data:` URL to its base64 payload, as text, so
    a JSON template can carry the bare base64 of a client's data URL; GI-Q1). Done as embeddings contract 2 was:
    `MEDIA_CONTRACT_VERSION` stays 1, `MEDIA_CONTRACT_VERSION_V2` and `MEDIA_CONTRACT_VERSIONS` are added, every
    media-1 package keeps declaring media 1, and a host admits a media-2 package by widening its range.
    `compatibility.json` records media 2.
  - The new package `image-gemini` 1.0.0 (family `gemini-image`, `header_secret` `x-goog-api-key`): generation and
    multipart edit through `POST {base_url}/v1beta/models/{model}:generateContent`, `n` sent as `repeat` (GI-Q2),
    `tokens` metering with `total_input` / `total_output` required (the modality split only when it adds up) or
    `images` metering with `images_reported` null, the `resolution` tier only on per-image calls where the client sent
    one (GI-Q3), safety outcomes per GI-Q5, edit input media types per GI-Q6, thought parts skipped (GI-Q7). It shares
    the crate-private module `gemini_image` with the coming Vertex package (I3-3). It declares `contracts.media` 2 and
    `south_runtime` 0.59.0, the first runtime that decodes media 2.
  - `image-minimax` 1.0.1 is a behaviour fix: each string of an `image_url` array is its own
    `{"type":"character","image_file":…}` reference, as the native arm builds it (1.0.0 wrapped the whole array into one
    reference; found by token-station-server's I3-1 dual run).
  - Q47: every other package published with 0.58.0 takes a patch with unchanged behaviour.
- **The release commit** (this branch): the workspace bump and `image-gemini`'s `south_runtime` (§5), and the release
  notes (README row and package rows, ARCHITECTURE v0.59.0 paragraph and crate versions, the I3-2 record's status, this
  record).

The kernel pin is unchanged (mirror `v0.5.0`, `canonical_ir` 4).

## 2. API changes

### `south-contracts` 0.52.0 → 0.53.0

- `MediaTransformV1::DataUrlPayload` (wire `"data_url_payload"`): reads text, produces text.
- New: `MEDIA_CONTRACT_VERSION_V2` (2), `MEDIA_CONTRACT_VERSIONS` (`[1, 2]`),
  `MediaTransformV1::minimum_contract_version`, `MediaRequestDescriptorV1::minimum_contract_version`.
  `MEDIA_CONTRACT_VERSION` is still 1.

### `south-component-conformance` 0.56.0 → 0.57.0

- New module `reference_gemini_image` (`GeminiImageReferenceV1` and its constants) and the crate-private module
  `gemini_image`.
- `reference_minimax_image`: the `image_url` array fix above; its refusal messages are the native arm's.
- The references' `VERSION` constants follow §4.

`south-provider-api` (0.53.0) is unchanged.

## 3. Hosts

A host that re-pins keeps serving what it served before, provided its media range check is not "exactly media 1": to
admit `image-gemini` it widens the range to `MEDIA_CONTRACT_VERSIONS`, as it did for `EMBEDDINGS_CONTRACT_VERSIONS`.
Serving the `gemini-image` family additionally needs multi-round dispatch (`repeat > 1`); token-station-server has it
(dev-v2, 2026-10-13), and the I3-2 record §5 lists the rest of the host's preconditions. Nothing enforces yet that a
package declaring media 1 uses only media-1 words (`minimum_contract_version` has no caller); that is a host or gate ①
decision for later.
