# v0.29.0 发布准备：不可变包身份与任务兼容证据

2026-09-20；基线 `acdcc8c`。本批准备正式发布内容，但不推送、不打标签、不创建 Release；版本号修改不代表已发布或任一宿主已生产采用。

## 版本和包身份

workspace 与 compatibility release 为 `0.29.0`。五个包分别为 openai-compatible `2.1.1`、anthropic `1.0.2`、gemini `1.1.1`、task-kling v1 `1.0.1`、task-kling-v2 `0.29.0`。每包 Cargo、manifest 和 reference metadata 三方一致，manifest 的 south_runtime 为 `0.29.0`。内部 path 依赖版本和 fuzz lock 同步；不得改写既有 tag、历史包字节或历史版本回归哨兵。

发布包包含 manifest 与 Wasm；任一内容改变都不能在相同 world/name/version 下覆盖旧包。此次 provider 翻译不扩能力，但构建与兼容元组变化，同步递增身份。task-v1 同时包含已验证的查询认证修复；v2 包含显式定位、完整任务事实与独立请求估算，保持 world 与 v1 可辨认。

## 独立兼容状态

compatibility schema 升为 4，新增 task_component_capabilities，按宿主与 task_v1/task_v2 分开记录生产采用；当前四格均为 not_verified，不填写伪造 passing cases。conformance 明确登记两个任务 suite。既有 host_capabilities 仍对应其九项 transport 验证，顶层 hosts 仍只汇总 provider_call，不替代 task 能力。

South 原生／Wasm conformance、server 的 11 条真实授权／计价／估算候选测试属于已取得的有限证据；完整 prepare/reserve、数据库任务恢复、worker 升降级、managed 链路与社区 task 采用尚未验证。不能把本仓 suite 或临时消费者测试标成完整宿主采用。

## 历史 runtime 与发布边界

继续严格比较宿主独立给定的兼容元组，0.29.0 宿主期望拒绝 0.28.1 包。禁止从清单反填期望或增加未经真实验证的兼容白名单。旧包不可变留存不等于跨 runtime 恢复；旧 worker 排空或显式兼容实现由宿主后续验收，旧包需留存于与新 runtime 活动根分离的位置。

发布继续走现有 tag workflow：tag 与 workspace 一致、使用既有五个构建脚本、打包两个普通文件、生成 SHA256 校验和，再由 workflow 发布。此准备阶段只在本地执行相同构建／打包和检查，不手工上传，也不改变 CI 触发模型。
