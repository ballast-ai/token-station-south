## 1. What this release carries

- **`image-qwen` reports a resolution tier word** (issue #297, server backlog 03 #142; lv 2026-10-27 chose the South
  route). The package declares the `resolution` tier dimension and reports `1K` or `2K`, in the price card's spelling,
  on every request:
  - A size word is reported upper-cased. `4K`, which the card does not price, is reported as well, so the host refuses
    it before dispatch.
  - A `WxH` / `W*H` size is `2K` above 2048 × 1024 pixels and `1K` otherwise.
  - An unsized request, or any other size, is `1K`.

  The host then prices the model's tier price table, `input_each` × input images included. Until now every input image
  of an image-to-image or edit request went unbilled (the card lists about 0.003 USD per input image).
- **`provider-openai-responses` refuses a non-empty `stop`** (issue #298, server backlog 03 #62; lv 2026-10-27). The
  Responses wire has no stop field. The package used to drop the field silently, so a client got a 200 with an answer
  that was never cut and paid for the extra tokens. It now refuses with a capability error (400) before any upstream
  call. An empty `stop` is still accepted. This covers the three families the package serves: `openai-responses`,
  `openai-codex` and `bedrock-mantle`.

## 2. API changes

None to a public contract.
- `south-component-conformance` 0.76.1 → 0.77.0 (minor): the two reference changes and their fixture packs. A request
  carrying `stop` that used to be accepted is now refused, so the change is not compatible (CONTRIBUTING).
- `south-contracts` (0.56.0) and `south-provider-api` (0.63.0) are unchanged, as are `south-north-codec` and every other
  workspace-versioned crate apart from the release number. The kernel pin is unchanged (protocol 0.7.0), as are the
  South contract numbers and the `compatibility.json` kernel tuple (`canonical_ir` 5, `stream` 3).

## 3. Hosts

Nothing breaks at compile time on re-pin: no struct gains a field, no enum gains a variant, no delivery suite changes.
A host that records runtime 0.77.0 admits every package of this release (§4). The host moves its pin to the 0.79.0
release index and tag, because every package took a new identity.

Behaviour a host will see:
- **Qwen-Image now always reports a tier.** On a host model without a tier price table, the host serves only the
  catalog default resolution, so a Qwen-Image model routed to `image-qwen` 1.1.0 needs a tier price table (`1K`, `2K`,
  and `input_each`) before it serves. That is the same order of operations as `image-xai`. With the table, the host
  prices per tier and per input image; without it, requests are refused before dispatch. No request is charged at the
  wrong price.
- **A Responses-family row refuses `stop`.** A Chat (or Messages) request with a non-empty `stop` routed to an
  `openai-responses`, `openai-codex` or `bedrock-mantle` row gets 400 and the upstream receives nothing.

## 4. Package identities

`south-component-conformance` is linked by every component, so the version bump changes every `component.wasm` and every
package takes a new version (boundary record §13.12, §16 Q47):
- `image-qwen` 1.0.21 → **1.1.0** and `provider-openai-responses` 1.5.4 → **1.6.0** (behaviour changed);
- the other 39 packages take one patch with unchanged behaviour, for example `image-minimax` 1.0.21 → 1.0.22 and
  `provider-openai-compatible` 2.13.2 → 2.13.3.

Declared runtime: **no package raises `south_runtime`; all 41 keep 0.77.0.** The `resolution` tier dimension and tier
words are image contract 1 vocabulary that 0.52.0 already parses (`image-xai` reports them), and the refusal is an
ordinary error envelope. The release introduces no manifest field or value that an older runtime's gate ① refuses or
reads differently, and no runtime-side meaning a descriptor depends on. The release index is expected to list 41
packages and 1 catalog.

## 6. Verification

The gate is the release pull request's CI run. `quality` includes `scripts/check-declared-runtime.sh --build` on
`release/*` branches; `crate-versions` and `language` run as well. The release workflow runs on the tag: build scripts,
gate ② reports, `check-declared-runtime.sh --dist`, the release index, `check_crate_versions.py --tag`, and the
digest-stability comparison with the published `v0.78.0` index.

Local checks on the feature commits (#300), each judged by its own exit code:
- `cargo fmt --all -- --check`;
- `scripts/check-language.sh`;
- `cargo test -p south-component-conformance --tests`;
- `cargo metadata --locked --offline` for every component, `fuzz` and the synthetic speech guest;
- `python3 scripts/check_crate_versions.py --tag v0.79.0`.

The tag itself is not created here.

## 7. Not verified

- The 1K / 2K pixel boundary. The card names the tiers without a pixel boundary. The rule here (more than 2048 × 1024
  pixels is `2K`) is inferred from the nominal sizes and has not been checked against a real Bailian bill.
- Whether Bailian accepts a size word (`1K`, `2K`) for every Qwen-Image model; the package forwards it as sent, as
  before.
- No package of this release has been called against an upstream.
