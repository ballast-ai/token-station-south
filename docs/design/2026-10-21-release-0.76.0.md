## 1. What this release carries

- **Bailian thinking cap** (`feature/bailian-thinking-cap`). `request_facts` may declare a reasoning cap
  (`reasoning_cap`, the body locations of the reasoning budget) and `cap_overhead` (the tokens the upstream adds beyond
  the two caps), so a family whose `max_tokens` bounds only the answer can split the authorised cap N into
  `thinking_budget = B` and `max_tokens = N - B - cap_overhead` and still keep the billed output at most N. Gate ②'s
  `RequestFactsHonoured` accepts the split and `ImmutablePathsHonoured` exempts a declared reasoning-cap path.
  `provider-openai-compatible` gains the family `bailian-openai-compatible` (DashScope's OpenAI-compatible Chat
  surface) with `cap_overhead` 3, `thinking_budget` immutable to request extras and the model-parameter word
  `thinking_budget` that opts a model into the split.
- **Qwen-ASR** (`feature/speech-qwen-asr`). `speech-qwen` adds `transcribe` for `qwen3-asr-flash` on the Qwen-TTS path:
  the multipart `file` part sent as a data URL (at most 10,000,000 bytes), an optional context `prompt`, `language` and
  `enable_itn`; client formats `json` and `text` only; billed by `usage.seconds`. Synthesis is unchanged.
- **Wan media** (`feature/bailian-wan-media`). `task-bailian-v2` sends `input.media[]` for wan3.0, `wan2.7-i2v`,
  `wan2.7-r2v` and `wan2.7-videoedit` (reference images, videos and audio, first and last frames, clips and video
  edits), with the models' count and duration rules enforced by the component and a reservation that counts the
  default `1080P` tier, smart duration and input video seconds. The model catalog gains the four models'
  capabilities.

## 2. API changes

- `south-provider-api` 0.62.0 → 0.63.0: `RequestFactsV1` gains `reasoning_cap` and `cap_overhead`, with their gate ①
  rules. Both are omitted at their defaults, so existing manifests serialize byte for byte.
- `south-component-conformance` 0.74.0 → 0.75.0: the gate ② checks above, the `bailian-openai-compatible` reference,
  the Qwen-ASR reference and the Wan media reference, with their fixture packs.
- `south-contracts` (0.56.0) is unchanged. No contract number changes; the kernel pin is unchanged.

## 3. Hosts

**Breaking on re-pin** where `RequestFactsV1` is built by struct literal. A host must record runtime 0.76.0 in its range
to admit `provider-openai-compatible` 2.13.0 (§4). A host that re-pins without changing its output-cap seal refuses
split requests (fail closed, thinking cap record §6); operators should declare `thinking_budget` on a model only after
the host's seal change is deployed.

`compatibility.json`: the delivery suites are unchanged.

Unverified: the Qwen-ASR and Wan media upstream behaviour beyond what each record measured (nothing was called against
an upstream for this release).

## 4. Package identities

`south-provider-api` and `south-component-conformance` changed, so every package published with 0.75.0 retires
(`bailian_retires_every_published_075_package_identity`):
- `provider-openai-compatible` 2.12.1 → **2.13.0** (a new family), `speech-qwen` 1.0.10 → **1.1.0** (`transcribe`),
  `task-bailian-v2` 0.31.33 → **0.32.0** (Wan `input.media[]`);
- the other 38 packages take one patch with unchanged behaviour, for example `provider-anthropic` 1.4.2 and
  `image-openai-compatible` 1.0.6.

Declared runtime: `provider-openai-compatible` raises `south_runtime` 0.74.0 → **0.76.0** (thinking cap record §7):
`RequestFactsV1` refuses unknown fields, so no earlier runtime parses `reasoning_cap` or `cap_overhead`; until the
workspace is 0.76.0 no runtime of that number exists, so the raise lands in this commit, as the ten raises of release
0.74.0 did. The tests that pin it move with it: `declared_runtime_now`, the ten retired-identity rows of the package in
`shipped_packages_v1`, and the runtime assertions in `openai_compatible_t9_v1` and `bailian_openai_compatible_v1`.
Every other package keeps its `south_runtime`, and no package's `contracts` move. The release index is expected to list
41 packages and 1 catalog.

## 6. Verification

The gate is the release pull request's CI run (`quality`, which on `release/*` branches includes
`scripts/check-declared-runtime.sh --build`; `crate-versions`; `language`). The release workflow (build scripts, gate ②
reports, `check-declared-runtime.sh --dist`, the release index, `check_crate_versions.py --tag` and the
digest-stability comparison with the published `v0.75.0` index) runs on the tag.

Local verification is listed in the integration hand-off; on this tree, each step judged by its own exit code:
`cargo fmt --all -- --check`, `scripts/check-boundaries.sh`, `scripts/check-language.sh`,
`python3 -m unittest discover -s scripts -p 'test_*.py'`, `python3 scripts/check_crate_versions.py --unreleased`,
`cargo metadata --locked --offline --manifest-path fuzz/Cargo.toml` and `cargo test --workspace`.

The tag itself is not created here.
