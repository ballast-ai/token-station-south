## 1. What this release carries

- **Speech batch V3-1** (#219 record, #221): `speech-openai-compatible`, `speech-xai`, `speech-groq` and
  `speech-elevenlabs` (synthesis), and **`contracts.media` 3**: a media descriptor's query may carry a parameter the same
  package declares in `query_parameters`; gate ① refuses a speech manifest that declares `query_parameters` under media
  below 3.
- **Speech batch V3-2** (#222, #224): `speech-mimo` and `speech-minimax` (synthesis); the MiniMax `base_resp` table is
  shared with `image-minimax`, whose behaviour is unchanged.
- **Speech batch V3-3** (#223, #226): recognition (and translation on `speech.translate` rows) added to
  `speech-openai-compatible`, `speech-xai` and `speech-elevenlabs`, and the new `speech-azure` (recognition).
- **Speech batch V4** (#225, #227): `speech-qwen` (synthesis over a second hop, the `url` form's optional
  `upgrade_insecure` and `upgrade_insecure_artifact_url_v1`, SV-Q10), `speech-vertex` (synthesis, the `vertex_sa`
  recipe), SSML synthesis added to `speech-azure`, and the `ssml_escaping` row relaxed as ruled (SV-Q11).
- **Speech step S-S-5** (#228): `compatibility.json` records `contracts.speech` 1, the suite fields and a `speech_v1`
  entry in `media_component_capabilities`, `not_verified` for both hosts (Q9); the nine speech manifests declare
  `speech` 1.
- **#220, the Kiro native rewrites**: `provider-kiro` 1.1.0 makes the native arm's rewrites where 1.0.x refused (KR2–KR5)
  and drops an image in a system message or a tool result as natively (KD15).
- **The release commit** (this branch): the release bump (§5), the nine speech packages' `south_runtime` moved to 0.65.0
  (§4), and the release notes (README row and package rows, ARCHITECTURE v0.65.0 paragraph and runtime version, the
  speech and batch records' status, this record).

The kernel pin is unchanged (mirror `v0.5.0`, `canonical_ir` 4). `speech-vertex` 1.1.0, which refuses the four
transcoded formats (Q7), is not in this release: it follows only after the host accepts the Vertex dual run.

## 2. API changes

- **`south-contracts` 0.55.0 → 0.56.0**: `contracts.media` 3 (`MediaRequestDescriptorV1::parse_with_declared`,
  `parse_prepared_speech_call_with_declared_v1`, `MEDIA_CONTRACT_VERSIONS` `[1, 2, 3]`), the speech `url` form's
  `upgrade_insecure` and `speech::upgrade_insecure_artifact_url_v1`.
- **`south-provider-api` 0.57.0 → 0.58.0**: `ManifestErrorV1::SpeechQueryParametersRequireMedia3` (gate ①, SV-Q5).
- **`south-component-conformance` 0.63.0 → 0.64.0**: the nine speech references, the recognition helpers, the shared
  MiniMax and DashScope readers, the relaxed `ssml_escaping` row and the stricter SSML reader, the Kiro rewrites.

**Breaking for hosts on re-pin**: an exhaustive match on `ManifestErrorV1` stops compiling. To admit the speech
packages a host's range must list `speech` 1, and to admit `speech-elevenlabs` its media range must include 3. A host
that re-pins without widening its range keeps serving what it served before; the speech packages are refused at load.

## 3. Hosts

Serving speech needs host adoption (the generic speech executor and the prerequisites each batch record lists: V3-1 §7,
V3-2 §4, V3-3 §6, V4 §7) and a dual run per family before any cutover. The §11 / §9 real-key measurements each pack's
README lists are cutover prerequisites, including the SV-Q6 segment count for token-priced OpenAI-compatible rows.
`provider-kiro` 1.1.0 changes no host contract.
