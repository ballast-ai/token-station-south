Records: [explicit cache reads](2026-10-17-explicit-cache-reads.md),
[boundary record](2026-09-30-host-zero-vendor-boundary.md) §6 (known difference 1), §11 (work item "IR explicit /

## 1. What this release carries

- **#264, `provider-openai-compatible` reports Bailian's explicit-cache reads.** The host prices a read from a cache
  the caller created explicitly apart from an implicit hit, but a component row bills only from the IR, and the
  package's usage mapping never filled the IR's explicit part. `provider-openai-compatible` 2.11.0 fills
  `explicit_cache_read_tokens` (a subset of `cache_read_tokens`, carried since kernel protocol 0.5.0) by the host's
  native rule: the presence of `prompt_tokens_details.cache_creation_input_tokens`, even at 0, makes every hit,
  orchestration's cached subset included, an explicit read. The rule is keyed on the wire, not on the family, and the
  stream path shares the function; an upstream that never sends the key gets a byte-identical IR. No kernel change.
  Gate ② gains `provider.response.bailian-explicit-cache` and `provider.stream.bailian-explicit-cache`; the usage IR
  contract tests cover the explicit, implicit and stream cases. The boundary record's known difference 1 and its
  cache-bucket work item are marked resolved.

## 2. API changes

- `south-component-conformance` 0.70.0 → 0.71.0: the reference's usage mapping, the reference metadata versions and
  the two new fixtures.
- `south-contracts` (0.56.0) and `south-provider-api` (0.60.0) are unchanged. `ComponentManifestV1` and
  `ManifestErrorV1` are unchanged. No contract number changes; the kernel pin is unchanged.

## 3. Hosts

No API change on re-pin. No client-visible output changes: the north codecs render `cache_read_tokens` and do not read
the explicit part.

Host follow-up (record §5), once the host pins this release:
- map `explicit_cache_read_tokens` to the explicit-read bucket and the rest of `cache_read_tokens` to the implicit
  bucket, refusing a report whose explicit part exceeds `cache_read_tokens`, in both the non-streaming and the stream
  paths;
- drop the fallback that keeps a model whose price card prices the two reads apart on the native arm;
- add the explicit-cache case to the usage dual run.

Unverified: the rule against a real Bailian upstream (nothing in the record was run against an upstream).

## 4. Package identities

`south-component-conformance` changed, so every package published with 0.71.0 retires:
- `provider-openai-compatible` 2.10.1 → **2.11.0** (a new bucket reported);
- every other package takes one patch with unchanged behaviour, for example `provider-anthropic` 1.2.6,
  `image-openai-compatible` 1.0.2, `speech-vertex` 1.1.6, `task-veo-v2` 0.37.1 and `task-gemini-omni-v2` 0.2.1.

No declared runtime moves: between `v0.71.0` and this release the forty-one `manifest.json` files change only in
`version`, so each package keeps its `south_runtime` and its `contracts`. No contract moves. The release index is
expected to list 41 packages and 1 catalog.

## 5. The release bump

This is step 1 of boundary record §13.12. It changes:
- `[workspace.package] version`, 0.71.0 → 0.72.0;
- `compatibility.json` `release.version`;
- the requirements on the workspace-versioned crates in `south-provider-conformance`, `south-testkit`,
  `south-transport-reqwest` and `fuzz`;
- the literal in `south-task-core`'s version test;
- `fuzz/Cargo.lock`.

`fuzz`'s requirement on `south-component-conformance` stays at 0.71.0 (moved by #264). The guest-linked crates keep
the versions they have on main (`south-contracts` 0.56.0, `south-provider-api` 0.60.0, `south-component-conformance`
0.71.0).

## 6. Verification

request's CI run: `quality` (which on `release/*` branches includes `scripts/check-declared-runtime.sh --build`),

(build scripts, gate ② reports, `check-declared-runtime.sh --dist`, the release index and the digest-stability
comparison with the published `v0.71.0` index) runs on the tag.
