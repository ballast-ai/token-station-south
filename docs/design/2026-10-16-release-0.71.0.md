## 1. What this release carries

- **#262, the task world's Vertex families declare their own credentials.** For a `vertex_ai` row the host minted the
  service-account token by row type and derived the location prefix the component used as its base URL. With that
  type gone, each package declares `image-vertex`'s `vertex_sa` recipe (fields `service_account` and `project_id`,
  slot `provider_api_key`) in a `credentials` section scoped to its Vertex family:
  - `task-veo-v2` 0.37.0, family `vertex-veo-video`;
  - `task-gemini-omni-v2` 0.2.0, family `vertex-interactions-video`.

  The sections omit the exported `project_id` attribute: the task world has no value channel, and gate ① refuses
  exported credential attributes there. The Gemini API families (`veo-video`, `gemini-interactions-video`) keep their
  static `x-goog-api-key`. Manifest only: neither component's logic changes. Gate ② gains the five Vertex
  `credential.*` cases in both fixture packs.
- **#255**, docs: the component packaging assessment record (Q1 answered, Q2 ruled (A)).
- **#260**, docs: the `image-openai-compatible` record corrected from the host's read-back (D10 and the Azure `v1`
  binding).

## 3. Hosts

No API change on re-pin.

Host prerequisites for the two Vertex task families:
- Bind each family on a `component` row whose endpoint is the full location prefix (record §3):
  - `vertex-veo-video`: `https://{region}-aiplatform.googleapis.com/v1/projects/{project}/locations/{region}`, or
    `https://aiplatform.googleapis.com/v1/projects/{project}/locations/global` for `global`;
  - `vertex-interactions-video`: `https://aiplatform.googleapis.com/v1beta1/projects/{project}/locations/global`.
- Give the row a credential carrying the recipe fields (`service_account`, `project_id`); one stored service-account
  credential serves every Vertex package.
- Confirm the recipe's token endpoint (`https://oauth2.googleapis.com/token`) for each package digest before minting;
  a confirmation for another package's digest does not carry over (boundary record §3.4).

Unverified: the whole Vertex task path against a real account (both records list what a real-account test must
settle).
